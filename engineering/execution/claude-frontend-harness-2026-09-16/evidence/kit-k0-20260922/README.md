## Concrete proposal

Select the [v1 contract](contract.md): exact Kit descriptor digest plus pinned core/deferred references, declarative resource requirements, explicit conflicts, owner-supplied runtime evidence, bounded pure output and fail-closed required content. Dependencies and native contributions are unsupported in v1. All Kit inputs are supplied explicitly; nothing is fetched or installed.

No existing product hunk is required for K1. Kit-present rendering reuses the current compiler on single-instruction views and one catalog view, with explicit code-unit ordering; no-Kit calls the original compiler directly. This avoids both a second serializer and the existing compiler's ambient `localeCompare` ordering in the new path. Exact rendered segments, separators, UTF-8 bytes, UTF-16 units and content hashes are accounted. The original binding is never changed or passed back as an altered admission decision.

The [future consumer proposal](consumer-and-verification.md) identifies the exact Host admission/output call sites and the separate persistence gap. It is a proposal only; K1/K2 must not edit those owners or mount a live Kit.
