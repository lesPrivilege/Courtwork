## 1. 总定义

CourtWork 是一个本地优先的 AI 工作空间：把交谈、资料准备、Agent 执行和人的决定连接起来，让持续工作不依赖某一个模型、某一段聊天或某一次运行的记忆。

Chat、Spark、Attention 是三种面向用户的职责与入口，不是三个永久固定的模型，不要求三套独立存储，也不预设三个并行常驻进程。底层能力按作用域、权限、预算与实际 Runtime 支持组合；正式工作状态仍由原 owner 管理。

## 2. Chat · 交谈由你选择，资料由本地持续管理

### 产品定义

Chat 是自由交谈与资料交接的入口。用户可以在受支持的连接之间选择 Provider；CourtWork 统一管理应用自身保留的对话记录、附件版本、引用、导出与本地缓存，使材料可以在后续交谈或正式工作中继续使用，而不必重新从分散的聊天窗口收集。

当所选 Provider 和执行接入支持工具调用时，Chat 可以通过 CourtWork 的受控工具层使用获准 MCP 等能力。工具是否能用取决于当前连接、Runtime、策略和审批，而不是一个与所有 Provider 通用的“已连接”标记。

### 边界

“本地管理”限定于 CourtWork 自己保存的数据。不能据此承诺第三方云端聊天、服务端 prompt/KV cache、所有副本删除或跨 Provider 原生会话无损搬迁。切换 Provider 时，发送哪些本地来源是一次实际披露，应显示范围并受权限约束。

自由交谈不强制建立 Matter。进入需要版本、义务、正式成果效力的持续工作时，再显式绑定合适的 Work Contract。对话记载不是正式接受。

### 当前与后续

当前基线已经有模型连接、Host 会话/运行、保留来源/文件阅读和受控工具的局部实现；具体支持按 capability 表和对应证据列出。[S10][S11]

跨 Provider 网页会话聚合、完整统一导出/缓存治理、各连接的全部 MCP 行为不能统一写成已交付。需要分别验证账号/会话/连接隔离、协议兼容、工具编码和断线恢复。

## 3. Spark · 快读、快查，把资料准备成下一步可用的证据

### 产品定义

Spark 是面向短任务的快速资料准备与核对角色。它对明确授权的材料开展外部检索、快读、翻译、比较、索引整理和审计核对，把结果整理为有出处、可回源、可失效和可重新生成的准备材料。

它的默认目标是降低主 Agent 和人的阅读成本，不接管所有专业判断或全部长任务。可以预置便于检索的插件组合，但插件安装、工具暴露、联网披露与实际调用权限分别控制。

### 模型与工作边界

Spark 可以配置快速模型，但产品定义不绑定 Luna、某个 Flash 型号或一家 Provider。具体模型只是一版执行配置，要按任务质量、延迟、成本和上下文要求验证。

建议公共文案用“检索、整理与核对”，不使用含义易误读的 exploit。内部可保留 review/explore 的工种名，但不能以名称替代实际任务契约。

Spark 可以指出遗漏、矛盾和过时结论，也可以提出修订；不因为它说“检查完成”，就自动接受专业成果或关闭正式义务。独立审查只是流程/权限分工，不代表自动获得独立正确性保证。

### 索引/翻译的治理

应区分：原始来源；定位/目录；派生翻译或摘要；结论/核对发现。这是语义与生命周期区分，不要求四套数据库或立刻冻结一种通用目录格式。

派生结果至少能够回答：从哪一版材料而来；经过什么处理；哪些范围未覆盖；目前是否仍适用；可在哪里读到原文。摘要不能替代原件身份，翻译不能抹去原文锚点，去重不能消除互相冲突的判断。

### 当前与后续

当前 Spark 有 work-derivations 只读投影，不等于已经存在通用检索/翻译/索引 Agent 循环。[S10]

先选一个真实短任务：固定几份资料 → 产生索引/翻译/差异 → 主 Agent 或人能回源核对 → 源版本改变后明确过时。按这一消费者补最小缺口，不为“统一索引”预建全能 Broker。

## 4. Attention · 让重要请求不失联，让下一步有所依据

### 产品定义

Attention 是人和 Agent 之间的待办、跟进与核查入口。它关心的不是通知有没有出现，而是重要请求落到了哪里：是否交给合适执行者、是否形成明确处置、是否有对应结果、是否经过检查，以及还有什么需要人来决定。

在压缩、任务插入、执行中断或更换会话后，Attention 根据保留的请求、来源与工作记录找出尚未闭合的事项，帮助执行者恢复下一步，并把可观察的处置状况回报给人。它降低失联风险，不承诺模型永不遗忘。

### 消费必须分成不同事实轴

| 事实 | 可以说明什么 | 不能自动说明什么 |
|---|---|---|
| 接收/投递 | 消息存在，投递到指定目标或 mailbox | 已进入模型输入 |
| 输入披露 | 精确版本被提供给某个 Run / context generation | 模型真正理解或重视 |
| 处置回执 | 执行者给出计划、拒绝、需澄清、行动或结果引用 | 处置正确、要求已满足 |
| 核查 | 某个检查者按规定范围检查了输出/证据 | 已获正式接受或永远适用 |
| 正式决定 | 原 owner 在授权合同下接受、退回、延期或关闭 | 新版本和后续任务自动继承同一效力 |

这些是相关但独立的事实轴，不应强行做成一条永远向前的“已读→完成”进度条。被替换、拒绝、延期、冲突、unknown、部分完成都需要保留原因与范围。

“尚无消费证据”是可以如实显示的；“模型一定没看”通常不是。Attention 不读取或裁定模型内部注意力。

### 最小可检验场景

人提出两个明确要求 → Agent 只产生其中一个结果 → 中途压缩/插入任务 → Attention 根据已记录处置指出另一个要求尚无对应证据 → 下一 Run 获得当前请求与版本 → 产生结果并经检查 → 原 owner 作决定。

另设反例：补写一句“已完成”但没有结果引用；旧消息被新版本取代；重复投递；完成回执晚到；压缩前的结果被错误用于新要求。不能因为文本提到了某要求就自动勾掉它。

### PR 与外部 message 跟进

未来 GitHub 接入应绑定仓库、PR、具体 comment/review、head SHA 和检查时间；follow-up 的对象是明确请求，不能只看 PR 是否 merged。新提交可能使旧核查失效。对外催促、发消息和自动续行各自需要权限、去重与停止条件。

当前 authenticated 邮件/GitHub/calendar connector、全局 scheduler 和 Expert delegation 在相关合同中仍列为未交付，不能由本地记忆/Thread 接口推导已接入。[S12]

### 当前执行边界

已有全局 Attention 会话、目录/精确消息读取、受治理的 Core 查询等能力；但与项目 Run 共用单一活动 Run 准入。因此“主 Agent 工作时，后台另一 LLM 持续盯办”不是当前可用承诺。[S12]

首个增量可选择确定性观察保留事件，加用户显式触发或受控排队的 Attention 核查。并行 Agent、自动恢复、后台调度以后按需求单独设计，不突破当前 owner 与准入边界。

## 5. Experts 与三入口的关系

Expert 是可版本化的专业能力与验证组合；Work Extension 承载专业差异；执行 profile 或 Provider 不应成为工作语义本身。[S10]

Chat 可以直接交谈，不必经过 Spark；Expert 可以回原文质疑 Spark 的整理；Attention 可以直接提醒缺失证据，不必先调用一个新 Agent。三入口共同服务同一件工作，但不强制串行流水线。

## 6. 建议公共首页/README 主段落

以下段落用于“产品方向”，必须与后面的当前状态说明一起发布，而不是单独摘取成可用性承诺。

> **Orchestrate your agents. Govern your work.**
>
> CourtWork 正在构建一个本地优先的 AI 工作空间，把交谈、资料准备、Agent 执行与人的决定连接起来。你可以选择合适的模型与工具；工作的来源、已作决定和未完事项，则不必跟着一次对话结束。
>
> **Chat — 交谈与资料。** 在受支持的 Provider 之间选择交谈对象，由 CourtWork 管理本地保留的记录与材料，并按连接能力使用获准工具。
>
> **Spark — 检索、整理与核对。** 用快速短任务帮助阅读、翻译、比较和组织资料，让准备结果能够回到来源，供后续工作继续检查。
>
> **Attention — 跟进重要请求。** 把尚未闭合的请求、缺失证据与需要决定的事项带回眼前，让人和 Agent 都能找到下一步。
>
> 三者是产品方向，不代表所有能力已在当前版本贯通。当前工程以固定执行组合和一条可审阅、可继续的专业工作纵切推进；可复现范围与未完成项见下方状态说明。

## 8. 配置面不应被文案偷偷改变

这一轮先裁决自然语言定义和能力状态，不默认修改凭据规则、存储 schema、Provider 默认值或角色权限。

连接身份与 Provider 身份、模型能力与 API 编码、用户希望的 setting 与实际请求 binding、当前配置与历史 Run 需要分别呈现。未验证设置不能标成已生效；连接检查成功也不证明完整工具/专业工作闭环。

“缓存由本地管理”不要改成隐式开启跨作用域上下文共享；“预置插件”不要变成默认授予网络和任意执行；“Attention 跟进”不要变成自动重新运行未知副作用任务。

## 9. 建议内部裁决项

| 裁决 | 采用后影响 | 不随之自动成立 |
|---|---|---|
| 三入口以职责定义、模型可替换 | 产品文案、帮助文本、未来 profile 的命名 | 并行调度已实现 |
| Chat 的本地资产范围明确 | 导出/缓存/来源治理需求与当前 owner 映射 | 第三方服务端缓存可控 |
| Spark 以短任务准备/核查定位 | 检索插件、派生来源、失效与重建验收 | 通用索引代理已可用 |
| Attention 跟踪可观察处置 | 消息/结果/检查/决定的关系与展示 | 内部认知可测量、任务必完成 |
| 目标与能力资格分开 | README/Pages/配置帮助和支持表 | Paper 必须改版 |

不要直接为上述建议分配新的 schemaVersion、API 字段或编号。本地先映射现有合同与已有登记，只有已选消费者确有缺口时才开施工片。
