## 1. 这个 PR 实际解决什么问题

问题不是"Pages 文案不好看"，而是发布面的信息架构把内部验证责任压到了产品叙事前面。旧首页证据纪律很强，却很快进入 Event Log / Work State / Compiled Context、synthetic verification、benchmark 方法、SHA、fixture、build/reproduce，更接近可审计的工程验收报告；Spark、Attention、Matter、Experts、replaceable Runtime 这些形成产品辨识度的判断反而没有成为首页第一层。旧 `copy.mjs` 的公开内容直接承载大量测试状态与 benchmark 说明。

问题定义：保留 evidence / reproducibility 底座，把"产品是什么"与"我们如何证明它"重新分层。第一屏回答产品问题，第二层展示真实工作面，验证方法成为可下钻的独立 destination。与 PR 自述目标一致（旧页面混合了 product narrative、test totals、source hashes 和 engineering acceptance commentary）。

## 2. 不看实现的预定方案

四层：Product proposition（Spark · Attention）→ Product reality（Tour · screenshots · Review · Matter）→ Product architecture（Matter · Experts · Runtime）→ Evidence（Eval → Method → Raw evidence）。首页只留短 Eval teaser；完整 Eval 独立页，区分 `synthetic result` / `evaluation design` / `not run`；deterministic build、evidence hash、media manifest、replay 不破坏，只后移。

两条发布纪律：产品截图有唯一明确的 product snapshot；评测证据有唯一明确的 evidence snapshot。二者可以不是同一 SHA，但不得把旧截图称为 Current，不得从冻结评测文档重新链接到会移动的 `main`。

### Blocking 1：冻结方法页重新指向会移动的 `main`

PR 新增 `emitMethod("benchmarks/SPEC.md", "benchmark-contract.md")`、`emitMethod("…benchmark-series/README.md", "benchmark-series.md")`；`emitMethod()` 遇相对链接写成 `https://github.com/lesPrivilege/Courtwork/blob/main/...`。`benchmarks/SPEC.md` 含大量相对引用（Continuity protocol、observation contract、PAPER、BM series）。文档本体被冻结，解释它的依赖却漂移。现有 `check-links.mjs` 只扫 built `.html/.css/.mjs`，新生成的 `.md` 不在检查集合，gate 抓不到；作者记录 deterministic build 通过——是 semantic reproducibility 未被 gate 覆盖。

修法不是把 `main` 换成 `release.source_sha`（`9e5384f` 是产品 evidence snapshot，新 BM 文档未必存在于该历史版本）。应明确两种 identity：`product_source_sha`（`9e5384f…`）与 `publishing_source_sha`（当前 Pages 内容所在完整 commit）。Method export 的内部 GitHub 链接 pin 到后者的 40 位 SHA；link checker 同时扫 `.md`，或 Eval 页直接链接到 immutable GitHub source，不复制 Markdown。合并/发布前必修。

### Blocking 2：`current` screenshot 已不是 current

`site/media/main/manifest.json` 整份 UI capture 固定在 `e818463ab31aa06a4c9d52a968a68099fdb02c3e`（2026-09-09，synthetic）；远端 `main` 已是 `9c8b64e85e1b4a906dcd23cd5be621da1ba90638`，中间 76 commits，含 Spark、Attention triage、provider/model surface、typography/shape 等可见 UI 变化。PR 函数仍叫 `currentHome()`，公开文字仍说"Courtwork 当前 Home"，build 把 manifest 称作 `"current-main page media"`。provenance semantics 失真。`validateMedia()` 只验 manifest SHA 格式、每图 `source_sha` 一致、bytes / dimensions / sha256；不验 `pageMedia.source_sha === 本次声明的 UI snapshot`。

两种修法：A 不重截图，"Current Home" → "Recorded product snapshot · e818463 · 2026-09-09"；B 为发布面定义 `public_ui_sha`，按其重截，build 强制 `pageMedia.source_sha === public_ui_sha`。推荐 B。

### Important：scope 太宽

相当部分是 `engineering/research/data-organization-2026-09-10/`（inputs/1-assistant.md、2-assistant.md、manifest、selection-index、roadmap…），不参与 Pages build，不是本 PR 成败所需的代码依赖。revert 与 cherry-pick 都会互相拖带。建议拆成 PR-A data-organization intake / research index、PR-B public narrative + Pages implementation。merge 前拆。

### Follow-up：provenance 仍是 stringly typed

PR 已注意真实性（"Spark · Product direction"、"Experts · Product direction"、"CONTINUITY / SYNTHETIC SUITE"、"STATE MACHINE / EVALUATION DESIGN" 等），符合 BM-01 的 publication contract（Continuity 只是 development calibration，规划中的 family 不得伪装成实验结果）。但这些状态藏在 `featureRows`、heading 与 template literal 里，如 `['Spark · Product direction', …]` 而非 `{ feature:'Spark', maturity:'product-direction' }`；截图由 renderer 无条件追加 "Synthetic demo"。建议后续建一层很薄的 PUBLIC SURFACE registry（identity / maturity / claim scope / evidence reference / copy），frozen JS registry + test 即可；与 Spark / Attention sample provenance 同一思路，但不强行共用 runtime 类型。
