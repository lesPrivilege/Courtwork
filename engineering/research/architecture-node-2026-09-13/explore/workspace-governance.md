## What is already covered, and what remains open

The registered direction already rejects a second universal resource store. [RD-007](../../RD-007-resource-governance.md#L7) separates content resources from Runtime capability resources, retains bytes and authority with current owners, and distinguishes identity, revision, relation, disclosure, and formal acceptance. The [data-surfaces delivery](../../data-surfaces-2026-09-13/README.md#L13) now provides Session-scoped retained UTF-8 uploads, exact-version reads, Files/Inspector references, and deterministic same-source comparison. It explicitly leaves general source authorization, directory capture, PDF/OCR, cross-scope binding, annotation, indexing, and context priority open [at the contract boundary](../../data-surfaces-2026-09-13/README.md#L34).

Require objective, scope, output/evidence format, and stopping point. This is first-party evidence about Anthropic's system, not an independent CourtWork result or a human-attention savings claim. |

The strongest combined implication is a *governed index plus exact readers*, not “put every file into context”: enumerate only an explicitly authorized source set; state its scope, revision/watermark, and coverage; then read the exact version under the source owner's current policy. A missing row is not evidence of nonexistence unless the owner can attest complete coverage for that scope. This is an inference joining MCP's discovery/read split with CourtWork's existing scoped readers and version contracts.

For multi-agent work, the research does not justify an always-on manager or a larger agent count. It supports a bounded case for parallelism when tasks are independently answerable, while CourtWork's own contracts supply the stronger authority rule: assignment/permission is explicit, agents return versioned findings or candidates, another actor reviews evidence, and the existing owner decides the formal effect. NIST role separation is a security control reference; Anthropic's performance claim is self-reported; neither proves reduced human effort here.

## Candidate first reversible slice

Before creating a cross-owner service, test one read-only cold-start takeover with synthetic data: one authorized project/Matter, one source Session, two exact versions of a text source, one accepted result, one pending candidate, one open obligation, and one stale or revoked reference. Let one synthetic actor prepare and a second start from current owner pointers, not the first actor's chat. Use the existing files, Intake, Work Core, and Attention readers; generate only a disposable handover projection/fixture. A separate reviewer checks the selected source version, inventory coverage, and next action. This validates whether the existing seams suffice before any persistent handover record or unified workspace catalog is proposed.

The vertical slice should fail visibly when the authorized inventory is incomplete or paginated inconsistently; a same-name file in another scope is not substituted; hidden entries/counts are not disclosed; unavailable, corrupt, revoked, and not-yet-inventoried sources remain distinguishable; a stale summary cannot restore a revoked read; a budget limit cannot silently drop obligations or coverage; and an old Run with unknown effect cannot be re-run as if ownership transferred. In this fixture, the non-author reviewer is an evidence-only role without permission to accept or close; a separately authorized human may make that decision. No “done” summary may substitute for owner evidence. These are test cases, not a frozen API or acceptance decision.

Measure retrieval correctness, coverage, stale-source detection, permission failures, duplicate work, missed/false escalations, and time to recover the next valid action. Keep context/token cost alongside human time; the external multi-agent report suggests coordination can increase resource use. A synthetic pass may justify a narrowly bound implementation follow-up; it does not claim cross-owner atomicity, production handoff, or measured attention savings.

## Non-author review of Astra's canonical map

I reviewed the current [canonical draft](../workspace-governance.md) after Astra incorporated the bounded review notes. The wording now keeps “may encompass” as a question for research, distinguishes a governance kernel from physical storage, separates takeover data from protocol/process resume, identifies one commit owner per formal effect while allowing multiple authorized actors, and distinguishes non-author review from statistical independence or professional qualification. The attention filter also includes a route for newly detected material risk before an obligation exists.

The resource-directory test now requires a complete-enough oracle for its explicitly authorized scope and a truthful coverage statement; hidden objects/counts stay undisclosed, while visible-but-missing and unscanned-unknown remain distinct. I find no remaining overclaim in those five requested areas at this bounded documentation review. This is not implementation acceptance or architecture authority; the [current project status](../../../current.md) and individual owner contracts remain authoritative for implemented capability.
