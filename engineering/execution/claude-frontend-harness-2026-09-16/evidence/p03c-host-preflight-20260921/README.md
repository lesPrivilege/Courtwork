## Decisions adopted now

1. **Existing Host/Store ownership.** Retain Pi's strict `{id,path}` hostSession and journal semantics. Use a separate remote binding on the CW Session with a frozen admitted Run snapshot; do not disguise a remote ID as a Pi path or create a second registry. Migration belongs to RuntimeStore/RD-001, not Core or the bridge. It must use the existing strict validation and exact-backup path, preserve all prior Pi data and prohibit mismatched configuration/credential identity during reuse. Exact field names/validation remain to be specified in the finite consumer contract before source edits.
2. **Durable intent before remote creation.** Create an attempt tied to the admitted CW Run before dispatch. A lost creation reply stays unknown with admission fenced. No auto-recreate, guessed native ID or claimed lookup method. Operator reconciliation for that case is deferred to its explicit recovery owner; this first slice must describe the limitation rather than invent an API.
3. **One governed reader, no second tool policy.** Required actions must reach the existing repository-tool/governance boundary with admitted repository identity/revision. Unknown, denied and out-of-scope tools do not invoke a filesystem helper. The Agents adapter owns native identity/normalization, not grants or formal completion.
4. **Adjust Luna's execution ordering.** An immutable native call claim must be persisted **before** invoking the governed reader, with duplicate/concurrent delivery checked against that claim. After successful execution, durably store the exact bounded serialized result and digest before submission. Persisting only after the read is insufficient to prevent duplicate dispatch. Keep execution and result-delivery states separate: no result yet, result retained, submission in flight, HTTP accepted, native observation and unresolved outcome are different facts. Do not adopt the report's illustrative status enum as a final schema.
5. **Result ownership and recovery.** Exact result bytes belong to the existing RuntimeStore-owned call/result receipt for this first bounded read consumer; repositoryRead digest events remain evidence, not a reconstruction source. The final contract must state byte/count limits and retention rather than duplicating a general artifact store. No secrets in bindings or receipt diagnostics. On restart, in-flight remote work is fenced unknown; no automatic re-read, result resend or new input. Full observation reconciliation remains original D; write/check parity remains E.
