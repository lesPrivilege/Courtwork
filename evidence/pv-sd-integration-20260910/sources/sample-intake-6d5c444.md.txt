## 2. 裁定

**SD-1（契约采纳，产品进入另有门）** 转发稿的 takeover 契约采纳为本批次的契约文本（§3）。它的产品化在 Spark 上意味着改写 SP-10 的一句话——SP-n 归 Astra，且"不显示任何合成数字"是 Astra 在 BE-41 未交付期间的明确选择。本批次不越权改写：先以探索与契约成文，产品进入以 **Astra 对 SP-10 的修订 + 用户裁定** 为门。已升报（§5）。

**SD-2（sample 不是回退）** 回退的定义是"live 失败后拿假数据顶上"；本契约里 sample 只在两种入口出现：该面在此宿主上 `unimplemented`（后端明确 404 的合同态），或用户显式打开预览。live 失败从不落到 sample。这一条与 SP-10 的动机（不让读者把合成数字当事实）同向，差别只在"有来源标签的样本"是否算"合成数字"——这正是要请 Astra 复裁的点。

**SD-3（空响应是 live）** 有效的 live 载荷包括空集；Attention 返回 0 项时投影切到 live 的空态，不保留样本。否则用户永远看不到自己已清空。

**SD-4（原子切换，单一来源）** 一个面在一个时刻只有一个 provenance；live 首次有效到达时整个投影原子切换；已有 live 之后的错误显示错误并按各面既有契约保留最近一次 live，不回到 sample。

**SD-5（来源标签一次，字先于形）** 标签在 surface header 出现一次，不逐卡标注；用字沿 copy-convention 复看后定（候选 `Sample` / `Preview data`），不着色、不用图标承担语义（与 PV-36 / PV-41 同源）。这与 Projection Grammar 的"投影不得创造事实"相容：标签正是使样本不成为事实的那一句。

**SD-6（Attention 的样本是内容 fixture）** Attention 的样本记录必须是 Core Attention DTO 形状（与 `attention-actions.json` 的动作描述符同一契约），可由 Gmail / GitHub 情境改写而来，但 Gmail / GitHub fixture 本身不进前端，不成为第二套数据模型。样本态的动作可展开、只读，不向 Core 写；需要完整交互时另作确定性的本地 reducer，假 ID 不进真实 store。

**SD-7（Spark 的样本晋升现有 fixture）** 不新造数据：五份 fixture 即五个 canonical 场景；默认场景待 EX-SD1 核过各场景露出的解剖后定（稿中建议 `stale`）。fixture 一旦成为产品资产，其变更须与 BE-41 DTO 同步，测试与产品读同一份文件。

**SD-8（Design Scout 位阶）** 稿中优先级（current main / accepted rulings → existing implementation → mature external practice → old Scout as leads → new local specimen / ruling）与 WK-112 的设计研究回路及 Scout README 一致，采纳为本批次与 PV 批次的共同读法；不另立规则。

**SD-9（EX-SD1 派单）** Sonnet 只读探索：① 两面今日的数据装载与四态（loading / unimplemented / empty / error）处理，file:line；② 五份 Spark fixture 各自露出哪些 UI 解剖（哪些区块只在该场景可见），据此给默认场景建议；③ Attention 五状态样本可从哪些既有 fixture 与 DTO 字段合成，动作描述符如何在只读态渲染；④ 仓内已有的"显式预览 / 本地模式"开关先例（local-fake provider、skin-policy、URL 参数、Settings 项）——sample 入口应长在哪个既有开关上，不新造开关；⑤ Pages 截图与视觉回归链路今日读什么数据；⑥ 转发稿引用的 Grafana TestData、Storybook 网络 mock、Linear Inbox 三条以第一方文档核其被引用的那一句是否成立。产出事实与矩阵；契约文本与 specimen 归 Fable。

## 3. 契约文本（草案，待 SD-1 门）

```text
Surface projection ← exactly one DTO
  provenance ∈ { live, sample }
  sample  ⇐ unimplemented(404 by contract) ∨ explicit preview
  live    ⇐ any valid live payload, empty included
  error after live ⇒ error state (+ last live where the surface contract retains it); never sample
  live ∩ sample = ∅ ; switch is atomic and whole-surface
  label: once, in the surface header; text, uncolored
  sample actions: expandable, read-only, no write to Core
  default sample scenario (Spark): stale.json ; pagination state not covered by any fixture (SD-11)
  read-only exit: one explicit branch between chooseAction/submitAction and mutate(); send() stays the sole write point (SD-13)
  entry: a text action "Show sample data" inside the surface's own unimplemented sentence; session-scoped, not persisted; no global switch (SD-14)
```

## 6. EX-SD1 回执（Fable，2026-09-10）

回执 [explore/ex-sd1-sample-surface.md](explore/ex-sd1-sample-surface.md)。

**SD-10（四态与保留的事实）** Spark 的四态齐全但"曾有 live 后出错"不保留（`spark-view.mjs:68` 无条件清空）；Attention 的 Home 卡保留并告知（`app.mjs:5335`、`home-view.mjs:182` "Showing the last loaded records."），完整工作区不保留且 `refreshRegistry` 存在无提示的隐式保留。裁定：保留行为按各面既有契约（SD-4 原文），本批次不为 sample 新增保留逻辑；`refreshRegistry` 的无提示保留登记为 Attention 线的观察项，不在本批次处理。

**SD-11（默认场景 = `stale`）** `stale.json` 是唯一同时露出 Overview 的 Behind 区与 Up to date 区并给出非空 Activity 表的 fixture，稿中建议由事实成立。五份 fixture 无一触发分页器（total ≤ limit），分页态不在样本覆盖内，如实写进契约。

**SD-12（Attention 样本缺 `waiting`）** `attention-packets.json` 可供四态完整 DTO，`waiting` 无任何快照。裁定：样本集的 `waiting` 记录须与 `attention-actions.json` 同法——对运行中的 Core 发一次真实 `set_waiting` 捕获，不手写；样本数据集因此是"捕获再冻结"的，与 SD-6 一致。Gmail / GitHub 摄入 fixture 不是 DTO 形状，确认不进前端。

**SD-13（只读动作的落点）** 唯一写入点是 `attention-view.mjs:427` 的 `request(...POST)`；`toAttentionActionDescriptors` 为纯函数可复用。sample 态的只读分支须落在 `chooseAction` / `submitAction` 到 `mutate` 之间的一个显式出口，不替换 `send()` 内部（写入点保持唯一、可读）。

**SD-14（入口不新造全局开关）** 仓内没有数据来源级的预览开关；`?shell=desktop` 不持久且不可见，local-fake 连接是 provider 模式而非数据来源，两者都不宜承担。裁定：sample 的入口长在该面 `unimplemented` 态自己的那句话上——"No source yet…" 后接一个文字动作 "Show sample data"，会话内有效、不持久、刷新即回到 live 判定；header 标签随之出现。显式预览因此是每面一次的明确动作，不是模式。Pages 取证脚本可点击该动作，替代今日在 `browser-checks.mjs` 注入 mock 的做法——这会使 `evidence/spark-delivery-20260910/README.md` 的"夹具不进入运行产品数据源"一句改义为"夹具进入产品渲染但带来源标签"，属 SD-1 门的后果，一并请裁。

**SD-15（外部引用）** Grafana 成立；Storybook 的"同一契约、确定性网络态"为稿作者的概括，官方页无此措辞；Linear 的 J/K 与 snooze 成立。本批次无裁定以其为条件。

§3 契约文本据 SD-11 / SD-13 / SD-14 补三句：默认场景 `stale`；只读出口位置；入口为 `unimplemented` 态内的一次显式动作。§5 升报不变，待用户与 Astra。
