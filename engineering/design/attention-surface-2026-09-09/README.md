## 常驻Attention与Home：同一对象的三个入口

建议产品结构：全局导航中的稳定Attention入口 → 独立Attention工作面；Home可选展示少量需要人的摘要，指向同一个对象。常驻指对象可发现、可续行、跨Session存在，不意味着常驻进程、定时轮询或模型常开。

- 独立工作面拥有列表/筛选、具体原因、下一动作和详情披露；桌面列表与详情、窄屏列表→详情返回。进入后仍能回原Chat/Work；切Session不会重置Attention对象。
- Home默认仍以开始工作为主；可选摘要只显示获准的最有意义条目、下一动作和“查看全部”。隐藏Home摘要不删除、resolve或snooze对象。是否开机落在Home还是Attention另作可逆偏好，首版不新增启动选择。
- Dashboard上的PR/roadmap是工作信息的视图：确切PR/工单由现有工程来源维护；Attention保存引用、关注理由和需人动作，不复制PR状态、项目台账或Matter治理记录。没有接入则只保留合同研究，不读取本仓文件冒充产品功能。
- 当前Today strip是既定三类work-summary投影；未来Attention有独立生命周期，不能改名便声称已有。Needs You/In Motion/Waiting/Later是对话中的候选分组，需映射后端状态和授权动作，不能直接替换当前词表。
- 初层显示“什么事、为什么现在需要我、下一动作”；展开显示依据、变化、关系，再按授权读原始内容。完整memory指可寻址；存在性、标题、数量同样经过权限过滤，grep不是授权旁路。Schema及来源版本保持一级引用，缓存可重建。

## 补充输入：动态 composer 与停止按钮（22:17）

用户提供的截图10已转为 [来源元数据](sources.json)，下列文字保留当时的设计观察。静态可见：输入区与底部控件行分层；左端附件/权限，右端模型/effort、语音与圆形停止钮；停止钮以实心方块识别；变更摘要在输入框上方独立显示。截图中的 Full access 是参考产品自己的权限说明，不映射为 CourtWork 新权限或本次执行授权。

可消费原则：composer 的高度随输入内容变化时，底栏与主动作保持可预测位置；发送/终止的形状应容易识别，命中区不随状态词伸缩；改动摘要只投影真实变更来源。动态高度、动效曲线、切换时序、interrupt/reduced-motion 行为不能由一张截图确认，须另有交互证据后成单。当前只登记输入，不添加语音、Auto 模式、新权限或 PR 控件。

合流截图另发现 CourtWork 既有 composer 图标丢失问题：初始化 `setAction` 创建 icon-only 的 Send/Cancel run，后续 `renderComposer` 替换子节点，文本挤入圆形按钮；CC-W 前 `172130e` 已用 textContent 覆盖，同样丢图标，非本单引入。见 [CC-W合流证据](../../../evidence/cc-w-main-integration-20260909/README.md)。后续 composer 单须保留图标身份、更新可访问名与 tooltip，证明发送/取消在途以及重绘后仍有正确图标与稳定命中区；当前 M-9 短文本按钮补丁不宣称解决此问题。由 Fable 纳入后续单写者工单，未自行扩大 CC-D0-a。
