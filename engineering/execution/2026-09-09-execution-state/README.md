## 1. 从问题推导边界

用户检查的是某次尝试产生的具体内容。若接受时重新读取可变路径，或者沿用旧内容的验证结果，就可能接受从未检查过的内容。执行成功只能证明一次执行的结果；不能推出成果正确、依据仍有效，或执行者有权把它变成正式成果。

因此需要四个可分别检验的事实：

1. **身份**：候选究竟包含哪些字节，来自哪个 Run、Matter 和输入版本。
2. **适用性**：检查所依赖的输入、契约和策略在接受时是否仍有效。
3. **权限**：谁能对哪个候选作何种决定，由既有服务与 Core 判定。
4. **持久性**：接受后的确切字节与决定在重启后仍能一致读取。

文件快照只承担第一项的一部分。摘要证明身份，不能恢复丢失内容；验证回执说明检查结果，不能授予决定权限；文件版本不能表达全部 Matter 状态。

```text
受限工具的一次文件尝试
  → 捕获不可变文件包（尚无正式效力）
  → 现有 Candidate 引用文件包与依据
  → 对确切候选执行声明的检查
  → 现有 Work API / decide 重查权限、版本、依据、回执
  → 现有 Core 事务生成 Artifact / Decision
```

## 4. 共同不变量

| ID | 必须成立 |
| --- | --- |
| ES-I01 | 工具 allow、Run completed、capture success、verification pass、正式 accept 分别记录，不能相互替代 |
| ES-I02 | 展示/验证/接受使用同一个不可变候选身份；内容变化必须生成新候选 |
| ES-I03 | 接受时核对当前依据；已知输入过期必须重新生成或重新检查，不能以写集合无冲突放行 |
| ES-I04 | 依赖观测不完整不能标成 complete；文件包内的 root 不覆盖包外依赖或网络副作用 |
| ES-I05 | 验证器与策略版本由可信侧确定；模型不能自签 PASS、修改 actor 或绕过 decide |
| ES-I06 | 接受事务持久保留确切内容、关系与决定；ACK 丢失按原 request ID 查询/重试，不重复接受 |
| ES-I07 | discard/end/Stop 不隐式接受；重建文件副本不撤销历史 Decision，也不撤销 MCP 外部效果 |
| ES-I08 | 无合法动作、未知契约、producer 缺席或数据完整性失败时不能执行接受；历史效力与当前可读性分别表达 |

## 5. 最小纵切与后置项

第一张实现只处理受限工具产生的有界 UTF-8 普通文件包：固定基础输入 → 捕获候选 A → 校验 A → 人接受 A → 重启/新 Session 读取 A。候选 B 用于证明修改必须生成新身份，以及旧回执不能授权 B。无需并发 scheduler、Git worktree、FUSE、CAS/CDC/COW 或第三方 SDK；普通目录和既有持久化机制即可实现。

“接受”把文件内容纳入正式 Artifact，不自动覆盖用户工作目录。将文件包实际应用到任意目录是另一个受权动作，涉及目标版本、路径权限、部分失败与恢复，后置独立 PR。第一张单也不提供 restore/fork/discard 按钮、自动三方合并、任意格式 diff、通用依赖追踪或物理 GC。
