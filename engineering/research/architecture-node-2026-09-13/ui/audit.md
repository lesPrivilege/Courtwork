## Findings

- **Files long-scroll return control now passes at 175% zoom.** The first flex-only adjustment still allowed the outer dialog to scroll the header away (44). The latest height constraint isolates scrolling to the body; screenshot 50 retains a visible, clickable Close X at the bottom of the expanded form. Escape and the X close locally, focus returns to the Chat files trigger, and the unsent draft survives close/reopen. This is browser evidence for the current working-tree correction, not product acceptance.
- **Return placements communicate different scopes.** Page-level return controls include Back to app, Back to chat, and Back to workspace. Files/Attention/Spark dialogs have local Close/Escape paths. Chat overview is an inline side overlay with its own Close; both visible Close and Escape returned focus to the Chat overview opener in Chrome. Hide work surface collapses the rail rather than navigating the session away.
- **Home Attention return focus now restores its opener.** The first browser check landed on global Attention after Back to workspace; after Astra's Home-scoped focus correction and hard reload, the same route returned focus to Home's Attention items control (61). The current fixture has no row from which to inspect an individual item.
- **Run completion and candidate review are separately visible in Workspace.** The tested workspace showed Run Completed on the Work summary while its candidate remained pending and Artifact was empty. Review actions were visible but not exercised. Source and routing details are in the companion inventory.
- **Planned and unavailable capabilities are static labels.** Expert is Planned; several More surfaces say Not available yet. These did not expose focusable destinations in the observed Work surface.

## Coverage limits

This is a bounded visual/interaction audit, not a full WCAG or product acceptance review. Evidence is from one desktop Chrome window at its default viewport plus a 175% browser-zoom Files check. I used screenshots and accessibility-tree output, but did not run a screen reader, complete a keyboard-only tab-order audit, test mobile device widths, or inspect every Settings nested disclosure/provider configuration. The menu-open native screenshot was unavailable, and no Attention item row existed to exercise the item-detail state. I did not inspect every chat action-menu command or Home Attention filter combination, or exercise alternative candidate decisions. The companion [source inventory](./source-inventory.md) describes implementation paths not captured here. No state-changing review decision, provider call, or Files submission was performed.
