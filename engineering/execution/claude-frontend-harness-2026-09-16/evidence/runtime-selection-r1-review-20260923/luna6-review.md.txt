## Blocking finding: later bound Runs can change adapter revision under a reused ref

`validateExecutorState()` in [executor-choice-state.mjs](/Users/lesprivilege/Projects/.worktrees/courtwork-runtime-selection-r0-20260923/app/server/executor-choice-state.mjs:143) validates each Run binding against the Session's adapter ID, `configurationRef`, and `choiceRevision`, and freezes an existing Run's own binding. It never compares one Session's bound Run adapter revision with its other bound Runs. `RuntimeStore.createRun()` also checks the current Session ref but does not compare `checkedExecutor.revision` with an earlier bound Run.

The Store API accepts a second completed-session Run carrying the same adapter ID and prior `configurationRef`, but a different descriptor revision (`pi-r1` then `pi-r2`). That violates the R0 contract's “later Runs require the same adapter ID, revision and executor configuration ref” invariant. The composition root ordinarily computes a new ref from revision, and service has a live-revision check, but Store is the durable authority and its own persisted-state validator must reject inconsistent lineages even if a stale/forged descriptor or corrupted state reaches it. Because the descriptor omits protocol/endpoint components, Store cannot recompute the fingerprint; it can compare each new bound Run's revision to the first/current bound nonchild Run for that Session, and compare all bound records on load. Legacy Runs have no known revision, so the first new bound Run remains the one-time pin.

An independent scratch repro creates a real RuntimeStore, admits `pi-r1`, completes it, submits `pi-r2` while deliberately reusing the first ref, closes and reopens the store. Both Runs remain readable with distinct revisions under the same Session/ref. Exact rerun script: `/tmp/cw-runtime-r1-luna6-revision-drift-20260923.mjs`; captured output: `/tmp/cw-runtime-r1-luna6-revision-drift-reopen-20260923.log` (SHA-256 `44fbe11a111e6b0b4c426e627ad5418aaa5bde5c8460a2c402d73b29576f7db2`).

Suggested bounded correction: enforce same adapter ID/revision/ref across every pair of bound nonchild Runs in `validateExecutorState()` (including `previousState` mutations and load validation), and compare a new descriptor revision against the existing bound lineage inside `createRun()` after command receipt lookup. Keep the schema-21 legacy → first bound Run pin exception; keep the child `executorBinding:null` proof exception unchanged. Add one Store regression for second Run revision drift plus persisted/reopen rejection of a two-Run conflicting lineage. No schema bump appears necessary.
