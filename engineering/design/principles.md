# 设计原则与陌生化边界

状态：设计约束草案。资料来源和发布者类别见 [sources](sources.md)，本项目的裁取是设计判断，不冒充品牌官方要求。

## 首要体验

用户能随时回答：我正在处理什么、Agent 做到哪里、它需要我决定什么、哪份成果已生效、失败后怎样继续。成熟感来自普通路径、长内容、等待、中断、失败和恢复同样完整，不能只靠一张默认聊天页。

通用 Work Agent 保留低门槛的自然语言输入、附件和运行控制；Matter、Contract、Evidence 等工程对象只在帮助人判断时转译到界面。零 Extension 时仍可开始通用工作；复杂治理在有正式成果责任的任务中显露。

## 从当前任务建立 fresh context

每次设计先明确目标用户、本次工作、关键失败、必须判断的内容和六条路径，再检索历史参考。Motto TUI、Deswrit kit、Courtwork 与网页端方案都是候选材料，不是新项目默认风格、布局或已接受契约。先写“这个设计解决什么问题”，再问旧材料是否能减少探索成本；过去熟悉不构成现在应采用的理由。

陌生化采用有/无对照：去掉某处装饰或巧思，若理解、定位、操作、判断都没有损失，就没有必要让它持续占用工作面。辨识度可以来自少量稳定的关系表达，不要求每块面板都新奇。每轮原型先只检验少量主张，避免将所有旧项目特色同时加入。

## 工作语义到可操作表示

以下是现有 Core 对象的呈现契约，不新增“UX Schema”作为运行时 ontology。视觉主题可以替换，状态含义和权限后果保持。

| 工作事实 | 用户可理解的表示 | 禁止的捷径 / 验证 |
|---|---|---|
| 当前 Matter 与 Assignment | 工作名称、目标、当前成果和未处理事项 | 不把所有 Session 都等同工作；切换后对象与待处理项一致 |
| Candidate 与有效 Artifact | “待审阅”与“当前采用版本”，差异和版本位置 | 不用同一个 check 图标混指生成结束与已接受；去色后仍可区分 |
| Evidence 与模型解释 | 可回原文的来源、支持/冲突/未支持的关系 | 不能靠相似文本制造引证；模型解释不显示成已核验事实 |
| 不确定性 | 指出缺什么、冲突在哪里、需要何种判断 | 不生成无校准依据的百分比或 confidence meter |
| Review 与提交 | 合法动作、确切目标、待完成检查和状态后果 | 不把每个读取动作升级为专业审批；必须有版本冲突出口 |
| rejected / superseded | 保留原因与版本沿革，默认不混入当前有效内容 | 检索命中不复活旧效力；历史可定位且可返回 |
| Context 的选择与限制 | 必要时展开“本次使用的材料/未纳入项” | 不是强制用户驾驶 prompt；不以隐形截断掩盖遗漏 |

图标是冗余线索；关键事实以文本和可操作证据成立。优先一套主图标语言，按实际对象覆盖、线重、尺寸、可访问名称与许可证比较 Phosphor/Remix 等候选；第三方品牌标识或确有必要的自定义符号可作为明确例外，不因“绝不混用”制造无法维护的绝对规则。库和具体图标尚未选定。

## 从成熟范式中消费什么

- Vercel 的 Web Interface Guidelines 用于键盘、焦点、输入、异步反馈和状态完整性检查。它不是要求复刻黑白外观，也不授权对正式成果做乐观接受。
- Linear 的设计案例用于研究导航、内容层级、密度与高频效率。低噪音不应导致状态只剩低对比色，快捷键也不能成为唯一操作入口。
- Apple 的 HIG/WWDC 用于交互反馈、空间关系、连续性和可访问性。平台原生组件与 Web 条件不同；玻璃、弹簧和阴影不是必须复制的品牌标签。
- OpenWork、DSH 用于寻找 Agent 运行和问题处理的现成结构。文档列出能力不证明 UI 无缺陷，更不证明已有 SE 的 Review/Commit 语义。

## 陌生化的可用范围

可以重新组织工作对象、阅读节奏、留白、字体层级、证据与成果之间的空间关系，使产品拥有辨识度。三个方向必须在信息组织和注意力分配上不同，不能只换颜色。

保留用户熟悉的输入、选择、返回、停止、搜索、链接与键盘行为。新隐喻必须让下一动作更可预测；不要求用户理解“卷宗”“仪表”或“舞台”等内部概念才能工作。

不通过移动停止按钮、隐藏错误、用颜色暗示生效、把确认做成手势、给证据正文降对比、持续播放装饰动画来制造陌生感。新颖性不能抵扣任务错误或恢复失败。

## 本项目的设计约束

| 方面 | 必须保持 | 可探索 |
|---|---|---|
| 信息结构 | 当前工作、有效成果、未处理问题可定位 | 以文档、待办队列或空间层级作为重心 |
| 输入 | 草稿不被流式更新打断；中文 IME 组合中 Enter 不误发送 | 快捷键设置与附加能力的渐进呈现 |
| 运行 | waiting/running/stopping/stopped/failed/unknown 不混同 | 细节折叠、活动摘要、时间表达 |
| 提交 | 服务端确认前只显示“提交中”；过期候选有冲突出口 | 差异、证据与接受动作的布局 |
| 滚动 | 阅读旧消息或选中文本时不强拉到底；提供回到最新 | 长输出折叠、分段与阅读模式 |
| 动效 | 即时输入反馈；可中断；reduced-motion 等价反馈；不阻塞操作 | 用动效解释展开、来源回跳和对象关系 |
| 密度与排版 | 中英混排、长标题、长来源、200% 缩放仍可读 | 正文与工具区不同字体语气；密集/舒适模式 |
| 可访问性 | 语义控件、可见焦点、错误定位、状态非单靠颜色 | 冗余标签、读屏更新聚合、输入方式适配 |

## 对通用指南的局部裁取

乐观更新可用于可逆的界面偏好；正式接受须等待真实提交。载入防闪策略不能推迟 Stop、键盘响应或重要错误。透明材质不能牺牲证据阅读，Web 原型始终允许缩放。无需将网页指南中的每项数值冻结为本项目 token。

原型阶段以正常文本至少 4.5:1、大字至少 3:1、关键非文本控件至少 3:1 对比度作为目标，依据 WCAG 2.2 的[文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)和[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)准则及例外；这些是待测目标，不是合规声明。屏幕截图无法单独证明键盘、读屏、IME 或恢复通过。
