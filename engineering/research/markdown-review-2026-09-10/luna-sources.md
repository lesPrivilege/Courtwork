## markdown-diff-viewer: what the default matcher actually compares

The source supports a useful read-only diff, but “original text” needs a precise qualification. `parseMarkdown(source)` receives the original Markdown string and parses it with unified/remark/GFM ([`parse.ts` lines 1–14](https://github.com/PiotrTrzpil/markdown-diff-viewer/blob/072632e9be4167773ee038d11052bcc0f46fea11/src/text/parse.ts#L1-L14)). The matcher then compares `blockToText(node)` values, which are reconstructed semantic strings: headings get generated `#` prefixes, fenced code gets generated fences, links/emphasis/lists are serialized, and the original delimiter/spacing choices are not retained ([`parse.ts` lines 17–37 and 75–119](https://github.com/PiotrTrzpil/markdown-diff-viewer/blob/072632e9be4167773ee038d11052bcc0f46fea11/src/text/parse.ts#L17-L37)). The pipeline passes those reconstructed strings to `findBlockMatches`, along with wrapper tags, rather than raw source slices ([`pipeline.ts` lines 44–56](https://github.com/PiotrTrzpil/markdown-diff-viewer/blob/072632e9be4167773ee038d11052bcc0f46fea11/src/core/pipeline.ts#L44-L56)).

At the default `normal` match level, the context is similarity `0.6`, at least `5` shared contiguous words, and `pairAdjacent: false`; `strict`, `loose`, and `inline` are explicit alternatives ([`config.ts` lines 14–30](https://github.com/PiotrTrzpil/markdown-diff-viewer/blob/072632e9be4167773ee038d11052bcc0f46fea11/src/config.ts#L14-L30)). Matching computes a Dice bigram matrix, requires a similarity or shared-prefix/run gate, then traces an LCS; exactness is set only by actual reconstructed-string equality ([`block-matching.ts` lines 172–257](https://github.com/PiotrTrzpil/markdown-diff-viewer/blob/072632e9be4167773ee038d11052bcc0f46fea11/src/core/block-matching.ts#L172-L257)). The default post-match stages then handle unmatched blocks, paragraph splits/merges, and moved text ([`pipeline.ts` lines 34–41](https://github.com/PiotrTrzpil/markdown-diff-viewer/blob/072632e9be4167773ee038d11052bcc0f46fea11/src/core/pipeline.ts#L34-L41)).

Therefore the algorithm does support original Markdown as parser input and preserves source line metadata in its host-facing block model, but it does **not** preserve raw Markdown bytes as the match key. It is suitable as a derived semantic/block diff reference. It cannot by itself provide Courtwork's raw quote, source-range identity, exact reanchor, or formal review state. A raw-preserving adapter would need to retain the original byte span beside each derived block and keep matching separate from anchor identity.

## mdProbe locator: source-confirmed sequence

The requested `hash → quote → fuzzy → tree → keyword` sequence is present in the implementation, rather than being inferred from the README:

1. **Hash/integrity fast path.** `step0_integrityCheck` slices the stored range, recomputes `computeContextHash(prefix + exact + suffix)`, and accepts only when both the context hash and exact quote match ([`locate.js` lines 17–27](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/src/anchoring/v2/locate.js#L17-L27); [`schema.js` lines 47–49](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/src/anchoring/v2/schema.js#L47-L49)). This is a hash of the local prefix/exact/suffix context, not a whole-source hash.
2. **Unique exact quote.** `step1_exactMatch` finds every occurrence of `quote.exact` and returns a confident result only for one occurrence ([lines 29–40](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/src/anchoring/v2/locate.js#L29-L40)). Repeated quotes become candidates for later recovery; the first occurrence is not silently accepted.
3. **Bounded fuzzy quote.** `step2_fuzzyMatch` searches a ±2000-character window around a hint and returns `confident` for score ≥ 0.80, `drifted` for score ≥ 0.60 ([lines 42–56](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/src/anchoring/v2/locate.js#L42-L56)). The implementation therefore has a fuzzy path that can report `confident`; Courtwork must keep its separate exact/candidate/ambiguous semantics instead of importing that label.
4. **Tree path with fingerprint and keywords.** `step3_treePath` resolves a heading, restricts to nearby paragraphs, scores MinHash/Jaccard fingerprint, keyword hits, and paragraph proximity, then runs fuzzy matching inside the selected paragraph ([lines 58–95](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/src/anchoring/v2/locate.js#L58-L95)). The fingerprint implementation is MinHash/Jaccard ([`fingerprint.js`](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/src/anchoring/v2/fingerprint.js#L29-L52)) and the tree path records heading/paragraph/character coordinates ([`treepath.js`](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/src/anchoring/v2/treepath.js#L22-L86)).
5. **Keyword fallback.** `step4_keywords` searches each stored keyword, estimates the quote start from `distFromStart`, and fuzzy-matches a bounded local slice ([lines 97–119](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/src/anchoring/v2/locate.js#L97-L119)).
6. **Orphan outcome.** `locate` calls those steps in order and returns `{state: 'orphan', score: 0}` when no result exists ([lines 121–142](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/src/anchoring/v2/locate.js#L121-L142)). The schema documentation names `open`, `resolved`, `drifted`, and `orphan`, and says drift/orphan are derived on load ([`SCHEMA.md` lines 164–173](https://github.com/henryavila/mdprobe/blob/2f55ec2e56f15494062f91e81c88ec55a6dd271e/docs/SCHEMA.md#L164-L173)).

The useful Courtwork lesson is the ordered evidence ladder and the separation of exact, recovery, and orphan paths. The implementation is not a no-silent-misanchor guarantee: the exact step does not choose the first duplicate, but `locate` uses the first duplicate as the fuzzy hint, and a fuzzy score of at least 0.80 can still return `confident`; tree and keyword recovery can return `drifted`. It has no Courtwork-style `ambiguous` outcome or explicit confirmation requirement in this locator function. It also uses UTF-16 offsets in its schema and YAML/sidecar persistence. Courtwork's A0 contract must therefore retain `ambiguous`/`unavailable`, expose recovery evidence, and require explicit confirmation for a new binding rather than importing mdProbe's labels or score thresholds.

## Reuse boundary for vanilla Courtwork

Courtwork is a native ESM application with a Marked + DOMPurify reader, one Core SQLite owner, and no React, Svelte, Go/Wails, sidecar review store, or second review service. The source evidence supports these bounded choices:

| Reusable idea | Courtwork form | Boundary that must remain explicit |
| --- | --- | --- |
| unist/remark source positions | Isolated parser experiment or a later vendored/adapted parser module behind the A1 source projection contract. Keep raw bytes, parser input, displayed segments, and parser version separately recorded. | unist describes offsets as UTF-16 code units ([README](https://github.com/syntax-tree/unist/blob/8b10b6113c1463113b879f423d605547e04efd0d/README.md#L167-L184)); Courtwork's file-content contract is code-point based. mdast `position` alone cannot prove raw-to-display selection mapping. BOM, CRLF, entities, references, repeated blocks, and combining characters require independent fixtures. |
| mdProbe's evidence ladder | A pure derived locator candidate, with context hash/quote/tree/keyword evidence exposed to the service and an explicit confirmation action. | Never write an mdProbe YAML/sidecar owner. Similarity, fuzzy score, heading path, or keyword hit can rank candidates but cannot turn a new revision into exact or resolve a comment. Preserve `ambiguous`, `orphan`, and `unavailable` outcomes. |
| markdown-diff-viewer's blocks and inline diff | A read-only block/diff adapter whose model is serializable and whose source identity remains the existing file revision/hash. | Diff pairing is derived and explainable; it must not mutate anchors, accept a Candidate, or claim semantic equivalence. Preserve whole-block fallback for rewrites and ambiguous pairing. |
| streamdown/remend incomplete-markdown handling | Only a future streaming reader experiment, after a bounded need is demonstrated. Port test vectors or a tiny local normalizer if needed. | Do not pull in the React component, Tailwind classes, or permissive default hardening. Its default harden config allows `allowedProtocols: ["*"]`, `allowedLinkPrefixes: ["*"]`, `allowedImagePrefixes: ["*"]`, and data images ([source](https://github.com/vercel/streamdown/blob/e0ce123f493e2a7eb6d304be62ca0040ab8c3881/packages/streamdown/index.tsx#L292-L305)); Courtwork retains its own allowlist and negative security corpus. |
| md-review-server selection/context UX | Use as interaction research for block selection, context display, review rounds, and version navigation. | Do not copy its sidecar storage or infer CAS/idempotency from its JSON patch loop. Formal review events stay in the existing Core transaction boundary. |
| upmark reading polish | Borrow reader-width, outline, typography, and calm reading behavior as visual references. | Do not import Go/Wails/Svelte or `goldmark.WithUnsafe`; raw HTML and links/images still pass Courtwork's sanitizer and URL policy. |

No upstream is a direct dependency recommendation for the first vertical slice. `remark` is the only plausible parser candidate, and only after A1 parity proves its coordinate conversion and projection behavior. The remaining sources are algorithm or interaction references. This also preserves the current read-only renderer fallback while A1 is evaluated.

## Bounded Terra handoff

The mature, separable Terra slice is **MR-T1 · Reader representation**, after Astra freezes A1 input packets and the projection profile:

- Implement one vanilla ES-module reader module with semantic Markdown blocks, outline/find/jump, loading/error/unsupported states, and a read-only block-target action.
- Consume only A1 DTOs and current V1 tokens. Do not guess source ranges, implement fuzzy re-anchoring, own `app.mjs` routing, write Core, add a dependency, or modify shared CSS/global tokens.
- Keep the work in the assigned reader module and local styles. Astra owns host lifecycle, service packets, security allowlist, and the eventual Core seam.
- Verify 1440px and 390px layouts, light/dark mode, 200% zoom, long documents/tables, keyboard focus/return, and the safe/unsupported corpus. A block target may show a selected quote, but it must not display a save or review acceptance that the service has not confirmed.
- Report the fixed implementation SHA, actual packets and fixtures, rerun commands, and any unsupported input. Do not claim annotation persistence, fuzzy recovery, semantic diff, or model quality from this slice.

This keeps Terra's task concrete while preventing it from choosing a parser, inventing a locator contract, or creating a second state owner. It is ready to dispatch only after A1's source projection DTO and fixture oracle are accepted.

## Verification limits

- Existence, commit, package metadata, README claims, and the cited source paths were checked from the seven fixed shallow clones listed above.
- Tests and applications were not run; no npm/pnpm/go install was performed; no paid provider or networked runtime was used.
- The source inspection verifies what the code currently does at the recorded SHAs. It does not establish browser compatibility, performance, security completeness, or Courtwork parity.
- Any dependency or vendoring decision remains Astra-owned and must include Courtwork's coordinate, sanitizer, license, and migration checks.
