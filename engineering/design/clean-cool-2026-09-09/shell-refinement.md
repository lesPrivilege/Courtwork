# 用户补充：模块首页、独立 Settings、标签式工作区

2026-09-09；基线 `cc99571`。本页记录用户在七张截图之后明确提出的方向，优先于本包上一轮不相容的建议。属于供 Claude 消费的设计更新，本次不实施 UI。

## 已确认的结构方向

1. **保留一版模块化 Home。** 热力图、邮件、日历、attention 助手、模型管理／用量统计可以解耦实现。上一轮简洁 Home 是一个版本，不是禁止首页卡片的永久规则；按模块能力逐项交付，无需等待全部集成才制作外壳。
2. **边距、留白、对齐是基本质量。** 可以提高内容可发现性，但不能把“更紧凑”解释为填满屏幕或消灭留白。列表、正文、设置和 dashboard 的密度分别设计。
3. **Settings 替换全局导航。** 进入 Settings 后取消左侧 Home／项目／会话 dashboard 栏，只保留设置自身导航和 Back to app。上一轮 `models-preview.png` 的双重侧栏不再是目标；无需再问是否可以移除全局侧栏。
4. **右侧工作区展开靠近浏览器标签页。** 将用户的“chrome tap”按截图理解为 Chrome 风格 tab strip：顶部标签与内容连为一体，可切换／关闭已打开对象，紧贴工作区顶部 chrome。不是增加任意网页浏览能力或地址栏。右侧工作区规则适用于 Work；进入 Settings 时使用独立设置版式。

这些结构方向已由用户给定；新生成图的具体比例、文字、颜色和装饰仍是可调整视觉输入，不自动成为逐像素合同。

## 最新补充：窗口控制、贯通三面与 composer 主位

用户进一步建议预留 window control，工作台展开接近三个上下贯通的工作面；首页热力图等缩小，避免占据 composer 的视觉空间。提供的 frontier 产品范式是成熟交互参照，接近这些实践符合用户习惯。本节优先于旧图的相反表现；无需为追求差异而重新发明导航、设置、标签或输入框的交互。

### 原生窗口控制预留

沿用 [现有 shell 合同](../../../docs/interface-components.md)：桌面宿主左上默认预留80×52px；overlay宿主按实际titlebar环境值调整。此区域不放brand、返回、搜索、tab、折叠或其他产品控件。品牌与产品操作从安全区之后开始；保留连续的可拖动区域，输入、按钮及标签不能被拖动层覆盖。

此约束覆盖Home、Work、独立Settings与侧栏折叠态。原生窗口控制由宿主绘制，网页不画假的红黄绿按钮。普通浏览器没有原生覆盖时不叠加无意义的第二层安全区。新概念图若没画预留，只能作内容布局参考；Claude实施仍须验证所有可聚焦元素与安全区不相交。

### 三个上下贯通的工作面

按“左导航／中对话与输入／右文档工作台”理解：三面共享窗口上、下边界和一致的顶部chrome基线，自顶部安全带以下延伸到窗口底部。右面在展开态是固定分栏，tab strip接在它的顶部，正文延伸到底；中面composer固定在自身底部，正文独立滚动。不是三个悬浮卡片、三个上下堆叠区，也不要求三等分宽度。

面之间使用轻分隔线，内部各留阅读边距；贯通不等于文字贴窗边。分栏宽度服从阅读：保留既有中面可读宽度，在容纳不下时收起左导航、调整右面或切主次视图。1440px下无法同时容纳256px导航、640px中面和宽文档时，应明确选择折叠/切换策略，不能静默把中面压到550px。更宽视口可保留三面；设置仍沿独立两列布局，不被强行放进工作台三面。

### 首页模块退为辅助

`home-modular.png`中的四块大卡和大热力图不再作为尺寸目标。composer保持首页最强的可操作锚点：完整输入区、清晰发送入口和周边留白优先；标题不压过输入，统计不成为视觉主角。

热力图缩为一条辅助摘要或小模块，初始可试宽280–360px、高96–140px（包含标题，属待验证初值）；小格旁提供可读的区间与详情入口，完整统计另开工作面。不得靠缩小文字到不可读来完成缩小。Usage/Models采用简短摘要行；邮件／日历先显示1–2条相关内容或轻量空态。Attention有需要时可突出一项待处理，不让所有模块都采用同等强度。模块放在composer之外的次级带，可折叠／移除；无数据不占一张大空卡。

验收时先看输入区是否仍明显且完整，再看辅助信息是否可扫读；热力图不会把composer挤出首屏、挤窄或夺取首屏中心。窗口高度变化、模块全部出现和长标题都要检查。不把“composer优先”写成固定百分比大空白，按实际内容和视口保持呼吸感。

## 模块首页的解耦约定（施工草案）

一个模块负责一个用户问题和自己的数据读取。Home 宿主负责布局、显隐、加载占位与键盘顺序；模块不另建会话／成果／连接真源，也不以截图样式强迫统一所有后端。

| 模块 | 数据归属与第一段 | 不可伪造的状态 |
|---|---|---|
| Attention | 先消费既有 work-summary 的问答／授权、失败／unknown；规则排序与辅助解释后续可独立做 | 缺少人工成果复核汇总时，不能声称该清单覆盖所有工作未决项；解释不代替决定，不自动发邮件或接受候选 |
| Activity / 热力图 | 单独补时间桶聚合契约：事件定义、时区、区间、去重、分页完整性；当前BE-1/3差距单列 | 空白桶可表示无数据；unknown／缺覆盖不能显示0。显示的是活动量，不是完成或生产率 |
| Mail | 独立只读来源 adapter，先摘要与深链；身份、账户scope、刷新时间由来源给出 | 未连接与空收件箱不同；没有连接不展示虚构邮件；发信另有明确授权和动作接口 |
| Calendar | 独立日历来源 adapter，明确时区、全天事件和刷新边界 | 未连接不画“今天无安排”；创建/修改/发送邀请不由卡片隐式触发 |
| Models | 首页只读当前默认/可用性摘要和已有设置入口；编辑仍在Settings | 不新增第二个配置表单或本地连接注册表，不把preview结果标为已保存 |
| Usage | 单独聚合真实usage记录；明确输入／输出token、缓存token、计费来源和统计区间 | characters不是tokens；未知费用不是零费用；估价和实际账单分名。未上报显示Not reported |

共通显示状态至少区分 loading、ready、empty、not connected、unavailable/error、stale；缺少接缝时提供诚实空态或不安装该模块。模块刷新互不阻塞，隐藏不意味着删除来源、撤销连接或取消运行。首版可用有界预置布局与模块显隐，无需同时实现任意拖拽网格、插件市场或第三方代码执行。

可先交 Home shell + Attention + Models link；Activity/Usage补统计契约后接入；Mail/Calendar各自接来源。设计原型允许标明合成数据，正式产品不可借演示数字充数。模块首页本轮不裁定替代默认简洁首页，可作为一个布局版本供后续选择。

## 呼吸感：实现初值与验收对象

以下数值为下一轮可测初值，最终随选中图稿收敛；不是对参考截图的精确像素测量。

| 区域 | 建议约束 |
|---|---|
| Settings | 唯一导航列约240–256px；桌面内容左右至少48px，宽屏可56–80px；内容列约760–960px上限，不能把控件拉满整个屏幕 |
| 设置分组 | 组间40–48px；组内行垂直16–24px；label/help同起点，控件同右边界；说明可换行，不压缩字号 |
| Home 模块 | 主区外边距24–40px；模块gap20–24px；卡内20–24px；同一行模块标题共基线，不把所有模块强迫成同高度 |
| Chat / Work | 阅读列与composer边界一致；右区打开后先收非必要信息，再切换布局，避免三列互相挤到不可读 |
| 标签与正文 | 标签条高约40–44px；正文距其下边缘24–32px；标签截断保留全名访问途径，关闭命中区与选中区域分开 |
| 窄屏 | 外边距16–20px；设置导航变独立列表／选择器；Work使用主次视图切换，不能缩放整张桌面三栏；触控目标≥44px |

验证空态、短/长列表、长标题、中文说明、200%缩放及侧区展开后的重排。呼吸感来自稳定的分组距离和可阅读宽度，不来自给每一页加固定大空白。标题、正文、按钮、card边界分别对齐；文字基线和控件视觉中心需要目视，几何检查不能代替。

## 标签式右区：宿主契约草案

紧凑态可以保留目录／活动摘要；打开确切对象后进入右区 tab 内容。用户展开时以固定顶部tab strip与独立内容滚动为主，不用遮罩压暗聊天，不再套大圆角模态卡。再扩展为更宽阅读面时保留同一对象和标签状态。

- tab key 必须包含对象identity、scope、读取类型和必要版本；标题和数组序号不充当identity。同一来源不同版本可区分；重复打开同一identity聚焦已有tab。
- 区分读取tab与领域Review；预览文件不是接受成果。标签只组织可读取对象，不增加BE-2尚未提供的多文档领域实例能力。
- 保存每tab滚动位置和局部草稿；切换/折叠/扩展不重新Run、不重置renderer或提交动作。关tab只关闭视图；有未提交草稿时用明确的保留/舍弃交互，不静默丢弃。
- 关闭活跃tab选择邻近tab；全部关闭回紧凑目录；返回Chat恢复之前focus。键盘支持tablist方向键与明确的关闭动作，不劫持浏览器快捷键。
- source stale、renderer缺席、读取失败各在该tab中呈现；其他tab仍可读。不把未知回执、关闭tab或producer完成当成正式决定。
- Shell拥有标签、尺寸、focus和实例生命周期；renderer只占宿主分配区域。多实例必须先核对现有BE-2及renderer契约，第一段可以只有一个受信活动文档，不为视觉效果谎称多实例完成。
