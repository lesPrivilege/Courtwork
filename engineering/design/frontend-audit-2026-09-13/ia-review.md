## Findings

**Usage local return — source review passes, with native-dialog behavior still delegated to browser evidence.** `inspect()` records the originating `data-usage-focus`, scroll offset and view before opening a drill. Pagination preserves that origin; `returnToUsage()` increments `detailGeneration` before removing the drill, so late detail responses fail their generation guard, then restores view, scroll and focus without fetching a new observation. All inspected activation paths visible in the commit have focus keys: daily heatmap, ranked model, stacked segment, legend, model totals and day totals. The committed `app/tests/usage-view-navigation.test.mjs` now uses 26 synthetic runs to cover late-response suppression, same-snapshot return, origin focus and scroll, rank-row round trip, Next → Previous → Back origin preservation. The author reports the expanded case passes 1/1; I did not rerun it. TinyDOM cannot establish native dialog focus containment or rendered scroll geometry; retain the real-browser interaction evidence as the source for those claims.

**Files reader return — retaining `comparisonButtons` is consistent with the DOM lifecycle.** `cancelRequests()` aborts pending details/comparisons and invalidates request generations, while `returnFromFile()` restores the retained Files DOM and focuses the original opener or its stable `data-focus-key` replacement. Clearing the map there would strand completion callbacks from finding the still-live Compare button. The map is reinitialized on session change and reset, matching its state owner. The `intake-ui.test.mjs` case exercises a reader round trip, then starts a comparison and confirms its same button remains keyboard-focusable and announces busy state while pending. No source-level defect found in the bounded path reviewed.

**Runtime default provenance — the suppression guard is appropriately narrow.** `routineDefault` requires a writable scope, a configurable resource, no false parent gate, a winning `source default` entry, and equality between the recorded provenance value and authoritative `resource.exposed`. Parent-gate, ceiling and provenance/exposed disagreements therefore stay on the row; override actions remain represented. One caution for the test review: this branch should be covered with paired normal-default / explicit-override / parent-gate fixtures, since suppression is easy to broaden accidentally. I did not independently execute those fixtures.

**Runtime disclosures — state is preserved by stable per-mount keys.** Before replacing each rendered mount, `render()` collects open `details[data-runtime-disclosure]` values, then reapplies openness to matching keys in the new tree. Scope disclosures are keyed by view; unavailable-capability disclosures use fixed pane keys. The short deny/ask warning remains outside the scope disclosure. This is consistent with the current composition; evidence should continue to verify a disclosure stays open after a refresh/polling render and that hidden scope metadata remains reachable by keyboard.

No additional blocking finding surfaced in these bounded paths. This is a source-level review, not a claim that the complete repository or all runtime states were accepted.
