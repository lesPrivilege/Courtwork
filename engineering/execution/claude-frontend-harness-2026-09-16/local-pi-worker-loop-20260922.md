## Outcome and adopted boundary

A CW parent can delegate a bounded source-reading job to an **upstream Pi process**, receive an attributable retained result, and distinguish successful execution, refusal, cancellation and unknown outcome after failure. A native process is genuinely exercised against a deterministic loopback model; this proves integration, not model quality or live-provider access. Governed coding is a subsequent capability within this direction, not something a read-only milestone claims.

CW already owns Spark assignments, attempt admission, exact sources, budgets, retained results and explicit consumption in `app/harness/subagents.mjs` / `subagent-state.mjs`. The accepted Pi Runtime Port is an **in-process SDK** implementation. The missing seam is an external process under those existing owners. Consume both; do not implement another assignment ledger, queue, artifact store, shared transcript, permanent orchestrator or agent framework. `child-execution.mjs` is conformance-only; its abort race cannot prove a process stopped.

Use Pi as the upstream/public name. Keep existing IDs and historical evidence intact. Installed binary, compatible protocol, available authentication and admitted capability are four different facts. Runtime replacement concerns future admitted work; it does not transfer an active native session.

## Permissions and capability decision

The initial consumer is bounded consultation/source reading. The process receives approved source versions or Host-owned source callbacks, never an unrestricted workspace read tool by implication. Disable native tools and automatic executable extension discovery where the selected upstream actually permits it. If a small explicit CW extension is needed for callbacks, verify its public upstream contract and keep each call's authorization/effect in the Host owner. Do not fork Pi or imitate unsupported native permission protocols.

A CLI tool list, system prompt, cwd, worktree or separate HOME is **not an OS sandbox**. Configuration hygiene protects against accidental ambient authority; the runtime binary remains a trusted local process. Record that trust boundary honestly. If required tool control cannot be enforced at the model-reachable boundary, retain a tool-less bounded invocation and return the missing Host callback seam; do not enable filesystem/shell coding as a workaround. Read-only execution does not imply no credentials/network unless actually constrained and tested.

Future write/check delegation must use the existing repository candidate, approval identity and fixed check owners, with an explicit leased increment and fresh evidence. Model output, exit zero and result consumption do not grant formal Work acceptance. Native child agents remain native-owned unless CW actually creates and accounts for their attempts.

However, current schema19 only checks generic event type/data structure. A19 reader would ignore the new recovery authority while retaining old reconcile/retry behavior. Therefore L3 is authorized to introduce RuntimeStore20 with validated19→20 migration and exact backup, retaining Core4/bridge5. Test the actual19 reader refusing20 without writing. Preserve old events byte-for-byte and do not rewrite past Pi/remote histories. Schema20 is now reserved for this task's narrowly specified L3 compatibility boundary; do not bump main entry points before delivering that source.

All new authoritative records require strict payload and sequence validation, including references to the actual assignment/attempt/session/Run, exact admitted adapter/binding and retained packet/result hash/length. Validate on load and every mutation. Enforce uniqueness/idempotency and CAS inside the existing store mutation, with Host-only writers; arbitrary native events may not impersonate Host dispatch/result receipts. Await durable dispatch intent before spawning; a repeated command/receipt must not spawn again. Retain exact output bytes before any completion/publication claim; missing or mismatched bytes cannot trigger re-execution. Treat PID as observation, not durable process identity or permission to kill a later reused PID. Bound records and diagnostics.

**Reject: delivery alone changes Spark to resolved.** The existing [Spark contract](../../../app/docs/spark-agent.md) requires retained findings and actual reads of every assigned source. Read/adopt/reject/defer stay explicit and the existing human source-expansion check remains. If a future consultation definition uses delivery rather than read coverage, propose that explicit definition separately; it is not silently substituted for Spark here. Source inclusion, model-reported interpretation and formal acceptance remain different facts.

**Adjust: existing reconcile is an integration risk.** `Subagents.action(reconcile)` currently converts an unknown attempt to failed after checking only that its Run is terminal. That suffices neither to establish an external child's termination nor to resolve an uncertain dispatch. For local-process attempts, prevent this route and subsequent retry from removing an unresolved process/dispatch fence on that evidence alone. A terminal local Run, EOF or a persisted PID is not decisive process ownership evidence. No new human recovery endpoint is required; retain an honest blocked state when conclusive evidence is unavailable. Confirmed pre-dispatch refusal or observed owned-process completion/termination should keep the supported result classification instead of being automatically labelled unknown.

Required counterexamples cross the actual Host/reopen/action/admission path: crash between durable intent and spawn; crash after spawn but before PID/native receipt; retained output before publication; malformed/cross-attempt/duplicate receipts; source revocation before dispatch/publication; old reconcile/retry attempting to clear an unknown local attempt. Assert zero second spawn/provider request and no false source-read/acceptance. Prove successful exact result retention and explicit consumption separately. Keep source and unknown-result access revalidation with existing owners.
