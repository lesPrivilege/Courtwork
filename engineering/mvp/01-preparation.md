# MVP 前置准备工单

遵守 [共用规则](README.md)。本组以文档、取证和裁决为产物。

## MVP-01 范围与执行章程

依赖：无。

工作：裁决工单包的拟议 MVP 范围、首个任务和非目标；明确执行环境、实现目录、角色及各阶段允许动作。仅开工单不等于派发实现。

产物：范围裁决、Assignment 模板实例、变更规则；标明代码/本地运行/真实模型各自准入。

验收：每项能力能映射到工单；未指派 Reviewer、未定预算或未获执行范围不能被写成 ready。若不接受文本备忘录任务，更新样本、GUI 路径及依赖后重审，不继续沿用其假设。

## MVP-02 Runtime 与语言版本卡

依赖：无。

工作：对 OpenCode server/SDK 与 Pi coding-agent SDK 固定可获取发行版/commit，核验协议、事件、取消、恢复、pending、Context 注入、工具隔离、许可和维护方式。DeepSeek 是 provider 对照，不能未经核验当作同层 Runtime 替代品。

产物：RD-001 输入版本卡、选项差异、语言/进程边界候选、弃用与退出条件。

验收：每项关键能力有固定版本的官方来源，缺证据明确 unknown；社区 GUI fork 的存在不算接口可靠性证据。若需自行维护完整 fork 才达标，列维护成本并允许两候选都不选。

## MVP-03 Core 契约与存储试验输入

依赖：MVP-01。

工作：将 Core 草案具体化为字段、状态转换与边界示例；定义 request/Matter/Run/version/Candidate/Decision identity、错误类别、可信 Review 入口、幂等载荷绑定、CAS、补偿及原子边界。比较 SQLite 状态加审计与事件溯源。

产物：契约版本、RD-002 输入、提交与故障时序图、数据迁移/恢复约束。

验收：同键异载荷、并发旧版本、伪造身份、验证后来源变化均有唯一明确结果；区分工具权限与成果接受。不要求实现通用事件总线或多用户身份系统。

## MVP-04 样本与证据规范

依赖：MVP-01。

工作：制定可复用合成/脱敏输入、期望结论和异常变体：证据缺失、错版、否定含义、冲突、未完义务、长文本、无候选及失败。分开工程真实性与专业结论正确性。

产物：带版本的样本说明、预期/实际记录模板、日志脱敏与保存规则、Reviewer 任务脚本；关联三个 RD。

验收：每条六路径可复现，错误可被独立检查而非凭模型自评；无默认复制原项目敏感业务材料，无未经运行填写的 PASS。

## MVP-05 当前任务的 Design brief

依赖：MVP-01、MVP-04。

工作：先定义工作目标、阅读密度、四个等内容比较状态及注意力优先级，再按需消费历史材料。逐项限定有用陌生化机制及其无装饰对照。

产物：D0/D2 brief、信息架构候选、P0 状态映射、A/B/C 比较标准；可废弃既有三方向。

验收：接受/未接受、运行/工作完成、权限/Review 均可区分；停止和错误恢复不藏在新奇隐喻里；无默认继承旧字体、配色、术语或整份 style guide。

## MVP-06 成熟 GUI 定向取证

依赖：无。

工作：按 Design D1 观察可访问的 OpenWork/DSH 关键路径；核验 Vercel、Linear、Apple 文档/skill 的作者、版本及许可。记录实际 UI 与文档声明的差别。

产物：版本/入口/窗口/操作/截图或录像索引、可借鉴机制及不适用边界，更新 Design 来源。

验收：至少定位主路径和失败恢复的证据缺口；访问受阻则交付明确缺口，不冒充已观察。可凭缺口说明继续自主设计，不能将“取证工单完成”解释为所有上游已经实测。
