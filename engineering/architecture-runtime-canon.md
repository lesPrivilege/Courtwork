# Runtime and Work

The current authority is [architecture](architecture.md): five responsibility layers, Host composition, data ownership and allowed dependencies. [Current](current.md) routes active work and evidence. This page explains the vocabulary; it does not accumulate dated capability claims.

## Mechanism and semantics

Courtwork reuses the locked Pi loop for execution. Provider protocols, MCP, SQLite, Git and sandbox libraries supply mechanisms; external projects supply bounded design references. Courtwork still owns its adaptation, admission, effect reconciliation and formal Work contracts. Reuse is implementation provenance, reference is a studied precedent, and independent acceptance is an engineering result. None substitutes for another.

| Responsibility | Meaning | May not become |
|---|---|---|
| Adapter | Translate a Provider or Runtime protocol faithfully | A source of Work acceptance rules |
| Harness Core | Execute an admitted Run through the reused loop and its lifecycle | A second implementation of professional Work semantics |
| Harness Extension | Provide admitted tools, context, communication and environments | Self-granted execution or formal write authority |
| Work Core | Maintain lawful Matter, source, candidate, decision and obligation transitions | A container for provider SDK behavior, native session internals or UI decisions |
| Work Extension | Supply professional constraints, validation and presentation requirements through a Work adapter | Domain-specific branches in the generic runtime loop |

The Host composes these responsibilities and owns Session/Run identity, permissions, execution receipts and recovery. Its private Work integration translates execution facts and scoped artifact access into the existing Work contracts. This integration is Courtwork-owned code, not an upstream feature or a new architectural layer. Remaining coupling is documented in [architecture](architecture.md#runtime-port) and its original owner task; do not describe a partial extraction as full runtime independence.

Runtime logs and summaries are execution evidence and navigation aids. Formal Work state remains with Work Core. Opaque execution descriptors may be retained as provenance without letting a provider name or a completed Run decide an accept/reject transition. Storage, runtime and GUI replacement each require evidence for the contracts they cross.

## Product vocabulary

Role describes a job and its review responsibility. Kit supplies reusable domain knowledge and bounded methods. Agent profiles bind admitted resources and choices. Runtime executes the loop; Provider supplies model access; Model identifies a chosen model; Environment constrains execution. Their names do not imply a new registry or schema. Use **Pi** publicly and in development prose while preserving underlying persisted IDs and historical evidence.

Local Agent Orchestra continues the five layers and the continuable workspace. It is a composition direction, not a sixth layer, a second ledger or a generic workflow engine. [Supported preview](../app/docs/supported-preview.md) owns what startup actually wires. Current Kit and profile support is routed by the [Attention/Kit reading index](research/attention-assistant-20260927/INDEX.md); an earlier direction document's unimplemented list is not current support status.
