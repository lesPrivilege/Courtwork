## Astra 本轮接续：先呈现，再逆向合同

1. 立即在当前隔离候选上制作可交互Fake UI action row，无需等待后端或SD-FIX正式接受。与D1/D2共享文件时由同一Astra串行编辑；最终组合验证仍保留。复用现有Lucide、icon/action/tooltip、语义与来源index，不复制参考站SVG或强推新图标族。
2. 覆盖完整动作集合与上下文，而不是补一枚copy就结束：复制、朗读、赞/踩、再生成、分叉、分享、固定及更多菜单；按消息角色和状态给出摆放裁定。不要机械照搬四张图的并集为每条消息常驻按钮。
3. Fake UI通过显式合成fixture/adapter提供idle、hover、focus、selected、busy、success、error、unavailable与流式状态，可点击切换验证；与生产adapter分离，标明演示来源。缺后端也必须能验证布局和状态，不能只留不可操作的灰色占位。Fake成功不写真实反馈、不发请求、不创建Run、不外发、不启动付费语音服务。
4. 已有真实能力（如精确消息范围复制、已存在的菜单/读取动作）直接沿原handler接线。无真实能力的产品入口明确当前不可用及原因，不伪报成功；Fake演示仍完整保留。前端退出条件不要求这些后端全实现。
5. 由Fake UI反推下表：每项记录consumer/intent、对象身份、输入输出、状态转换、幂等/取消/权限、已有owner/接口证据、缺口和后续单。先查已有合同及A账，不因旧盘点说“无owner”而忽略今天已有实现。不从图形直接新建endpoint或状态真源。
