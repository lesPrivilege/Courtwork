# E1 corrected scope assessment

This note supplements `/tmp/cw-e1-independent-review-20260923.md`; the original raw report is preserved.

## Correction to the stale-scope finding

The real K3 snapshot uses `sessionScope.kind: "project"` for the ordinary Chat created by the Host fixture. Therefore the frontend must not require `sessionScope.kind === "chat"`; both ordinary `project` Chat scope and any other explicitly ordinary non-global scope remain valid. The safe condition is:

```text
choice.sessionId === currentSession.id
&& choice.snapshot exists and is ready
&& choice.snapshot.sessionKind !== "global"
```

The previous report's phrase “ready snapshot whose `sessionKind` is `chat`” was too restrictive and should be disregarded.

The source does establish a narrower race: `syncAgentChoice` reads `choice` before calling `agentChoice.load()` and computes `shown` without checking `choice.sessionId === session.id` or read readiness (`app/web/app.mjs:3812-3821`). On a Session transition, `readSnapshot` clears the controller snapshot and emits loading before the new read answers (`app/web/agent-choice.mjs:167-179`). Thus the chooser's visibility and Send projection can be computed from a mismatched or not-yet-ready state during that transition. The source review does **not** prove that the old Agent label remains: the controller clears `snapshot`, and the view recomputes its label from the emitted state. The concrete requirement is to keep the chooser hidden and its Send contribution non-authoritative until the current Session's snapshot is ready, while preserving ordinary `project` scope.
