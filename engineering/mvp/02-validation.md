# MVP 局部验证与裁决工单

遵守 [共用规则与执行准入](README.md)。本组包含需单独明确执行范围的实验，当前文档不代替其授权。

## MVP-07 Runtime Adapter 验证

依赖：MVP-01、MVP-02、MVP-04。

工作：按 RD-001 用最小适配试验比较两候选，优先可控 provider/工具；仅对进入决选者在预算内做真实 provider 验证。观测启动、取消、重连、pending、非法参数与 Context 注入。

产物：可复现 RD-001 记录、真实/模拟分栏、能力矩阵、薄 Adapter 契约与技术推荐。

验收：取消三个阶段、失联/重启、重复回复、跨 Run 回复、无人答复、预算阻止均有结果；unsupported 不被接口假装支持。只会流式聊天不通过；候选均失败则退回范围或换候选，不强行选型。

## MVP-08 Commit 与恢复验证

依赖：MVP-01、MVP-03、MVP-04。

工作：独立于 GUI/真实模型实施 RD-002 的 C1—C9；比较存储方案所需复杂度，验证可信入口和实际工具能力边界。

产物：事务及 kill-point 证据、存储选择推荐、威胁边界说明、可复现故障集。

验收：原子提交、丢 ack 幂等、CAS、来源变化、产物完整性、索引/Session 丢失、迁移/备份和直写绕过均有实际检查。目录隔开不算沙箱；边界不能成立即拒绝相关工具能力或退回架构。

## MVP-09 等内容视觉方案与裁决

依赖：MVP-05、MVP-06。

工作：制作至少三套信息组织有实质差异的方向，在相同内容/状态/窗口下比较；巧思带有/无对照，来源缺口显式保留。

产物：D2 视觉候选、可读性/判断负担比较、用户接受/修改/全退的 Design 裁决。

验收：硬失败不能由审美得分抵扣；保留被拒原因。工单到选定可推进方向才关闭；静态图不声称交互通过，不凭作者偏好默认选择。

## MVP-10 可交互状态 Prototype

依赖：MVP-03、MVP-04、MVP-09。

工作：按 D3 用固定 fixtures、延迟/故障开关演练六路径；交付 tokens、组件状态、文案、焦点/键盘与投影接口。

产物：明确标识模拟边界的原型及演练记录、设计交接包。

验收：适用 UI01—18 均有状态/恢复出口；IME、草稿、滚动选择、停止未知、pending 重现、旧版本冲突可复现；不能只用成功 toast。此处刷新/提交是模拟，真实可靠性留给 22—24。

## MVP-11 Review 与 Context 任务验证

依赖：MVP-04、MVP-08、MVP-10。

工作：执行 RD-003 的 Review packet/原始 trace/非结构化输出比较，以及状态投影与按需历史对照；结合 Core 试验，不把原型操作算真实提交。

产物：独立任务观察、遗漏/误判记录、Context 必需字段、修改后的 Review 契约和设计。

验收：参与者能发现预埋错版、缺证据、否定与义务问题；错误若仍导致误接受须修订重测。记录小样本限制，不虚构统计结论；GUI 与 Core 分别列通过项和未测项。

## MVP-12 真实切片施工裁决

依赖：MVP-07、MVP-08、MVP-11。

工作：汇总 RD 和 Design 证据，冻结一个 Runtime/provider、语言与进程结构、数据库/提交方案、设计方向、依赖版本和局部退出路径。

产物：工程裁决、后续施工 Assignment、接口基线、剩余风险与停止条件；明确实现目录和真实调用预算。

验收：关键不变量无未解决阻断；弱证据或未观察上游 UX 可保留为限制，但不能豁免取消、授权、持久提交等硬门槛。裁决可接受/缩小/退回，只有明确接受的范围进入施工。
