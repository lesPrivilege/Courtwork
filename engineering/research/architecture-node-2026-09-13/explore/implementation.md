## Chat、Attention、Spark、Expert：各自路径与闭环缺口

| 产品责任 | 当前确有的执行路径 | 不成立的等号 / 可检验边界 |

| Spark | [`server/index.mjs`](../../../../app/server/index.mjs) 提供 `GET /api/v5/work-derivations`；[`RuntimeService.getWorkDerivations`](../../../../app/server/service.mjs) 校验项目、page / snapshot token，再调用 Core [`derivations.project`](../../../../app/core/derivations.py)。[`spark-view.mjs`](../../../../app/web/spark-view.mjs) 读取和投影当前/过时衍生记录，并可把人引回 Work。 | 这是 Core 的只读观察与投影；不执行模型 Run、不写 Candidate / Attention、不解决义务。文件头仍写着 BE-41 endpoint “not implemented / 404”，和同文件实际请求以及 server route 矛盾，是已实现代码上的陈旧注释；不能按注释把当前路由登记为不存在。 |
| Expert | `index.html` 导航中的 Expert 标为 `Planned`。固定 Runtime profile / instruction 和 Work Extension 是存在的相邻能力；`app/harness/` 也有有限协作对象。 | 当前没有可发布的一般 Expert 对象/registry/分发市场、跨 Runtime Expert delegation 或自动“Spark 检查 → Expert 修改 → Attention 关闭”loop。profile 不是 Expert，Work Extension 不是一个自主 agent，Thread 协作工具也不证明该闭环已实施。 |

因此实际已有的是：受限 Pi Chat、局部 Work Extension / Core 候选与人的治理动作、Global Attention 对话及分离的 Core Attention item 状态、Spark 的只读衍生投影。逐项箭头能否组成一条带来源、权限、版本、回执和可恢复性的工作生命周期，仍需按真实 consumer 验证；上表不能外推成已完成的通用产品闭环。

## 独立复核：架构公式、工作区治理与选型

2026-09-13 对 Astra 当前工作树中的 [`architecture.md`](../architecture.md)、[`runtime-replacement.md`](../runtime-replacement.md)、活动 canon、[`workspace-governance.md`](../workspace-governance.md) 与 [`engineering/options.md`](../../../options.md) 作了有界非作者核对。架构/治理文件仍由 Astra 负责；以下只记录核对结果与可复现边界，不代表架构决策或产品验收。

- 实现分类和事实 owner 与固定代码 `273ad12a9796aa0547d65e4811a6c56baa5c6a49` 相符。Pi `AgentSession` 是 coding-agent 的 session/lifecycle wrapper，实际 Agent loop 属于锁定 `pi-agent-core`；Host Service 仍直接开/建 Pi `SessionManager`。空 `ResourceLoader` 与 `noTools: "builtin"` 关闭 Pi 默认发现/工具，`app/harness/` 是有限的 CourtWork 协调对象。Host schema 13、Core user/app 4/5 与 Intake / Pi journal 等物理 owner 分开，不能把“Work Core长期语义方向”表述成所有原文和运行数据已入库。
- 公式 1–7 作为设计合同写明版本、授权、来源、撤回、批准与恢复边界；公式 2 要求 `Required(a) ⊆ AllowedCapabilities(a,t)` 及审批/前置条件，集合非空本身不授权。公式 4 初稿容易读作每个 Run observation 都产生 Candidate；Astra已改为 `Candidate?` 且限定为 Work Contract 要求提议时产生，明确普通 Chat observation 不必生成 Candidate，与实现边界一致。
