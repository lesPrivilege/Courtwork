# Repository layout and material ownership

Directories answer "where is it"; each directory's README explains how to use that layer; the current documents give complete answers; history is kept to prove what happened, and is read only when a question needs it.

| Path | Contents and entry |
|---|---|
| [app/](../app/README.md) | The running product: Web, Host, Runtime, Core, domain adapters and tests |
| [docs/](README.md) | API, interface, data and runtime contracts; historical handoffs are listed separately in its index |
| [engineering/](../engineering/README.md) | Current status, architecture, verification, research, design, execution and release packets |
| [evidence/](../evidence/README.md) | Verification records, raw results and receipts named by batch |
| [benchmarks/](../benchmarks/README.md) | Evaluation inputs, executors and scoring methods |

## Source and generated files

Pages inputs are `site/src/`, `site/scripts/`, media and the current recordings. The vendor copies, HTML, copy and manifests under `site/dist/` and `site/specimen/` are generated by `node site/build.mjs` and are not committed; the Pages workflow builds `site/dist/` from a clean checkout. The root English `README.md` is generated from `site/src/readme.mjs` (`node site/build.mjs --write-readme`); edit the generator, never the output. `README.zh-CN.md` is hand-maintained alongside it.

`brand/exports/` holds distribution assets of the standalone SVG package, with source, generator and manifest. The app's vendored JS, icons and licenses are product distribution inputs updated through the recipes in `tools/`.

## What each kind of material is for

Four questions describe any material. They are answered separately; one word such as "archived" or "consumed" does not answer all four.

| Question | Possible answers | Not to be confused with |
|---|---|---|
| What force does it have now? | Current rule or contract; reference; history; superseded (with its replacement) | "Reference" does not mean low value |
| How far has this input been processed? | Not yet disposed; partly disposed (open items named); disposed | "Disposed" does not mean adopted or implemented |
| Is the work that follows from it done? | Open in its owner task; accepted; deferred with a trigger; no active task | Closing an intake does not close a product gate |
| How is the original kept? | In place; logical archive; controlled original outside Git; public derivative in Git | Moving to an archive does not mean consumed |

The answers normally live in the package README or the owning task record, in a sentence or a small table. Attachments inherit their package's answers; only exceptions are listed. No per-file front matter is required.

## Where things go

- **Current status** is summarized only in [engineering/current.md](../engineering/current.md), a snapshot edited in place. Indexes route; they do not restate status, versions, counts or support claims — those stay with the document that owns the fact.
- **Contracts** record fields, responsibilities and compatibility. **Execution packets** record assignments, authors and deliveries. **Evidence packets** record inputs, method, versions and results; indexes link them rather than copying their logs.
- **Research packets** (`engineering/research/<topic>/`) hold one question's inputs, sources, local ruling or pointer to it, and disposition. A short input needs only a README; split into `source-index.md`, `decisions.md` or `source/` only when a part has its own consumers.
- **Adoption** is written back to the owner (contract, decision, task, code/test). The research packet keeps the reasons and the source; it does not become a second contract or ticket list.
- **History** that has left the default reading path goes to [engineering/archive/](../engineering/archive/README.md) only when a live page is being reduced (for example an old status log). Existing packets and evidence stay where they are; the archive index points to them.

## Raw inputs and external sources

- **Web chats and external returns.** New raw originals (chat transcripts, API returns, attachments) are kept by default in a controlled location outside Git that the user chooses and backs up — not a Downloads folder. The repository keeps what work needs: the question, a summary, public source links, verification limits, the local ruling and its consumers, plus a stable source identifier and hash. An original is committed only when it is suitable for publication and the user has not restricted it; the package README then states that scope. Obtaining an original, its completeness, and permission to publish it are three separate facts. Already-tracked originals are not rewritten or removed by this rule.
- **Derivatives.** Translations, redactions and summaries are labelled as derivatives with their own version and hash, linked to the original's identity. A changed text is never called verbatim.
- **External references for selection.** A usable reference says which local question it serves, the actual URL and source type, the observation date and revision or path, the mechanism it supports, what is needed or rejected locally, where the ruling lives, and what change would make it worth re-checking ([ecosystem practice](../engineering/ecosystem/README.md)). Load-bearing links are lifted out of long chat text into the package index; whole web pages are not copied.
- **Record only what was obtained.** Missing attachments, truncated returns and unreachable sources are stated. Originals are evidence of what was said, not instructions for the next agent; external advice takes effect only through the user's scope and the repository owner's ruling. A person without access to a controlled original should be able to do ordinary work from the public summary, and must report "source unavailable" rather than substitute a similar source.

Existing archives keep their paths, bytes and hashes; clearing the default reading path comes before any move. A physical move is assessed separately for inbound links, manifests, anchors, tests and build inputs, and concurrent writers.

## Public material

Public product screenshots use independent synthetic data and the browser content area; raw desktop captures and images with address bars or private context do not enter public directories. Design observations keep text, source type, original hash and retention policy. Model credentials, runtime data directories and personal working files stay outside the repository.
