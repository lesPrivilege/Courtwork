# Long-life Roadmap

路线按证据依赖推进，不给尚未验证工作附承诺日期。当前进度见 [current](current.md)，阶段定义不承载每日状态。

本文件的 R0–R5 是 SE 的研究与验证阶梯。Fresh 壳从通用层施工到接管 Courtwork `main` 的施工阶梯另见 [夺舍前路线](pre-takeover-roadmap.md) 的 PT0–PT9；两套编号不互相映射，引用须带前缀。

## 阶段与退出条件

| 阶段 | 解决的问题 / 主要产物 | 退出条件 | 缩窄或停止条件 |
|---|---|---|---|
| R0 工程分解 | 架构→模块→局部选型；来源和现有资产索引 | 所有承重责任有 owner、依赖、候选与未知项 | 无法明确成果接受边界时退回一个更窄 Matter |
| R1 契约与验证设计 | Adapter、提交、Context、Review、RD | 每项可判定失败；版本、样本、范围与裁决者明确 | 仅有功能愿望或无法取得代表样本则不进入实现 |
| R2 组件验证 | RD-001/002/003 所需局部实验与反例记录 | 执行/取消、正式提交、恢复和投影必要门槛成立；维护成本可说明 | 只能 patch 上游内部、正式状态可被绕过、恢复不确定时缩小能力 |
| R3 单一垂类闭环 | 一个个人 demo Extension | 候选→退回→修订→接受→恢复可复现；真实运行与模拟证据分开 | 没有外部 Reviewer 或来源不足，结论限定为自用工程 demo |
| R4 通用性与替换 | 第二任务类型、第二宿主的配对实验 | 核心状态与裁决语义不变；变化只落在声明的 adapter/Extension | 迁移需重写语义则收窄可移植性，不造通用抽象掩盖差异 |
| R5 长期维护 | 升级、迁移、备份恢复、回滚和依赖退出 | 至少经历真实变更并保存前后证据、成本与剩余风险 | 维护成本持续超过收益，停止扩张、删除胶水或退回上游产品 |

R2 的确定性 Core 验证与 runtime 协议验证可独立进行；涉及真实 GUI 的闭环依赖两者。R4 不阻塞 R3 的个人 demo，但未经 R4 不声称跨宿主或跨领域已经验证。具体 API 的通过条件只适用于测试过的版本。

## Prototype 并行线

[Design D0–D5](design/prototype-plan.md) 是产品设计施工线：D0–D2 的来源、真实 UI 取证安排和三方向探索进入 R0/R1；D3 状态原型可与 R2 同期推进；D4 真实纵向切片依赖 RD-001/002 的相关门槛，进入 R3；D5 的可访问性、长内容与 craft 验证贯穿并随 R4/R5 维护。

不等 Runtime 选型结束才设计 GUI，也不把 mock 原型的“可点击”视为执行可靠。成熟 GUI 先按 [完成面](design/completion-surface.md) 覆盖适用状态与恢复路径，再选择和精修视觉语言。当前尚无 prototype 或设计方向采纳。

## 长期投资顺序

1. 正式状态、版本与裁决可追溯；事故后知道哪项成果生效。
2. Evidence 与 Review 足以支持人的判断；结构不掩盖未覆盖问题。
3. Context 和能力投影随规模增长仍保持关键约束；通过遗漏与污染实验而非 token 数证明。
4. 升级与迁移不会绑死领域语义；拥有可用退出路径。
5. 上述收益成立后再投入更广 Extension、桌面分发和多人协作。

这表示验证和设计精度的优先级，不是把所有通用组件重新实现。每次上游补齐能力都应重算本地持有成本。

## 按触发器维护

| 触发 | 重开工作 | 不自动扩大到 |
|---|---|---|
| 宿主 release / SDK 或事件变化 | 更新快照、受影响 Adapter 回归与弃用计划 | 全部领域 Contract |
| 存储 schema / Artifact 格式变化 | 迁移、备份恢复、版本指针一致性 | 自动重算专业结论 |
| 真实任务暴露缺失 Evidence / Completion | 更新候选 Contract 与验证样本 | 未经裁决的规则自动生效 |
| 模型或 context policy 变化 | 配对任务、遗漏和真实链验证 | 仅凭模型分数接受成果 |
| 安全/许可/停止维护变化 | 缩窄或暂停受影响能力、替代依赖 | 将临时 fork 永久化 |
| 文档负担开始超过决策价值 | 合并重复记录，删除无消费者规格 | 丢弃裁决与来源历史 |

采用依赖后建议每月人工查看 release/弃用/未决反馈，每季度复核保留理由、恢复路径和文档负担；这是维护节奏建议，不是已建立的自动监控。进入任何版本验证前必须重新核对实际快照。
