# Model effort and request measurements

RuntimeStore7 adds optional provider `reasoningEffort`: off/minimal/low/medium/high/xhigh/max. Provider configuration rejects a level outside the installed model's `getSupportedThinkingLevels` map; admission rechecks it. The descriptor is frozen on each Run and passed to Pi `createAgentSession({thinkingLevel})`. Omission retains SDK default/resume behavior; request events record actual effective effort. Catalog responses include supportedEfforts/defaultEffort. No endpoint test or credential inference follows selection. Configuration remains host-global and frozen during any active Run.

Schema3/4/5/6 is fully validated against its old shape before an exact byte backup and atomic migration. Existing project/global Session scopes and async tasks are preserved. Old hosts reject7. No running personal data directory is part of verification.

`runtime.request.telemetry` v1 events are emitted at the host streamFunction boundary, using a monotonic elapsed clock and separate wall-clock start/end. Identity is Run + requestId; purpose distinguishes agent from compaction. Phase is started, streaming, completed, cancelled, failed or interrupted. Multiple observations replace the same request only in a read projection. Event persistence uses the existing awaited drain; no second model loop or transcript owner is introduced.

firstOutputMs is dispatch-to-first nonempty thinking/text/toolcall delta observed by the host; firstTextMs uses text only. These include transport/adapter work and are not provider TTFT. decodeTokensPerSecond and providerTtftMs remain null because the current SDK provides no provider token clock or timestamped token counts. No output/Run-duration or character-rate proxy is labelled TPS.

Request context records serialized-request UTF-16 character count and ceil(chars/4), explicitly heuristic. It covers system text, messages and tool declarations passed to this request, not the exact provider encoding, tokenizer or remaining capacity. No context text is copied into the measurement event. Context window is declared catalog capacity. Terminal usage has independent nullable input/output/cacheRead/cacheWrite values; failed/interrupted requests have no successful-usage assertion. Requested and observed model identity are separate. These normalized fields alone do not support a cache ratio or billing; the separately observed raw request diagnostic is described below.

The shared model picker serves Chat and Attention. Native modal/select semantics, searchable catalog, declared effort options, explicit global-save label, empty-search save prevention and draft/focus preservation are retained. Closing a submitted save does not revoke it; parent state still receives the saved configuration. Attention's composer stays one line. In-place details show the last request; Inspector shows retained per-request history. Malformed measurements fail closed in the renderer.

## Provider response identity (2026-09-12)

The existing `observedModel` is the identity on the SDK assistant message, displayed as **Runtime model**; it does not establish the raw upstream model identifier or immutable served weights. Real DeepSeek tracing found `message.model=deepseek-v4-flash` while the SDK retained `message.responseModel=deepseek-flash` from the response. Terminal events now add optional `providerResponse: { source: "sdk-response-metadata", model: string|null, id: string|null }`, copied only from SDK `responseModel` and `responseId`. These opaque identifiers are limited to 256 characters without surrounding whitespace or control characters. No headers, reasoning text or other metadata are copied.

Pi may omit `responseModel` when it equals the requested model. An absent or invalid field remains null; it is never filled from the configured identity. Historical events remain valid and are not backfilled. The request detail shows separately recorded provider model/response ID when available. A provider-reported name can still be an alias and does not pin a deployment revision. Effort, usage, timing and frozen-null TPS semantics are unchanged.

## Request-input capacity and cache diagnostics (2026-09-14)

Optional `contextCapacity` and `cache` fields extend existing v1 events without a store migration or historical backfill. The installed OpenAI Completions/Responses transport observes raw SSE input and cache counters through a byte-preserving fetch wrapper. It keeps bounded numeric observations for the same request and resets them on each HTTP retry; failed/cancelled requests do not expose successful input usage. Response text, headers and credentials are not persisted by this observer. Unsupported or absent counters remain unknown.

`contextCapacity` v1 records `scope: request-input`, `source: provider-reported`, `usedTokens`, `contextWindow` and `windowSource`. Inclusive provider input counts cached tokens once; normalized input, output, estimates and cumulative Session usage are not substituted. A positive model-declared window takes precedence; otherwise the explicitly labelled 1,000,000-token default registration is a display reference only, never model capability or a compaction threshold. The ring labels the latest completed request input, excluding output and later edits; it does not claim the next assembled working set, Reserved or Free.

`cache` has request scope and provider source, with optional hit/miss/write/total counts. No raw cache field means unavailable and no diagnostic section. Comparable raw hit and miss, or hit with reliable inclusive input total, can support an adapter-calculated ratio; inconsistent totals retain counts without a bar. Explicit zero is distinct from missing. Cache writes remain separate and never expand the Hit segment or the context capacity total. Full UI semantics and future owner-dependent fields are in the [Context Inspector contract](../../engineering/design/context-capacity-ring-2026-09-14/contract.md).
