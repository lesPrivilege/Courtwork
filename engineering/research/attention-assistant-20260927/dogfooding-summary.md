# Dogfooding Kit: navigate existing owners, then execute a bounded task

**Adopted now:** a development reading protocol joining **Map → Grammar → Tools → Gates**. This packet is its first documentation consumer. The developer follows current ownership and verifies a real bounded change; the document itself installs no executable skill or runtime extension.

| Part | Consume | Meaning |
|---|---|---|
| Map | [Task index](INDEX.md), [engineering entry](../../README.md), [repository layout](../../../docs/repository-layout.md) | Find responsibility, source and stopping point |
| Grammar | [Architecture](../../architecture.md), relevant domain contract; UI also UX/frontend/spatial grammar | Preserve authority and existing interaction conventions |
| Tools | Actual source/API/CLI supported by the selected runtime and Host | Tool availability is not permission; source examples are not shipped commands |
| Gates | [Verification](../../verification.md), original task/evidence record | Run meaningful checks and retain findings; author success is not independent acceptance |

<details>
<summary>Expand: L0/L1/L2 and map ownership</summary>

1. **L0:** read repository instructions, current status and the bounded assignment; confirm branch/HEAD/status.
2. **L1:** select one index route; identify the owner, current contract, nearest precedent and required checks. Stop expanding unrelated topics.
3. **L2:** inspect exact code/tests or source evidence needed for the change. A generated structural map may help, but must state source SHA, scope and omissions.

The semantic map is hand-maintained responsibility and contract navigation. A structural map is generated paths/symbols/dependencies for a particular checkout. Aider supports the usefulness of budgeted structural navigation; its algorithm and budgets are not adopted CW contracts. No map generator is implemented in this intake.

OpenHands path rules are a client-specific mechanism, not part of base Agent Skills or current CW behavior. CW already supports metadata-first resources and explicit `runtime_load`. Future path-trigger adapters must declare their client/runtime support rather than claiming universal automatic disclosure.

</details>

<details>
<summary>Expand: Kit compatibility, convergence and the next consumer</summary>

A development Kit is operating material, not a replacement for CW's existing structured Kit/Profile semantics. K1/K2 planning, K3 immutable Run context and K4/K5 selected-profile preview/editing have bounded accepted implementations. Agent Skills can later be an instruction/reference interchange format; it cannot grant permission, replace retained hashes/payloads, create an accepted Runtime or erase Host policy. General catalog/acquisition and arbitrary-runtime support remain distinct gaps.

Borrow Spec Kit's convergence principle: compare delivery against the assignment and evidence, record remaining gaps in the **original** record, and let the appropriate reviewer decide. Do not import its commands or establish parallel `specs/`, `.cw/` or task ledgers. The source's `cw inspect`, `cw scaffold` and `cw replay` examples are proposals, not runnable CW commands.

The first next consumer is the bounded Hermes Attention discovery/adapter-contract case described in [Attention](attention-summary.md). Small implementation tasks continue through actual CW dogfooding; important self-developed mechanisms and architecture decisions stay with Astra/Claude, and Luna explores or independently verifies bounded claims. This routing does not launch another author or displace existing assignments.

Extract a reusable package only when repeated tasks show stable contracts and useful context boundaries. “3–5 examples” is a heuristic, not an adoption threshold. Preserve the existing user-owned untracked `.agents/` tree; this intake neither reads nor modifies it.

</details>
