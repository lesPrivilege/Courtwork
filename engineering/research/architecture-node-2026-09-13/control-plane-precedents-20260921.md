## Protocol corrections

- **ACP:** client-to-agent session integration is a candidate for a later local adapter. The fetched [v2 session setup source](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v2/session-setup.mdx) describes negotiated capability support, optional replay on resume, and `session/close` cancelling ongoing work before releasing resources. Therefore a future adapter must not map local transport disposal directly to that operation. Resume without replay does not imply lost history; replayed messages require their protocol identity/replacement rules. Pin the actual installed peer/version before implementing; this source does not prove current Pi or Hermes implements v2.
- **MCP:** the [2025-06-18 tools specification](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) defines named, schema-bearing tool calls. A bounded worker can be exposed as a tool. Adjust the intake's absolute “MCP cannot do agent communication”: CW still needs explicit attempt, cancellation, recovery and result-consumption semantics around that tool. Existing Codex MCP and typed-child precedents remain eligible.
- **A2A:** [v0.3.0 sections 7.1–7.2](https://a2a-protocol.org/v0.3.0/specification/) allow `Message` as well as `Task` responses and streaming updates. A Message can carry a valid answer. CW's requirement for attributable, durable results and separate acceptance is its own policy; it is not an A2A prohibition on Message output. External federation remains deferred until a concrete consumer needs it.

These protocols answer different interface questions and may coexist. None is the CW domain model, an authorization grant, or proof that an external runtime meets Host-governed tool requirements.
