# Model + effort · 逐连接、逐模型自适应登记

2026-09-12。用户要求统一model/effort的UI投影，同时根据单个Provider/model的真实能力自适应登记，派Luna查官方文档与成熟实践，落实Harness前后端可施工性。本轮交付是研究、合同与差额排单；不调用付费Provider、不改生产代码或既有标本。工作分支 `codex/chat-harness-intake-20260912`，登记基线 `69c1a5c84526bc0d298cc6436d5719a125607b75`；本地实现核查固定共享main `135492c7d7cf3c0ac634f9248c79530972c53004`，不以旧分支源码代称最新Harness。

## 裁决

**统一入口与操作关系，能力集合逐连接、逐模型、逐API适配。** 不把一个通用“推理强度”枚举或UI滑杆当作Provider已支持的合同。Model目录、参数能力、请求结果和Run绑定分别保留事实；不把这些信息压成一个“已握手”的绿灯。

三张[用户截图与hash](source-manifest.json)展示：composer内一个“模型＋当前档位”入口、展开后的局部调节、再进入模型列表。采用这棵控制树作为候选；截图中的Light、档位数量、推荐集合、颜色和模型名不构成Courtwork API能力证据，也不据此建立 `Light = low` 映射。

[官方Provider与成熟实践核查](provider-evidence.md)给出可消费事实；[Harness接线合同](implementation.md)给出实际owner、差额与验收。沿[PV批次](../../../mvp/execution/provider-surface/README.md)、BE-17/18、BE-39、BE-40@Provider和当前Runtime owner推进，不新建并行模型管理系统。

## Adapter作为握手中间层

按用户追加裁决，adapter承接上游协议：发现目录/能力、描述本模型支持项、校验并编码请求参数、解释响应与错误。它输出可校验的**数据描述**，由Host注册进已有provider/model目录，再由既有UI projector生成model/effort控制树。

```mermaid
flowchart LR
  P[上游Provider] -->|目录·能力·响应| A[Provider adapter]
  A -->|带来源和版本的能力描述| H[Host校验与现有registry]
  H -->|允许设置·作用域·检查状态| U[统一Model UI投影]
  U -->|选择意图与预期版本| H
  H -->|准入与冻结Run配置| A
  A -->|精确wire请求| P
```

“注册相应投影”指注册描述投影所需的能力事实与受控控件类型，不注册任意HTML/脚本、远程UI或带副作用的前端回调。Adapter不能自授权连接、写全局配置、换账号或接受工作；Host仍管理凭据、配置版本、访问范围与Run绑定。没有实际adapter实现或握手证据时只保留候选/未知状态，不因注册成功显示已生效。

能力描述与网络检查是不同动作。可从有版本的官方合同加本地adapter测试得到静态支持声明；能运行时发现的字段则消费真实返回，来源并列保留。上游未提供精确capability时不伪造“协商完成”；有界探测只证实覆盖的请求形状，不能穷举或推测所有能力。

## UI投影

1. Composer保持一个模型入口；紧邻显示当前已保存的模型及其有效配置摘要。运行期间当前Run使用自己的绑定记录，不能用已改的未来配置覆盖。模型列表按连接区分，同名model在不同endpoint/account不合并。
2. 展开先显示当前模型可用的设置，再进入换模型列表；连接、凭据、目录维护仍在Models/Settings。只展示Host返回的选项与不可用原因，前端不靠模型名正则推导档位。
3. 离散effort可用有明确名称的选项。截图式滑杆只有在Host声明了有序、有限、合法档位及准确往返映射时才可做specimen；每个停点必须落到一个合法值，不插值、不跨档补值。token budget是有单位/上下界/步长的另一种控件；thinking模式、budget、effort不能混作一个数轴。
4. `Provider default` 表示按该adapter合同省略设置，**不是Off**，也不承诺省略后一定省算力。只有模型支持明确关闭且adapter可表达时才显示关闭选项。只有一个有效状态时用静态说明，不做空转的选择器。
5. 未知、用户声明、官方声明、连接实测、Provider返回观察要可区分。未知能力不生成推理档位；允许保留模型候选并显示检查/配置入口。原有手工reasoning勾选只算用户声明，不自动长出low/medium/high梯子。
6. 换模型导致旧设置无效时保留草稿与待保存选择，说明不兼容，要求从新模型合法选项或明确的Provider default中选择；不默默套近似值。保存失败/目录过期时仍显示已保存值，保留编辑草稿。默认不引入自动模型fallback。
7. 设置作用域由真实后端决定。现“所有Chat的未来Run”不能投影成“此会话”或“仅本次”。单turn override仍候选，须另有输入、优先级与Run绑定实现；发送旁的二级动作不独自创造这种能力。

这些关系服务[human review attention](../review-attention/README.md)：默认入口短，能力来源与实际绑定可查；设置失败和运行配置差异不能被收纳成不可发现的metadata。模型已完成、工具已批准、工作已接受保持原有独立语义。

## 能力确认的含义

“握手”必须指出验证对象和证据范围：

| 事实 | 可证明 | 不能证明 |
|---|---|---|
| 目录返回模型ID | 该连接此时返回此候选 | 支持所有参数、工具或其他API；实际推理已发生 |
| Provider capability / 有版本的官方模型合同 | 指定型号、接口及条件下声明的参数能力 | 当前账号有访问权；每次请求都会使用某数量思考token |
| Host adapter验证 | 当前锁定版本能将允许设置编译成正确wire字段，非法组合被拒绝 | 远端一定实现或不忽略该字段 |
| 有界连接检查成功 | 某连接、模型、API与请求形状当时返回成功 | 每个字段都生效；其他档位也支持；工具/流式/多轮都成功 |
| Provider响应字段/usage | 仅它实际返回的model、配置或计数 | 未返回的设置已生效；低token说明关闭；隐藏推理内容正确 |
| Run绑定 | Host在准入时冻结并实际送出的请求配置及版本 | Provider内部计算完全可知 |

因此，UI可选择集合必须来自Host对**有来源的能力声明与已实现adapter**的交集；连接访问/检查状态另呈现，未验证就不称已验证。对未知或仅有布尔猜测的参数不发请求；如确需实测，沿显式有界检查而非打开菜单或滑动即发模型请求。HTTP200也可能伴随参数静默忽略，不能仅据此填 `effectiveEffort`。

官方endpoint、兼容网关、自建服务即使用同一个model字符串，也必须分开登记。路由、凭据代际、model版本、adapter版本或能力文档更新后，旧证据按其依赖失效，不跨账号复用。
