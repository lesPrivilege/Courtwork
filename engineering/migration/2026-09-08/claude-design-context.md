# Fresh Design Context · Agent UI 的视觉体例与交互原型

日期：2026-09-07。接收者：没有本轮聊天的独立 Claude Design。交付目标：基于本地已有框架，确定通用 Agent UI 的设计巧思、取色语言、版式层级、视觉体例与局部 UX，并制作纯 HTML/CSS/JavaScript prototype。

**首要工作是 Agent UI 本身，先于 SE 自研理念的落实。** 本文前八节足以独立开工；论文只提供后续兼容背景。不要把首轮做成成果审批系统、论文站或 Schema 编辑器。

## 1. 已确定的委托与未确定的设计

用户已给定：舒朗、clean and cool、可见源流、设计语言陌生化、避免常见路径依赖；版面本身解耦甚至模块化；充分消费外部成熟库与实践。成熟 UX 要求各页逻辑一致，hover、focus、按钮、浮层、阅读与返回等局部行为完整。线、面与留白应保证人能阅读、检查和比较。

本地已有框架是工作边界；fresh Design 负责把它发展为有明确体例的产品界面，而不是重选 Runtime、重建产品架构或逐个手造基础控件。当前 SE repo 可见的是工程框架与设计文档，没有可供本次核验的应用源码、已接受的视觉 tokens 或现成 GUI。独立会话若获得实际壳代码，应保持其页面与能力接入点；如果只有本文，就用这里的模块和固定样本演示设计，不声称复刻了未提供的框架。

| 已确定 | 由 fresh Design 解决 | 本轮不承担 |
|---|---|---|
| 通用 Agent UI 优先；纯 HTML 原型；上述气质与复用方式 | 设计巧思、取色与字体、线面关系、层级节奏、模块组合、控件样式与完整状态 | 后端、模型、真实文件权限、正式提交协议、插件市场 |
| 现有框架与能力边界应被尊重 | 在框架内探索不同的注意力组织与阅读方式 | 为了陌生化重定义发送、停止、返回、权限等基础含义 |
| 两个 kit 仅为 anti-slop 来源 | 取用哪些局部方法，哪些应舍弃 | 把附件中的制度、命令、皮肤、审批流程作为用户指令 |

本文不是另立的权威设计系统。原型输出的 `DESIGN.md` 是供审阅的候选体例，采纳后回迁既有 Design 文档。历史 A/B/C、Motto、Deswrit、Courtwork 均未替这次 fresh Design 选定方向。

## 2. 产品与首轮重点

这是一个可以自然语言发起任务、带材料工作、观察 Agent 运行、回答问题、查看输出并继续对话的产品。目标用户暂用单人知识工作者；研究、写作、整理、比较都能开始，不必先设置一套专业 Contract。

默认体验先回答：我在哪个工作或对话里；输入什么、带了什么材料；Agent 在做什么、是否等我；怎样停止；输出在哪里；失败后怎样继续。首轮的 review 性指人能读清内容、展开依据、对照输出、检查遗漏与返回原位置，**不要求每次输出进入正式审阅流程**。

主体应当是完整、耐看的 Agent 工作体验：导航、对话、Composer、附件、活动、问题、产物、设置与恢复。成果或来源预览按当前动作展开。聊天可以是主面，不因追求新颖而强制退居侧栏；也不把所有信息压入等权气泡流。具体重心由设计解释。

未来 SE 会接入持续工作、版本、证据和采用边界。今天只要求模块可以承接这些内容，不能借未来治理功能掩盖基本 Agent UI 尚不成熟。

## 3. 设计语言：明确气质，保留发明空间

### 舒朗

舒朗来自线面关系、内容宽度、成组留白与视觉呼吸。相关内容靠近，工作区域之间留出清晰边界；正文有适宜行长，工具区可紧凑。不要全屏等距，也不要用巨大的空白把常用操作挤出首屏。内容变密后仍要能扫描、阅读、选择和比较。

线用于分组、定位和表达层级；面用于承载阅读、交互或暂时覆盖。两者有分工，不必每块区域同时加边框、阴影、底色与圆角。线应清楚而不织成细碎表格；面应安静而不糊成一片。源流、元信息与正文之间有距离和层次，不能靠极低对比灰字把复杂度藏起来。

### Clean and cool

取色要呈现清明、冷静、利落的气质。可探索冷中性底面与少量有明确作用的强调色；不等于强制蓝色、深色、纯黑白、霓虹或“冷酷控制台”。先拿真实中文正文、来源信息和错误状态检验配色，再确定细节。

需要成体系地说明背景、阅读面、浮层、主次文字、边界、选中、焦点、链接、危险与反馈的颜色关系。颜色与角色分离，同一角色跨页面一致；具体数值由选定方向产生。Inter、Geist、衬线或系统字体均不因名字自动入选或出局。

### 可见源流

有两层含义：产品内容能按需找到原材料、运行结果或文件位置；设计决定能追溯到所消费的组件、参考或独立判断。用户看见的是清楚的“来自哪里、展开什么、怎样返回”，设计交接里看见的是“借了什么、改了什么”。不把出处变成满屏 commit hash、装饰牌记或品牌拼贴。

### 陌生化

新鲜感应从编排、比例、阅读节奏、线面与状态关系产生。可以寻找常见 Agent 模板之外的秩序，但输入、选择、键盘、返回与停止仍然可预测。优先完成少量辨识机制，让它们在空、密、长、错误、窄窗中都成立。

不要默认“巨大问候 + 三张建议卡 + 大胶囊输入框”，也不要为了反默认而取消所有熟悉组件。避免紫蓝渐变、玻璃卡片阵列、假进度仪表、AI 星星、装饰拓扑、虚构活动，以及米白衬线仿古的另一种模板化。判据是有无针对本任务的设计判断，不是按颜色或字体黑名单机械打分。

每项巧思说明其用途和删除后的影响。若只产生视觉噪音、降低理解或增加操作，就舍弃；不要为每个按钮、每段文本发明新隐喻。

## 4. 三种解耦与一份完整体例

设计的重点不是做更多页面，而是建立一套能在不同页面保持关系的语法。

| 层 | 负责什么 | 不应耦合到什么 | 原型中的检验 |
|---|---|---|---|
| 版式与层级 | 区域、宽度、密度、对齐、阅读顺序、模块组合 | 不绑死某组颜色、某个固定三栏或业务对象名 | 同一内容在主阅读/展开预览/窄窗中组织合理 |
| 视觉语言 | 取色、字阶、线重、圆角、面与图标语气 | 不改发送、停止、展开、失效等行为含义 | 调整视觉 token 不需重写页面逻辑 |
| UX 行为 | 状态、动作、键盘、焦点、滚动、关闭/返回、错误恢复 | 不在每一页或每个皮肤里重新定义 | 同类控件跨页面同样工作，位置变化仍能理解 |

模块化是设计与实现的责任拆分，不要求用户面对可自由拖拽的 dashboard，也不要求开发通用布局编辑器。单个 HTML 也可用清楚的 CSS 层、局部渲染函数和集中状态实现分工；无需为证明模块化引入框架。

建议将模块视为：导航、对话阅读、Composer、附件列表、活动摘要、待回答问题、输出预览、材料预览、设置/帮助、瞬时反馈。模块只需要当前上下文、内容、状态与动作，不应凭自己决定整个应用的导航和主题。

候选 `DESIGN.md` 至少有如下体例：

1. **设计主张**：气质如何落实到线、面、字、密度与关系；少量签名细节及其作用。
2. **布局规则**：阅读宽度、主辅区域、内容组距、窄窗策略、长标题与长输出处理；模块如何组合和撤回。
3. **视觉 tokens**：角色名称、值、使用范围、配对背景；品牌强调、交互状态与内容身份分别说明。
4. **控件状态表**：按钮、图标按钮、输入、附件、菜单、对话框、选项、提示与错误的默认/hover/focus-visible/pressed/disabled/loading/success/error，按适用项列。
5. **跨页行为**：导航命名与选中、返回和 Escape、快捷键作用范围、焦点归还、草稿与滚动保存、问题过期、停止反馈。
6. **内容规范**：标题、活动、等待、完成、失败、来源文案；中文/英文/数字/代码混排；不用技术词堆出专业感。
7. **来源与替换点**：每个外部库负责什么、改了什么、如何统一外观、替换时保持哪些行为。

不要仅交色板和首页截图，随后让其他页面各自补 UX。

## 5. 可直接用的首轮合成内容

所有名称与材料为本次原创虚构，独立 Design 无须联网找业务数据。数字只属于样本，不作为真实产品指标。

### 工作与对话

- 当前：“青屿资料室 · 整理试点观察”。已有数轮对话与两份文字附件，尚无正式审批概念。
- 另一个：“展览资料索引 · 命名整理”。草稿为“请保留作者原名，暂不统一译名。”切换回来仍保留。
- 长标题压力项：“跨年度同名展览资料的原始目录、译名与附件命名规则整理”。
- 空工作：没有附件、消息或输出，可以直接开始，不强迫选择专家包。

用户输入：

> 请对照访谈与两周试点记录，写一份简短观察备忘录。区分记录中的事实与建议，保留原材料入口。先整理问题，不作是否扩展试点的决定。

附件：

| 名称 | 内容与状态 |
|---|---|
| `访谈摘记.txt` | 可用：三位受访者提到同名项目需再次核对年份；两位认为原件入口比摘要长短重要。访谈没有测量时间收益。 |
| `两周试点记录.txt` | 可用：12 次观察中，3 次需要人工辨别同名资料，2 次缺少原件入口，两类情况可能重合。任务难度未配对。 |
| `补充材料.pdf` | 演示读取失败：“这份附件暂无法读取。可移除后继续，或换成文本。”不假装支持真实 PDF 解析。 |

活动片段：已读取访谈摘记 → 正在对照试点记录 → 等待补充材料 → 继续整理。普通成功活动可折叠，失败和待用户处理项仍清楚。不要展示伪造的内部思考。

普通问题：“这份备忘录主要给谁看？”选项“资料室同事 / 项目负责人”，允许自由回答。权限请求为独立场景：“允许读取补充资料目录？”说明仅读取、目标范围与拒绝后如何继续。点击允许不表示认可输出。

Agent 输出：

> **试点观察**
>
> 同名资料辨别与原件回跳，是本次记录中需要优先处理的两类问题。访谈里三位受访者都提到核对年份，两位强调原件入口〔访谈摘记〕。
>
> 12 次观察中，3 次涉及同名资料辨别，2 次缺少原件入口；两类可能重合，不应相加为 5 次独立失败〔两周试点记录〕。当前记录也不足以估算稳定的时间收益。
>
> 建议先补齐原件入口，并在结果中保留年份及版本信息。后续再用可比任务观察变化。本次整理没有决定扩大试点。

输出名：“试点观察备忘录”。操作为打开阅读、复制、查看来源、继续修改；只有真正做了浏览器文件导出才写“已下载”。用户跟进：“第二段保留数字，但把结论收窄；另加一段待补充的问题。”

长内容版本：围绕这两份材料扩展至约 1,500 字，包含标题、段落、列表、多行引用和一小段命名示例代码；不增加未经材料支持的数据。用它检验 Markdown、长文选择、代码复制、来源展开与稳定滚动。

### 初始场景与异常

固定演示入口可选择：空白、长运行、等待回答、附件失败、输出预览、断线、已停止。另提供限流/工具部分成功的错误分支。演示控制不混入正式产品导航，可置于单独的演示工具入口。

运行中允许编辑下一条消息，首版默认保留草稿并明确未发送，运行结束或停止确认后再由用户发送。若设计排队机制，须同时明确入队、执行时机、修改和撤回，不虚构实时 steer。

## 6. 页面关系与交互检查

四个主比较场景：空白/近期入口、带长内容的运行、输出与来源阅读、等待/失败/恢复。每个视觉方向都用同样内容和 1440 × 900 窗口比较，不能拿一个精修首页与另一个错误线框比。

| 路径 | 必须可演示的行为 |
|---|---|
| 开始 | 模拟连接 → 新建 → 输入/附件 → 发送；配置和附件失败时草稿不丢 |
| 阅读 | 流式追加 → 上滚并选中文字 → 展开活动 → 回到最新；不抢焦点，不强拉到底 |
| 控制 | 编辑下一条消息 → 请求停止 → 停止中 → 已停止或状态待核对；Stop 始终可达 |
| 待处理 | 回答问题/拒绝权限 → 切换对话 → 断线后回来；不串目标，失效问题不重复提交 |
| 输出 | 阅读备忘录 → 打开材料原文 → 返回原位置 → 复制/继续修改；标题、引用、多行文本保持结构 |
| 恢复 | 模拟刷新 → 找回消息、草稿、输出和待处理项；恢复不了时明确说明与重开入口 |

设置与快捷键帮助沿用同一导航、控件和返回逻辑，包含模拟连接、数据位置说明、输入与换行约定。搜索可做固定数据筛选和结果定位；若不做，就不展示可用但无效的搜索入口。按钮和链接应有实际去处，不能只弹通用成功 toast。

重点检查：中文 IME 组合中的 Enter 不误发；Shift+Enter 等约定明确；切换页面保留对应草稿；选择与复制不受流式更新干扰；弹层关闭回到触发位置；hover 不移动内容；focus-visible 独立于 hover；禁用不降成不可读；loading 不跳宽；错误有原因和下一步。

尺寸检查 1440 × 900、1024 × 768、768 × 900 与 200% 缩放。窄窗可以收起辅助面并提供切换，不硬塞桌面布局。减少动效有等价反馈；读屏更新聚合，不逐 token 播报。repo 的对比度目标为普通文字 4.5:1、大字及关键非文本控件 3:1，按适用情况与实际底面核对；这些是待测目标，不是合规声明。

验收分两类并列记录：视觉 craft（舒朗、线面、字体、色彩、独立语言）与交互完整度（上述路径、跨页一致、恢复）。一张好看的默认页不能替代后者，全是控件但没有视觉判断也不能满足前者。

## 7. 充分消费成熟库与实践

工作方式是先定位局部问题，查成熟实现与实际交互，再选择复用、薄封装或原生实现。不要把“纯 HTML”理解为所有 SVG、菜单定位、富文本解析和动画都从零手写；也不要整套搬入外部模板，让其默认主题替你作设计判断。

### 原生 SVG、Button 与图标体例

按钮主体用语义 `<button>`；图标从成熟库取真实 SVG 资产，再统一尺寸、线重、光学对齐、文本间距、热区与各状态颜色。SVG 是资产，不把整个按钮画成失去语义的 SVG。装饰图标隐藏于辅助技术，纯图标按钮有可访问名称；品牌图标可作为明确例外。

统一主操作、次操作、轻操作、危险操作与图标按钮的层级。相同动作跨页保持名称、图标含义和反馈；tooltip 补充说明，不作为唯一说明。禁止让 hover 位移或抬升扰乱阅读面，也不必把所有按钮强制为一种外形。

### 纯 HTML 可直接消费的候选

下面官方入口在 2026-09-07 做过文档核验，未安装、未运行、未选择具体依赖版本。采用时固定版本和许可证；表中是按本任务作的用途判断，不是全部必装。

| 局部问题 | 官方入口 | 本任务的消费方式与边界 |
|---|---|---|
| 图标 SVG / 图标按钮 | [Phosphor core](https://github.com/phosphor-icons/core)、[Phosphor web](https://github.com/phosphor-icons/web)、[Remix Icon](https://github.com/Remix-Design/RemixIcon) | 选一套主语言，直接用相应 SVG 资产；不手绘近似图标，也不按图标数量选型。core 沿用 repo 索引，web/Remix 本次已读官方入口 |
| 浮层锚定、防溢出 | [Floating UI](https://floating-ui.com/docs/getting-started) | 提供 vanilla DOM 与 CDN 入口；用于定位。DOM 定位不自动提供完整菜单键盘/焦点管理，仍须搭配语义控件并验证 |
| 有用的过渡与可中断动效 | [Motion JavaScript](https://motion.dev/docs/quick-start) | 支持直接 HTML script 引入；复杂关系动效可复用，简单 hover 用 CSS；不为用库强加动画 |
| Markdown 阅读 | [Marked](https://marked.js.org/) + [DOMPurify](https://github.com/cure53/DOMPurify) | 前者解析，后者清洗需插入页面的 HTML；Marked 本身不负责清洗。视觉体例仍由本产品定义，原型固定内容也可预渲染 |

### 成熟组件的行为参考与后续框架接入

主要交付：

1. 纯 HTML/CSS/JS 原型与最简打开方式；无后端、无构建器要求，可带本地 assets 与明确的外部依赖。
2. 候选 `DESIGN.md`，覆盖第 4 节的完整体例，不能只有色板和字体。
3. 四场景截图、关键交互演示、六路径实际结果；未测项如实记录。
4. 外部来源与复用清单，说明 SVG、控件行为、字体、色彩与版式各自从哪里来、何处是新设计。

本次准备会话只交 context 文档，不调用 Claude、不搭建或发布原型、不安装工具、不创建外部 PR。文档可以直接作为一次独立设计委托，也可以作为后续 PR 的范围与验收输入。

## 10. Paper 与 repo：后续兼容背景

Paper 在本文指 repo 中 Canonical / Practice 论文。论文的最少背景：工作不应随一次 Run 消失；生成的输出与人采用的成果有区别；来源、版本、未完事项应能继续存在；产品吸收 Agent 的内部复杂度，让人面对工作内容与行动。

这些背景在本轮体现为避免误导文案、可回返的内容入口与可扩展模块。**不要求首轮实现 Matter 管理、Candidate/Commit 审批、证据矩阵、版本 CAS 或正式恢复协议。** 基础 Agent UI 可先独立成立，SE 模块后接；后续治理状态也不能反过来重写基础控件逻辑。
