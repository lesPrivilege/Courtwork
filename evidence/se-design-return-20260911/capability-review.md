## Cross-cutting evidence

### Static artboards do not prove live transitions

The artboards include `support.js` but no event listeners, fetch calls, `requestAnimationFrame`, `setTimeout`, or projection imports. Their animations therefore demonstrate CSS appearance only. This matters for the “live (CSS only)” claim in `RETURN-design.md:77`: it can document intended timing and interruption states, but it cannot verify a state transition, an interrupted request, or the distinction between a pending receipt and a settled host state.

The actual composer preserves the distinction the board needs: a pending send makes the input read-only, an active run hides Send and shows the cancel control, and `Stopping` appears only after the host reports `stopping`; a cancel request alone does not claim the run stopped (`app/web/app.mjs:3278-3343`). The assistant delta row has a semantic `pending` flag, but there is no dedicated `.pending` CSS rule in the candidate; the stream is rebuilt while preserving focus/selection/scroll in `app/web/app.mjs:2528-3101`. Any future streaming cue should be text-led, interruptible, and preserve these invariants.

### Motion values differ from the packet’s summary

The candidate’s registered motion tokens are `--duration-fast: 120ms`, `--duration: 180ms`, and `--ease-out: cubic-bezier(0.2, 0, 0, 1)` (`app/web/styles.css:400-425`). The packet’s “120/180 ms and one curve” summary is therefore source-supported for transitions, but the candidate also contains:

- a 1.6s run pulse (`app/web/styles.css:3031-3052` and the earlier composer hint at `1545-1568`);
- a 1.8s activity shimmer (`app/web/styles.css:3433-3464`); and
- a raw 140ms Home attention chevron transition (`app/web/styles.css:5471-5487`).

In the inspected Home attention rule, 140ms is a raw duration outside the two registered tokens; this is a bounded observation, not an inventory-wide claim. It should be normalized to an existing token or explicitly adjudicated before motion parity is claimed for that rule. Reduced-motion and forced setting rules turn animations and transitions off (`app/web/styles.css:2669-2687`), which agrees with the packet’s static fallback.

### CSS cascade/material parity is incomplete in the artboard copies

The artboards copy the top-level palette (`--paper`, `--frame-s`, and dark `--paper`) but omit late, selector-scoped overrides that determine effective product surfaces. Home neutral overrides begin at `app/web/styles.css:5506-5553`, including light `--home-neutral-paper: #f4f5f6` and dark `--home-neutral-paper: #222627`; the role mapping is applied by `html:not([data-skin="custom"]):not([data-skin="gray-steel"]):not([data-skin="dystopia"])` at `app/web/styles.css:5548-5553`, not by an `.app-shell.home-neutral` selector. The authored message plane is overridden at `app/web/styles.css:5906-5925` (`#202426` / `#303638` / `#f5f7f8` / `#c8cdd0` / `#596267`), with dark authored surfaces mapping to `var(--float)`. Forced-colors and material fallbacks follow at `app/web/styles.css:5928-5941` and `6012+`.

Consequently, a dark artboard that uses only its copied base variables can have different card depth and text contrast from the mounted Home or authored-message surface. The return packet should cite effective selector-level tokens for dark/light parity rather than treating its top palette block as the final cascade.

## Suggested review order

1. Correct capability labels in DG-02, DG-05, DG-06, DG-07, PagesStory, and ChatSpace.
2. Normalize or adjudicate the raw 140ms motion value, then reconcile the packet’s “one loop/no shimmer” language with the actual pulse + shimmer rules.
3. If a visual parity PR follows, scope it to the supported Spark read states, Attention semantics, existing composer state words, and Settings rows that are actually shipped.
4. Keep rebuild, task-ladder lifecycle, and the eleven unavailable Chat intents as explicit backend/product gaps with no optimistic UI.
