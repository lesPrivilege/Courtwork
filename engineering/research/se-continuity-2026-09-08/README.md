## 判别问题与反证

| 命题 | 可观察实验 | 削弱命题的结果 |
|---|---|---|
| C1 工作跨执行实例持续 | 中断后由新执行者从可用记录继续，完成成果且保留义务 | transcript 或普通状态文件在相同预算内同样可靠且更便宜 |
| C2 显式治理改善变更正确性 | 来源替换、迟到请求、重复裁决、冲突后测实际生效内容 | 只是全拒绝，合法完成率下降，或常规事务审批同样有效 |
| C3 共享表示降低接管负担 | 真实人识别有效成果、依据、下一步并实际操作 | 漏项/误批准/耗时不改善，维护成本抵消收益 |

Paper §2.4 的删除测试与 F12 是反证入口；§3–4 的持续工作和 §4 的事务状态可替代事件溯源约束要求我们接受不同实现。这里只测试运行/连续性链；不声称证明专家示范→契约提炼，或生产反馈→跨任务改进。后两项另需冻结提炼流程和外部留出。

## 实验层次

| 层 | 交付与准入 | 可支持的结论 |
|---|---|---|
| B0 机制 | 独立评分器、合成正常/异常路径、真实 Core、原始观察、失败计入分母 | 声明操作在本地持久状态上的机制行为 |
| B1 工作续行 | NDA adapter + HTTP/新 Session，独立开发语料、有效修订、SIGKILL/回执丢失，冻结数据与 oracle | 合成领域/宿主纵切；脚本与真实模型分开 |
| B2 模型对照 | 三种 matched harness，模型与预算清单；先 pilot 再冻结留出与消融 | 指定任务分布下的模型/系统效果与成本 |
| B3 外部法律任务 | 固定上游数据版本/许可/子集，变更后 rubric 有资格人员复核 | 指定法律任务的成果质量与续行能力 |
| B4 人类接管 | 可用 GUI、真实参与者、平衡顺序与材料、预定义错误/时间记录 | 短时接管效果；不推出长期技能保留 |

先完成前一层的可复核入口再扩大下一层。付费调用不默认运行；人员招募与法律 gold 需要真实资源，不用 agent 角色替代。不得因 B0 通过关闭产品 G1–G5。

## 样本与扰动

pilot 目标为 12 个不同基础事项，每个正常路径 + 两种预设扰动，共 36 条轨迹。这是目标规模，不是已交付样本。按基础事项/任务族分组切分开发、验证、留出；同事项改日期/换名字/重复 seed 不算独立事项。当前最小开发语料只有一个合成 memo 族的五条机制路径，已暴露，永不重标留出。

后续 NDA 轨迹：v1→待审→v2关键条款变化→旧接受请求迟到→有效新候选→合法裁决后回执丢失→新 Session 对账并继续。另设无变化/不相关变化/合法提交对照，避免只会阻拦的系统高分。

扰动族：来源版本、候选并发或过期、重复/改变请求、执行中断、producer 缺席、执行者交接。分别记录前置条件、触发点、可见信息、允许结果与截止预算。用语义检查点触发，避免把不同系统在固定墙钟时刻截断造成不等价；未到触发点也记录为未完成，不删除尝试。

现有 NDA v1 facts/playbook 是不可变 envelope；更改业务事实需新绑定。B1 先覆盖已有 source replacement，不把 facts 原地更新、缺席 producer 的写操作或完整依赖失效传播假设成现有能力。Producer 缺席首先测历史读取/禁止动作；真正续行需重新提供兼容实现。

## 公平基线与消融

T：transcript + 原始文件 + 检索。

S：认真实现的普通持久化系统，具有可编辑摘要/任务清单、版本化文件、常规审批与事务保护。

E：Courtwork/SE 的显式契约、正式状态、Context 投影与提交规则。

三者使用相同模型具体版本、工具能力、原始信息、任务权限、执行预算与环境；不得只给 E 额外事实、审批者或答案。两类比较分开：同基础状态的配对 continuation（隔离恢复机制），以及各自完整 E2E（包含前期状态构建成本）。允许不同存储格式与工具名称，评分器只看行为语义；适配器必须接受独立审查。

S 不能故意实现为任意 append/全部批准。共同安全设施保留，消融只移除指定语义机制；增加的 verifier 调用、检索、人工补位、维护工时都计入成本。先比较 E/T/S，后比较去掉投影、去掉失效传播、用常规审批替代提交规则；多项一起变更只支持组合效果。

## 评分、统计与失败

| 轴 | 定义 |
|---|---|
| 成果正确性 | 固定成果 rubric 全通过率；同时列原子 criterion 覆盖率，二者不混写 |
| 错误生效率 | 无效操作实际生效次数 / 无效操作机会数，并列任何违规的轨迹比例 |
| 合法完成率 | 按规则应能完成的操作/事项实际完成数 / 全部相应机会数 |
| 续行成功率 | 中断后预算内达到允许最终状态、义务无丢失且无重复效应的轨迹比例 |
| 接管负担 | 正确下一步、漏项/误批准、耗时、人工补位；失败/超时保留 |
| 成本 | 全程 tokens/费用/latency、审阅与状态捕获维护时间；未知记 null |

联合成功 = 成果通过且无关键治理违规，只作附加指标，必须同时公布分项。没有合法/无效机会的轴记 N/A，不记 100%。B0 当前只输出 checkpoint 符合性与轨迹通过，不伪造上述模型或人的指标。

pilot 建议 2 模型 × 3 条件 × 36 轨迹 × 3 次 = 648 次完整轨迹预算，另计消融；不是当前执行授权或功效保证。先用小规模估计方差/成本，再冻结正式规模、最小有意义差异及停止条件。以基础事项为聚类单位进行配对 bootstrap 区间；不将步骤和重复 seed 当独立样本。报告模型分层与扰动分层，勿用总分掩盖异质效果。多次均成功的 pass^k 与至少一次成功的 pass@k 分别命名，三次 pilot 不足以估计高 k 可靠性。

运行错误、超时、中断、缺失检查点均保留在尝试分母，区分 infrastructure failure 与行为失败。非法操作被明确拒绝且状态正确才通过；进程不可用不能冒充拒绝。修复后使用新版本重跑，原失败保留；接触留出后该批数据成为开发数据。

## Oracle 与接管实验

生产 validator 不可作为 benchmark grader。B0 的 JSON 期望由协议作者编写，grader 只比较规范化观察；这仅有代码依赖独立性，尚无独立语料作者或独立专业判断。原始 snapshot 随运行保存，允许检查 adapter 是否隐瞒状态。

B1/B2 需独立样本作者和 oracle 复核，正例与反例并存；检查缺失、重复、乱序、字段损坏和中断记录会被正确判败。适配器通过共同 observation schema 输出成果/有效版本/开放义务/生效事件；不得因缺少 SE 特有字段失分。NDA 语义答案单独复核，避免与域 verifier 共用规则函数。

B4 比较 transcript、普通交接摘要、共享工作面，信息内容与可用动作相同；真实参与者交叉体验不同条件，平衡顺序/难度并使用不同事项避免学习泄漏。预置可审阅错误，记录实际下一步及完成时间，超时作为删失/失败明确报告。研究需要按经验分层，pilot 只能探索，不给稳定总体提升。Agent handoff、静态读图、模型角色审阅都不能替代真实人接管。长期技能保留需要另设纵向研究。

## 复现与记录

每次保存工程 SHA/工作树状态、runner/adapter/grader/数据哈希、环境、条件、模型版本、预算、全部尝试、checkpoint 原始状态、操作错误、评分与缺失值。合成临时数据库自动清理；不读取个人凭据或实际案件。来源/版本/论文引用保持可追溯。当前命令见 [运行入口](../../../benchmarks/continuity/README.md)，本轮证据见 [回执](../../../evidence/se-continuity-20260908/README.md)。

## 外部方法输入

- [τ-bench](https://arxiv.org/abs/2406.12045)：最终数据库状态与重复运行可靠性；借鉴行为评分，不继承客服任务含义。
- [Matrix v1](https://arxiv.org/html/2608.12761v1)：区分任务结果与治理证据；其契约迁移失败提醒我们增加合法正例与独立样本，而非只验证拒绝能力。
- [Mnemosyne v3](https://arxiv.org/html/2607.00269v3)：提交/恢复机制对照；宽松基线的结果不等于优于成熟持久化工作流。
- [Harvey LAB 官方说明](https://www.harvey.ai/blog/introducing-harveys-legal-agent-benchmark)、[上游仓库](https://github.com/harveyai/harvey-labs)：可作为 B3 任务来源；正式纳入前固定实际数据版本、许可和可运行子集。添加变化后需新 rubric，不自动沿用原 gold。
