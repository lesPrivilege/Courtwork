These pages converge on distinct artifacts with explicit purposes and owners. They do **not** establish a community consensus for one repository directory holding every signal, nor do they specify retention or disclosure rules for ChatGPT sessions, user messages, design source files, roadmaps, or intermediary agents' scratch work. The local repository contract must decide those.

## Evidence versus possible local rule

The external evidence supports a modest handoff chain: stable agent entrypoint → current status/roadmap → exact issue or assignment → bounded Explore with source manifest → decision owner/status → implementation or verification receipt. The chain itself is a CourtWork design inference: none of the four sources requires these exact paths or prescribes that every user message be archived.

As a local-policy inference, archive disclosure could use staged retrieval: expose an index and source identity first, then open the exact snapshot when the task requires it. Preserve the raw message as provenance, and present any summary as a derived record with a link back to it. The external pages do not establish a safe default for publishing session content. The existing repository boundary keeps secrets, private work files and runtime data outside Git; any public source material still needs an owner-scoped disclosure check.

An Explore record should therefore remain dated, bounded, version-aware, and explicit about its author, source set, observed facts, inferences, failure/unknown cases and limits. Its job is to make later review cheap and traceable, not to act as a proposed decision or roadmap item by implication. A parent decision owner can accept, reject or defer the recommendation and link that disposition to the relevant roadmap/contract/issue.

## Limits

This check did not survey project-management systems, public open-source repositories, archival/privacy standards, or historical CourtWork issue/PR/session completeness. GitHub's pages describe its template behavior, not the current remote repository state. AWS's ADR lifecycle is one established vendor guide. No new requirement or release gate follows from this source note; Astra owns the final local choice.
