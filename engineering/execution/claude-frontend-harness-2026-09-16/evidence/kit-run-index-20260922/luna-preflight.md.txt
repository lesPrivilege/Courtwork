## Minimal persisted representation

The fewest-owner choice is not an independent Kit catalog. Keep Kit definitions/descriptors with the Harness/RD-009 contract, and extend the existing agent_profile source through a backward-compatible profile-source version with explicit immutable Kit references, for example {id, version, sha256}. Do not overload resourceIds with undeclared kit strings: that field is currently an admitted resource allowlist and Runtime Control uses it for exposure ceilings.

At Run admission, the Harness K3 compiler should consume the validated profile binding plus explicit Kit descriptors and produce a deterministic kitPlan containing:

- selected Kit references and descriptor digests;
- ordered existing instruction/resource references;
- required, missing, unsupported, unchecked and deferred states;
- compatibility evidence supplied by the selected Runtime adapter;
- exact serialized context hash, UTF-16 character count and byte count; and
- compiler/plan version.

Persist that plan only inside the frozen Run runtime snapshot/binding in the same store.createRun mutation that emits runtime.bound. Keep the current profile/Kit selection as mutable configuration; never use it to reinterpret a recorded Run. The existing bound content/context references and hashes remain the source of exact material. If the strict Run schema requires a new field, RuntimeStore’s existing migration/backup owner handles the next schema increment; do not create kit-state.json, a second registry or a parallel CAS.

The execution path should read the frozen entry.runtimeBinding and invoke the existing compiler view. A profile/Kit edit during an active Run remains blocked by the current configuration/active-Run rules; a later Run creates a new binding. A lost/unknown Run keeps its original plan and result/effect fences; retry/reconcile never recompiles it from current configuration.

## Completion boundary

K3 can proceed as a contract and persistence-owner decision followed by a pure deterministic compiler/validator. It must not change profile UI, 06e, Settings, Runtime registration, permissions, Pi process lifecycle, ArtifactHistory ownership or child scheduling in the first increment. The Kit compiled proves only a plan/context projection; Run admission, native execution, source coverage, result consumption and formal Work acceptance remain separate facts.
