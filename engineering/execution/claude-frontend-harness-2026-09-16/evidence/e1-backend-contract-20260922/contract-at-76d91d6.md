## E1 frontend consumer contract — current implemented owner facts

The live lane uses authenticated `/api/v5` endpoints, not06a's synthetic per-profile store. All successful existing endpoints return200. A selected ordinary Chat must have its real Session ID before selection is persisted; an unsent chooser choice is frontend draft intent and carries no Run authority. No new server draft/profile registry is needed for this bounded first consumer.

1. Read `GET /runtime-control?sessionId=SESSION_ID`. `revision` is whole-configuration CAS. `resources.filter(r => r.kind === 'agent_profile')` supplies available profile IDs/titles, `source.hash` for imported source identity (`agent:general` is builtin), scope and selected/exposed reading. `composition` describes the effective selected profile: `id,version,hash,status,resourceIds,uiSlots,missing`; v2 additionally has `schemaVersion:2,kits,selectionScope`. `activeRuns` and `compatibility.hotSwap:'between-runs'` explain why a live edit may be refused. This is not a per-profile revision. Resource `permission` remains a separate per-action reading.
2. Inspect imported source through existing `GET /runtime-resources/ENCODED_ID?sessionId=SESSION_ID` (`resource` plus `content`), where `content` is exact profile JSON. v1 has no Kit declarations; v2 has the bounded `kits`. A draft can retain `{profileId,sourceHash,observedConfigRevision}` locally while preserving text/caret/materials. Do not display a local draft as effective or supported. The current executor remains the single Host-owned Pi Runtime; Models keeps global Provider/Model ownership.
3. Apply selection with `PUT /runtime-control?sessionId=SESSION_ID`, body `{revision:observedConfigRevision,operation:'profile',scope:{type:'session',id:SESSION_ID},id:PROFILE_ID}`. `agent:general` is explicit General; `null` inherits. Success returns the authoritative fresh Runtime Control snapshot.409 `runtime_conflict` means reread and retain the local draft;409 `active_run` means configuration stays frozen. On lost reply, reread the actual snapshot and compare selected ID/source hash before deciding whether another action is needed. No invented idempotent profile-save receipt exists. Source editing, if needed, uses existing `operation:'put',resource:{id,kind:'agent_profile',title,scope,content}` with whole-config CAS, then a fresh selection/readback; no per-profile save endpoint.
4. Start through existing `POST /sessions/SESSION_ID/runs` with `{input,commandId}`. The same command returns its original Run before consulting new configuration. New Kit admission returns400 `invalid_kit_input`, `kit_context_refused` or `kit_payload_budget`;409 `profile_incompatible`, `kit_scope_unsupported` or `kit_runtime_unsupported`; existing provider/permission/runtime errors remain distinct. A declaration-only compatibility absence is not an incompatibility: the admitted summary records `compatibility.status:'unchecked'` plus `policy:'reference-only-pi-unchecked-v1'`. Profile source cannot assert owner evidence. UI should preserve draft/materials on refused admission and display the specific owner message; it must not fabricate supported/ready.
5. Inspect bound facts through `GET /runs/RUN_ID` (`run.kitBinding`, null for no Kit) or `GET /runtime-context?sessionId=SESSION_ID&runId=RUN_ID` (`binding`, and for Kit `kitBinding,kitContext:{text,plan}`). These facts survive edits/restart; a recorded Run is not a current chooser state. Missing/corrupt history returns its failure and never substitutes current text. Existing Run status/usage/assistant events remain the result/lifecycle owners.

These endpoint shapes are implemented in current K3 source; combined E1 UI wiring/visual acceptance is still Claude/parent work. No synthetic preview adapter is a fallback for these live calls. Frontend static module names, if needed, are supplied to this backend writer for the existing server allowlist.

E1 admission intent addition: `POST .../runs` also accepts optional `runtimeSelection:{revision,profileId,sourceHash}` (`sourceHash:null` only for builtin General). This is a submitted expectation of the actual effective snapshot, not new persisted draft/configuration authority. After original-command receipt lookup and within the existing configuration queue, compare all three with the binding being admitted.409 `runtime_selection_conflict` preserves the draft and requires readback; no Run/provider call occurs. Without the field legacy clients retain existing behavior. Replay intentionally returns its old Run before checking a newer expectation. This closes the chooser-read→Send race without inventing per-profile revisions or a second draft owner.
