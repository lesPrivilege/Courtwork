## Answer for Astra

A Hermes executor cannot be admitted to the current global Attention role through capability registration alone.

Three independent boundaries must be respected:

1. The current Host executor path admits only Pi and Agents API IDs. A Hermes ID needs a new adapter registration and identity/configuration decision.
2. The current remote durable ledger is not runtime-generic: it hard-codes runtimeId agents-api, Agents protocol fields, and tool-result/call semantics. A Hermes remote binding cannot honestly be stored as agents-api or as Pi hostSession.
3. Global Attention executor choice is deliberately ineligible/read-only today. A global Session’s Run keeps the default Pi executor, and the existing Attention tools require a model-reachable governed tool loop. A text-only Hermes Run can be a bounded consultation only after an explicit consumer contract; it cannot claim the delivered Attention assistant behavior.

Whether a Store schema version bump is required is unresolved until the remote-record contract is chosen. Existing schema 22 has enough generic-shaped executor fields for a new descriptor/binding identity, but the schema-19 remoteBinding/remoteActions contract is semantically Agents-specific. A capability-only registration is therefore insufficient. A contract generalization could preserve schema 22 bytes if every existing field remains valid; introducing Hermes-specific durable fields or changing exact record shapes would require an explicit migration decision and byte-preservation evidence.

## Global Attention and text-only Hermes

The current global role remains explicit:

- app/docs/attention-agent.md:1-25 says Attention is a global role; Session owns the conversation, Run owns execution, global scope is immutable, and global Sessions cannot bind Matter extensions.
- app/docs/attention-agent.md:27-37 defines progressive Attention/memory/governance tools and says all executors pass governTools; no scheduler, generalized connectors or Expert delegation are delivered.
- app/runtime/attention-tools.mjs:27-83 defines the model-facing tools: attention_projects, attention_list, attention_inspect, memory_list, memory_read and governance tools.
- service.mjs:3188-3199 creates Attention tools only when session.scope is global and wires them through the captured attentionRuntimeAdapter/governance adapter.
- app/tests/attention-agent.test.mjs:13-44 proves the delivered global Run using attention_projects is a real governed Run and records tool.result/runtime.bound events.
- app/tests/attention-http.test.mjs:248-318 proves the Runtime Attention adapter can query/record a signal only under captured Host context; it rejects forged status/resolution and late calls.
- app/tests/runtime-selection-http.test.mjs:243-256 proves global Attention executor choice is locked with lockReason not_ordinary_chat, a PUT is executor_ineligible, and a global Run keeps Pi.

A text-only Hermes Port with submitToolResult=false can be honest only as a separately named, consultation-level consumer:

**Permitted outcome**

- Host starts a bounded Hermes text Run with no model-reachable CW tools.
- Host records the normal CW Run/input/assistant text/status observations and native identity.
- Text is an untrusted runtime observation/advisory. Run completion does not acknowledge, resolve, signal or formally accept an Attention item.
- Human users can use existing Core HTTP/UI actions separately.

**Mandatory refusals**

- Do not pass attention_projects/list/inspect, memory_list/read, governance or MCP tools to the Hermes text-only Port. Those tools require a tool-result loop and governed runtime adapter calls.
- If the native runtime emits a tool/approval/function-call request anyway, refuse before any local effect with a typed unsupported-capability outcome; do not execute, submit a result, or silently fall back to Pi.
- Do not call attentionRuntimeAdapter.query or recordSignal from text output. There is no model-originated disclosure context or Host-approved signal action without a tool-result path.
- Do not resolve/snooze/acknowledge/reopen an Attention from Hermes text, terminal output, run completion, cancellation, restart status or delivery.
- Do not present the text-only lane as the full global Attention assistant. If the product surface cannot distinguish consultation from governed Attention, admission should refuse with runtime_capability_unsupported until the tool-result contract exists.
- If a Hermes native run is unresolved after transport loss/restart, fence the CW Run and Session using existing remote_unreconciled/unknown semantics; never create another native Run automatically.

The answer to “can text-only Hermes be admitted to global Attention?” is: **not as the current delivered global Attention executor.** It can be staged as a bounded text-only consultation fixture after a separate role/consumer contract, but it cannot honestly claim Attention discovery, memory, governance, signal recording or obligation handling.

## Risks and exact open decisions

1. Remote ledger generality. Parameterizing runtimeId/protocol while retaining schema-22 bytes may be possible, but Agents-only request/call/result assumptions must be proven against Hermes’ no-tool text lane. A new field or altered exact record shape would make migration ownership explicit.
2. Global role binding. Current global Sessions reject executor choice changes. Astra must decide whether global Attention remains Pi-only, gains a role-specific fixed Hermes binding, or admits a separate consultation surface. Do not silently relax executor_ineligible.
3. Provider route. Current service rejects any remote executor under a non-fake Provider (service.mjs:2811-2815, getExecutorChoice :778-802). A synthetic fixture can stay fake/provider-free; live Hermes requires a separate provider/configuration contract.
4. Tool-result absence. Without reply/tool-result, text-only Hermes cannot consume existing Attention/memory/governance tools. Treat unsupported calls as refused capability and keep formal Core state human/Host-owned.
5. Native identity and restart. Native session IDs, API-run IDs and Hermes status must be bound in the remote ledger; status/restart evidence cannot be substituted for missing effect receipts or tool results.

No schema migration, executor allowlist, production exposure, global Attention binding, provider route or test implementation was performed in this preflight.
