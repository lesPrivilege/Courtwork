## Run lifecycle and handoff ownership

The lifecycle is already split in source. Preserve this split in the design and in any future real-provider work:

1. **Fixture entry:** `capture-fixture.mjs` creates a new temporary `dataDir`, calls [`app/server/index.mjs`](../../../app/server/index.mjs) `startServer` (lines 191–255), configures the local fake provider and extension through authenticated HTTP, and creates projects, sessions, bindings, Core Attention records and natural-language Runs. It is a capture operator, not a product authority.
2. **Host/runtime startup:** `createRuntime` in [`app/server/runtime.mjs`](../../../app/server/runtime.mjs) opens `RuntimeStore`, starts `WorkCoreOwner`, the extension registry, isolated model runtime and fake provider, then returns one runtime owner. The HTTP server only authenticates/routes requests; it does not own domain facts.
3. **Run admission/execution:** `RuntimeService.createRun` and its active entry own Run admission, provider selection, extension begin/close, permission waiters, tool admission, terminal status and append-only event projection. `createSessionRun` in [`app/runtime/pi-session-runtime.mjs`](../../../app/runtime/pi-session-runtime.mjs) owns one Pi AgentSession per Run, provider streaming, `waitForIdle`, abort and the final `completed`/`aborted` result. `RuntimeStore` persists Run/event facts; `WorkCoreOwner` remains the single Core writer.
4. **Browser projection:** `app/web/app.mjs` owns navigation, event polling, draft persistence, Run/cancel requests and focus restoration. It reads status words and facts; it does not manufacture a Run, approval, Attention revision or provider capability. `home-view.mjs`, `attention-view.mjs`, `spark-view.mjs`, `settings-view.mjs` and `surface-modules.mjs` are projections/renderers.
5. **Run exit:** a stable seed waits for terminal status. For a live capture, the operator captures while `waiting_user` or `running`, then sends the process signal. `startServer.close()` stops accepting HTTP before `runtime.close()`; `runtime.close()` closes service, registry, fake provider, Core and store. The running correction explicitly cancels the active Run before close. The service's cancel path preserves `stopping` until the owner reports `cancelled` or `unknown`; it does not claim success early.

The disposable capture process is not yet the requested in-product preview. For capture testing, keep temporary fixture IDs, fake credentials and runtime data isolated from real work. The new product preview should consume one deterministic story in its own projection identity, without starting a fake runtime inside the user's real data directory. Existing real projects and sessions remain in their existing store; switching from preview to real execution must not require a new data directory or migration. RuntimeService's successful real Run admission and the browser's confirmed real identity provide the handoff facts. A rejected start or a click is not success. Remove the preview projection only, retain drafts and user data, and keep an explicit path to reopen examples. Root/Astra owns this new behavior through [ONE-SHOT](ONE-SHOT.md); the capture recipes above are source precedents, not an implemented preview lifecycle.
