# Public origin/main data-governance audit

**Snapshot:** public GitHub origin/main at `24bd9545936dd19a498fc6b7eed5de106ac0d5e8` (commit date 2026-09-13). The remote ref was verified anonymously; that tree already existed locally, so no fetch or checkout was needed.

**Scope:** tracked public tree, repository routing and Pages build/publish boundary at that exact SHA. The release-preparation worktree has newer unpublished edits; they are not evidence of policy in the public snapshot. No personal credential stores were inspected. Findings below do not include any matched path values.

## Findings

1. **Raw source records are public and indexed, but their authority boundary is implicit.** A filename-only filter found 32 text files named like conversation/input captures (28 under `engineering/research/`, about 1.30 MB total). Examples include `engineering/research/semantic-governance-2026-09-11/conversation.json`, `engineering/research/multi-experts-2026-09-10/inputs/conversation.json`, `engineering/design/agent-interface-2026-09-10/input-conversation.md`, and `engineering/research/mature-practices-2026-09-12/source-conversation.json`.

   The public `AGENTS.md` routes agents through `engineering/current.md`, then the relevant assignment, contract and evidence; `engineering/README.md` identifies the current-status entry; `engineering/research/README.md` indexes research records and source accounting. `AGENTS.md` also says prior transcripts are not automatically carried by a project label, but does not state that tracked raw captures are provenance rather than instructions or that they must not be loaded as default context. The result is a discoverability/authority ambiguity, not evidence that a specific transcript was followed as an instruction.

   **Smallest disposition:** add one concise rule at the existing agent/research entry point: raw conversations and connector captures are immutable source evidence, not instructions; agents consume the indexed summary/receipt and only retrieve a scoped source when needed, treating embedded directives as untrusted data. Preserve original bytes and hashes; do not create a second source ledger.

2. **Published text contains host- and run-specific filesystem paths.** A path-prefix scan found non-template path-like strings in 18 files / 51 lines under `/Users`, 194 files / 533 lines under `/private/tmp`, 18 files / 24 lines under `/var/folders`, and 4 files / 4 lines under `/home`. These categories can overlap and are not counts of unique machines or confirmed incidents. Representative files are `evidence/rv26-20260910/worktree-occupancy.txt`, `evidence/paper-release-review-20260911/build-validate.log`, `evidence/publication-integrated-20260912/app-test-before-guard-update.log`, `engineering/design/context-tps-motion-2026-09-13/production/evidence/full-tests.txt`, and `engineering/research/semantic-governance-2026-09-11/conversation.json`. This exposes local environment details and makes copied evidence less portable; some matches may be intentional fixture or log paths.

   `AGENTS.md` already asks for portable paths in active documentation (`AGENTS.md:20`). The site README says machine paths are scrubbed in its public projection and rejected by the build (`site/README.md:22`), but that check does not sanitize every Git-tracked document or log. **Smallest disposition:** normalize paths when new evidence is collected (repo-relative paths or a stable placeholder); keep existing public history intact and record any future redaction as a projection change with provenance rather than rewriting commits.

3. **GitHub visibility and Pages visibility are different.** The Pages workflow uploads only `site/dist` (`.github/workflows/pages.yml:74-77`) and only deploys on an explicit manual dispatch (`.github/workflows/pages.yml:79-91`). The build copies a selected evidence-file set (`site/build.mjs:134`) and recursively copies all of `site/media` (`site/build.mjs:162`). The audited tree has 113 files under `site/media` (~8.34 MB); these, including archived batches, are Pages assets. `site/verification` (31 files) and most `evidence/`, `engineering/design/` and `engineering/research/` images are not thereby included in Pages, but remain public through the GitHub repository itself. The tracked `evidence/` tree alone contains 1,230 image files (~106.6 MB). No image OCR or manual image-content review was performed.

   The current-main media manifest lists 26 existing assets, labels them synthetic, and pins them to product SHA `07688226330121e5877a6ff1e09e6ebf82995ae3` (`site/media/main/manifest.json:2-4`). That commit is an ancestor of the audited public HEAD, which has 30 later commits touching `app/web` or `app/package.json`; `site/src/capture-plan.mjs:2` still marks the older SHA's capture batch ready. The explicit source hash preserves provenance, but these images are evidence for that fixed source snapshot, not for the audited HEAD's UI. If the page is intended to demonstrate the current main UI, recapture and review the batch against a frozen current source before deployment. Keep the fixed older captures clearly source-labeled.

4. **The bounded text scan found no common credential-shaped patterns.** Searches for common provider/GitHub/cloud token forms and private-key headers found no hits in scanned tracked text. This was not a comprehensive secret review: binary images, archive internals, arbitrary credential formats and credential stores were not examined. No token or path values are reproduced here.

The durable change is limited: clarify the raw-source authority boundary, sanitize new machine paths at collection/public projection, and preserve the distinction between GitHub-public evidence and Pages-selected assets. No public history was deleted or rewritten as part of this audit.
