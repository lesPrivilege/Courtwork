## Adapter seam and terminology

The provider boundary is a small Go `Backend` interface: `Execute(ctx, prompt, ExecOptions)` returns streamed `Session.Messages` plus one final `Session.Result`. `ExecOptions` carries cwd, model, prompt/context fallback, resume ID, custom args, MCP config, and runtime-native controls. [`server/pkg/agent/agent.go#L17-L112`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/agent.go#L17-L112) This is an executor/adapter contract; it does not establish the broader claim “daemon = HarnessCore”.

`Command` separates executable identity from a fixed argv prefix, and every task, version probe, and model probe is meant to cross the same launch boundary. [`server/pkg/agent/launch.go#L45-L115`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/launch.go#L45-L115) A custom profile is `command_name + fixed_args`; `BuiltinRuntime` separately maps a runtime identity to a protocol family and backend. [`server/pkg/agent/agent.go#L294-L327`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/agent.go#L294-L327) [`server/pkg/agent/builtin_runtimes.go#L8-L28`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/builtin_runtimes.go#L8-L28)

## Representative backends

**Pi.** Multica launches `pi -p --mode json --session <path>`, sets `cmd.Dir` from `opts.Cwd`, writes the prompt on stdin, and closes stdin. The session file path is the opaque resume ID; refused resumes are detected from stderr. [`server/pkg/agent/pi.go#L350-L412`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/pi.go#L350-L412) The adapter deliberately omits `--tools`, preserving Pi and extension tools; restrictions must be explicit custom args. It also relies on workdir `AGENTS.md`, rather than duplicating `SystemPrompt`. [`server/pkg/agent/pi.go#L980-L1028`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/pi.go#L980-L1028) The refused-resume fake-CLI test exists, but was not run. [`server/pkg/agent/pi_resume_refused_unix_test.go#L15-L84`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/pi_resume_refused_unix_test.go#L15-L84)

**Hermes.** The backend always starts `hermes acp` and speaks ACP JSON-RPC over stdio. It sets the task cwd and forces `HERMES_YOLO_MODE=1`, so autonomous permission behavior is materially different from Pi. [`server/pkg/agent/hermes.go#L248-L317`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/hermes.go#L248-L317) `session/new` and `session/resume` receive ACP-shaped MCP servers; remote transports are filtered after the initialize capability response. Resume checks provenance because Hermes may return success while silently serving a new session. [`server/pkg/agent/hermes.go#L502-L570`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/hermes.go#L502-L570) The source has fake ACP tests for silent rebind, but they are unrun here. [`server/pkg/agent/hermes_resume_test.go#L103-L180`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/hermes_resume_test.go#L103-L180)

**Codex and Claude.** Codex materializes managed MCP into task-local `CODEX_HOME/config.toml`, fails closed without an anchor, and uses `thread/resume`/`thread/start` with cwd and model. [`server/pkg/agent/codex.go#L1034-L1079`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/codex.go#L1034-L1079) [`server/pkg/agent/codex.go#L1954-L2024`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/codex.go#L1954-L2024) Claude uses stream-JSON, task cwd, `--resume`, a temporary managed MCP file, `--strict-mcp-config`, and `bypassPermissions`; its control requests are auto-allowed in the adapter. ## Context, skills, MCP, and managed markers

Context injection is provider-native: Claude, Pi, OpenCode and others receive workdir skill files; Codex uses task-local `CODEX_HOME`; Hermes uses a `HERMES_HOME` overlay because it has no workspace-relative skill discovery. [`server/internal/daemon/execenv/context.go#L121-L180`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/internal/daemon/execenv/context.go#L121-L180) Disabled skills are translated into Claude settings denies or Codex disabled skill entries. [`server/internal/daemon/execenv/runtime_skill_policy.go#L32-L93`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/internal/daemon/execenv/runtime_skill_policy.go#L32-L93) The source also has managed `BEGIN`/`END` context blocks that preserve existing `CLAUDE.md`, `AGENTS.md`, and `QWEN.md` content; the exact locator was not re-opened within this visit's 14-call read budget, so treat that detail as unverified here. Those blocks are distinct from the JSON discovery/provenance marker below. A non-secret `.multica/daemon_task_context.json` marker with `managed_by` serves as a daemon-task discovery/provenance hint when child sandboxes strip `MULTICA_*` environment variables; it is not a security boundary. [`server/internal/daemon/execenv/context.go#L17-L53`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/internal/daemon/execenv/context.go#L17-L53)

MCP has explicit three-state semantics: null means inherit, any object including `{}` means managed. [`server/pkg/agent/mcp_config.go#L8-L14`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/mcp_config.go#L8-L14) A generic adapter must not treat MCP, skills, or permission flags as portable CLI options.

## “26 CLI” and recommendations

The apparent 26 is a registry shape: 25 `SupportedTypes` protocol families plus one built-in `omp` identity that reuses the Pi backend. [`server/pkg/agent/agent.go#L330-L376`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/agent.go#L330-L376) [`server/pkg/agent/builtin_runtimes.go#L79-L101`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/builtin_runtimes.go#L79-L101) The lockstep test asserts that each family constructs through `New`; it does not prove a CLI is installed, protocol-compatible, or tested against a live provider. [`server/pkg/agent/agent_supported_types_test.go#L8-L32`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/agent_supported_types_test.go#L8-L32) Version probes can skip registration on failure. [`server/pkg/agent/run_collect.go#L241-L247`](https://github.com/multica-ai/multica/blob/8c4f4328f6e3baff08394b309034463b5db9d7af/server/pkg/agent/run_collect.go#L241-L247)

**Adopt:** the `Backend`/`Command` seam, protocol-specific lifecycle and resume evidence, native context placement, managed MCP markers, and explicit runtime identity versus protocol-family split. **Adjust:** call these provider adapters/executors and keep daemon orchestration separate; capability discovery must be version- and executable-scoped. **Reject as source fact:** “daemon is HarnessCore” and “runtime is a uniform executor”; the code demonstrates heterogeneous adapters with divergent permissions and context contracts. The repository is a behavioral reference only; no source is copied and no compatibility acceptance is claimed.
