## Concrete return: stale chooser can remain visible during Chat/Attention navigation

`syncAgentChoice` captures `choice` before starting a new session read (`app/web/app.mjs:3812-3821`). When navigation changes from an ordinary Chat to another Session, it calls `agentChoice.load()`, but the `shown` predicate is based only on the captured/possibly stale snapshot's `sessionKind`:

```text
const shown = Boolean(session) && !state.attentionOpen && choice.snapshot?.sessionKind !== "global";
```

It does not require `choice.sessionId === session.id` or a ready snapshot. During the new read, `readSnapshot` clears the controller snapshot and emits loading (`agent-choice.mjs:167-179`), but `renderComposer` can still set the chooser visible for the new Session because `shown` treats `null` session kind as non-global. The same route can briefly expose the prior Chat's effective Agent while opening the global Attention Session, or expose the prior Chat label while the new Chat's snapshot is loading. The Send path also computes `current` separately and may be waiting on a different state, so the visible control and send guard are not one projection.

Smallest correction: visibility must require a matching session and an explicitly ready snapshot whose `sessionKind` is `chat`; while loading or mismatched, hide the chooser and keep Send disabled until the new session's reading is ready. Add a navigation regression for ordinary Chat → ordinary Chat and ordinary Chat → global Attention during a delayed `runtime-control` read.

## Additional concrete return: first Settings deep link loses the selected source row

The chooser's Settings callback calls `openSettings("developer", { trigger })` and immediately calls `runtimeView?.openResource(id)` (`app/web/app.mjs:7623-7628`). On a first Settings visit, `openSettings` starts `refreshSettingsReads()` asynchronously (`:6808`, `:6816-6819`); `runtimeView.openResource` returns `false` when `resourceById(id)` is not yet present (`app/web/runtime-view.mjs:2799-2813`). It does not retain a pending resource id. Consequently the page opens at Developer overview and the requested Kit/source row is not expanded after the snapshot arrives, matching the parent browser observation.

Smallest correction: queue the requested resource id until the Runtime Workbench's first read has rendered, then call `openResource` against that loaded snapshot; preserve the existing focus return and source-read generation guards. Add a first-visit deep-link regression, separately from the already-loaded Settings case.
