## Directional boundary

The five sources support a small CW seam, not a shared industry ontology: `Role` describes product intent; `Runtime` selects a local or hosted execution transport; `Provider` and `Model` are execution configuration; `Capability` is a truthful, versioned contract. The direct counterexamples are material: Pi extensions run with full system permissions, Hermes delegated work is tied to its owner process, DeepSeek Harness is still alpha, CC Switch may convert protocols locally, and OpenCode subagents inherit the caller's model when no override is set. Therefore none of these sources justifies binding a role to a runtime/provider/model, assuming a cheaper or sovereign model is available, or treating a green wrapper test as runtime acceptance.

**Kit-adjacent precedent:** Pi packages can bundle extensions, skills, prompt templates and themes, with package dependencies and pinned install refs ([packages at the same pin](https://github.com/earendil-works/pi/blob/d981de1229ef899957bbe968bc8dcda02a21f477/packages/coding-agent/docs/packages.md)); CC Switch also documents cross-app MCP/Skills management. These are packaging/synchronization precedents, not a portable Expert contract: no source in this bounded scan proves cross-runtime extension compatibility. CW should therefore keep portable Kit content/manifest separate from runtime-specific hooks and resolve dependency/version/conflict failures before admission. The existing authorization form remains `AllowedCapabilities = Requested ∩ Granted(actor,scope,t) ∩ HostPolicy ∩ RuntimeSupported(rev) ∩ EnvironmentAllowed`: Role/Kit contribute requests and constraints; Provider declares model capability but does not grant execution authority. The intersection is a decision input, not a claim that every resulting capability is implemented.

**Not verified in this pass:** CW adapters against any of these live runtimes, real child execution, provider quality or subscription access, restart/recovery under external transport, security sandboxing, or product acceptance. Version pins were read from public release/tag metadata and source at the cited commits; no credentials or personal stores were inspected.
