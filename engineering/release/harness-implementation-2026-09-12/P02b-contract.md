# P02b · Bounded MCP semantic result fidelity

Astra local architecture decision. This slice consumes the existing RuntimeStore event owner and ArtifactHistory content-addressed bytes; it does not create another transcript, Work artifact or Core state.

Capture the decoded protocol's semantic fields `content`, optional `structuredContent`, and `isError`. Protocol `_meta` at result/content-block/embedded-resource level, request arguments, headers and credentials are excluded. This is a semantic result snapshot, not a claim of raw wire capture. User-supplied structured result values remain data, not instructions or governance facts.

Limit each retained semantic result to 1 MiB after SDK decoding. Model/UI projection is up to 32 KiB plus a short partial marker. Text and images are preserved when supported within the budget; other supported protocol blocks are explicitly labelled JSON. Both body and structure are projected, including false/null/array values when allowed by the negotiated SDK protocol. Truncated or skipped blocks are partial and resolve to the full retained semantic snapshot. Oversized/invalid/unpersistable results are unavailable and fence effects conservatively; no unbounded raw fallback or invented complete result.

The existing per-session ArtifactHistory stores immutable bytes. A `runtime.mcp.result` event records call/server/tool/config/binding identity, byte length, SHA-256 and projection coverage. It is the authority for a scoped read; a guessed digest or another session cannot obtain bytes. The reader verifies the content hash/length through the existing store. Events and native tool details contain only the pointer and bounded projection; `_meta` is not written to public logs.

Errors first close admission via P02, then retain their supported semantic result. Pi's public afterToolCall seam marks the returned MCP error result as isError while preserving its content/details and native image normalization. An adapter marker is generated by Host code, never taken from remote structuredContent. A failure to retain a result remains unknown, not a successful empty result.

Allowed paths: mcp-result.mjs, mcp-manager.mjs, pi-session-runtime.mjs, service.mjs/index.mjs, ArtifactHistory owner comment, runtime-control API/DTO documentation and focused tests. No UI redesign, schema migration, new dependency or paid provider. The added read API is an on-demand result reader, not a new writable resource service. P11 remains responsible for richer UI consumption.

Follow-up: the Host creates a unique dispatchId before each dispatch. It is distinct from the provider's callId and identifies the scoped result reader, so repeated native IDs cannot resolve the wrong receipt.
