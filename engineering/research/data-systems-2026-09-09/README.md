## 从实际需要推导，而非从技术名词推导

| 实际需要 | 可证伪的不变量 | 最小工程转译 |
|---|---|---|
| 人稍后仍能判断当时接受了什么 | 接受身份、精确内容、来源版本与决定可回读；当前适用性单独判断 | 复用 Core 的 Candidate/Artifact/Decision；补可携带的只读核对清单 |
| 换模型、窗口、界面后工作不丢 | 工作效力不由 provider session 或 renderer 恢复；只替换已声明的轴 | 固定历史样本及消费者契约，逐轴替换验证 |
| 索引损坏后能继续工作 | 缓存丢失影响速度或便利性，不改历史接受；重建使用合法保留的真源 | LG-02/04 的独立全量重建、失效与回退检查 |
| 写入后进程可能在回执前死亡 | 同一请求可查询、重试不重复决定；外部效果未知时不能猜成功 | Core 已有事务/回执测试；跨域效果另建有界实验 |
| 新版本仍解释旧数据 | 数据格式、行为语义、领域契约各自声明兼容；拒绝不支持的写入 | 将 ES 迁移和 AM 维护组织成一份有限版本矩阵 |
| 治理成本必须有实际收益 | 错误放行和不必要阻断都能测；增加结构须降低可观察成本 | 合法/非法成对用例，记录审阅与恢复负担，允许取消候选 PR |

这里的“权威”按对象和操作定义。来源字节权威不等于其中断言可信；执行记录对“工具做了什么”有证据价值，不取得成果接受权。用户偏好、草稿、运行日志也未必是可丢弃缓存。删除派生层可重建的前提是来源与处理版本仍被合法保留；保留期结束后应明确不可用，不能通过重建复活已撤销访问的数据。

## 对报告的采用裁定

采用 source/derived 区分、确切对象决定、版本演化、恢复与替换实验。它们沿 [M01–M14](../../architecture.md) 与 [R0–R5](../../roadmap.md) 消费，不形成新的 control/data/compute 三套服务。

报告的 `ActionProposal` 是示意，现有 Candidate 与 actions 已有版本、actor、CAS、幂等责任；优先扩原合同。现有 Core 使用 B0 SQLite state + audit，B1 是另有实现的实验模式，不能直接转为全系统 event sourcing。异步派生只有出现实际消费者与丢更新风险才考虑同事务 outbox；不要求 Kafka、CDC 平台或新数据库。

报告中的 SE 泛指软件工程。本项目 Schema Engineering 的语义采用仍由 [PAPER.md](../../../PAPER.md) 固定9.6，不用外部研究重解释 doctrine。未来研究观察须有工程 commit 与证据，再进入唯一 Practice Index；本次不改论文。
