# 成熟 Agent GUI 的完成面

“完成面”指每条用户路径都有可理解的状态、可执行动作和失败/恢复出口，不是把所有竞品功能放进 MVP。本表为本项目的要求；上游事实另外记录在 [sources](sources.md)，未逐行断言 OpenWork 或 DSH 已全部实现。

P0 是所选首个闭环必须设计和演练的行为；P1 是能力一旦开放就必须补全的行为；P2 是后续独立决策。所有项目前均未实测。

| ID / 级别 | 表面与状态 | 用户动作与恢复出口 | 状态所有者 / 验证重点 |
|---|---|---|---|
| UI01 / P0 | 首次进入、无工作、无 Extension | 明确开始工作；不假装已有数据或强迫挑专家包 | GUI + Registry；空态到第一份输入 |
| UI02 / P0 | provider 未配置、凭证无效、服务不可达 | 配置/重试/保留草稿；凭证留在宿主边界 | Host；不能把网络错误误报无权限 |
| UI03 / P0 | 工作列表、新建、打开、切换 | 找回正在处理的工作及未完事项 | Matter；快速切换不串内容和回复 |
| UI04 / P0 | Composer 空/有草稿/发送中/未发成功 | 编辑、发送、换行、保留或重试；失败不清空草稿 | 本地草稿 + request identity；IME/粘贴/键盘 |
| UI05 / P0 | 附件待处理/读取中/ready/失败/不支持 | 查看、移除、替换；说明何者实际进入本次请求 | Resource/Run；不把附件 chip 等同已读 |
| UI06 / P0 | 流式输出、tool 活动、长等待 | 读内容、展开工具摘要、查原因、停止 | Runtime；不用虚构百分比、总耗时或推理过程 |
| UI07 / P0 | 长输出、选中文本、正在读历史 | 保持滚动位置、复制、回到最新 | GUI；追加内容不抢焦点或打断选择 |
| UI08 / P0 | 运行中输入新消息 | 明确何时生效：首版可排队或禁发并保留草稿 | Runtime；不要让用户误认已 steer |
| UI09 / P0 | 取消请求→停止中→已停止/未知 | Stop 可达、必要时查看未确定效果和恢复动作 | Runtime + Core；UI 停止动画不等于进程已退出 |
| UI10 / P0 | permission 待处理、拒绝、超时或过期 | 查看对象/作用范围、允许或拒绝；保留处理出口 | Host；不能与成果接受混为同意按钮 |
| UI11 / P0 | 普通问题、多个问题、已回答或失效 | 选择/自由回答/暂缓（按实际支持）；恢复待处理项 | Runtime；跨工作回复、重复回答检查 |
| UI12 / P0 | 断线、重连、刷新、运行状态未知 | 保留草稿；重取 snapshot；无法恢复则明确重开 | Adapter；可见 pending 和 terminal 不靠猜测 |
| UI13 / P0 | 失败、限流、超预算、工具部分成功 | 说明已保留什么、可重试哪步；未知效果先核查 | Runtime/Core；不全量重跑有副作用行动 |
| UI14 / P0 | Candidate/有效版本/旧版本/无产物 | 预览、复制、定位版本；下载能力按实际提供 | Artifact；不能将流式正文默认为成果已接受 |
| UI15 / P0 | Evidence 存在/缺失/错版/冲突 | 原文回跳、返回原阅读位置、请求补证据 | Repository；锚点与版本一致 |
| UI16 / P0 | Review 待判断/检查未完/提交中/冲突 | 接受、退回、要求修订；冲突后看新版本并重新判断 | Core；不乐观展示已接受、不重复提交 |
| UI17 / P0 | Run 已结束、工作仍有义务 | 看下一步、继续 Session 或另起 Run | Matter；运行完成与工作完成分开 |
| UI18 / P0 | 基础设置、隐私说明、快捷键帮助 | 找到连接、数据位置、必要限制；变更影响可见 | Host/GUI；技术细节按需，不占主工作面 |
| UI19 / P1 | 搜索、分支、归档、删除、未保存变更 | 搜索结果回到正确对象；删除后果与恢复明确 | Matter/Session；删 Session 不丢正式成果 |
| UI20 / P1 | 多工作后台运行、通知与消息队列 | 去重聚合、跳回目标、编辑/撤回队列（若支持） | Runtime；通知不代替 pending queue |
| UI21 / P1 | Extension 加载、升级、不可执行或已卸载 | 说明适用性、授权与退化方式 | Registry；catalog-only 不呈现可运行假入口 |
| UI22 / P2 | 桌面更新、远程、多用户、共享/外发 | 独立协议与验收，不假设已有安全/回滚 | Host/Authority；另立工程选择 |

## 横向完成度

每个 P0 面须覆盖空、少、密、长内容、错误和恢复中有意义的状态；逐项标不适用及原因，不能自动取笛卡尔积制造测试负担。检查键盘、焦点回归、读屏异步更新、reduced motion、窄窗口、缩放和中文 IME。流式 token 不逐个播报给读屏器；使用可控摘要与状态通知。

关闭尚不支持的能力不是设计缺陷；呈现可用入口却没有真实路径才是。prototype 中的假数据、延迟和故障注入要在演示说明标明，不能用 toast 代替持久失败处理。

## 首轮必须完整演练的六条路径

1. 首次配置→创建工作→输入/附件→运行→得到候选；在配置/附件失败分支保留输入。
2. 长输出→向上阅读并选择文字→工具等待→回到最新；过程不抢焦点。
3. 运行中编辑新消息→明确排队/未发送→停止中→已停止或未知；新消息不丢、不误执行。
4. 权限/普通问题→拒绝或回答→断线刷新→重新定位 pending；不串工作和授权。
5. 候选→原文与差异→补证据/退回→修订→接受；旧页面提交产生可解释冲突。
6. 中断后重新进入→恢复有效成果与义务→继续工作；Run end 不掩盖未完事项。

每条保留初始状态、操作、期望、实际、失败画面/录像和对应 request/Matter/version。静态图只能覆盖表示，交互、恢复和后端真实语义分别验收。
