# 工程工作流

状态：现行定本

## 角色

- 架构：拍板 schema 语义、跨层接口、ADR 与验收标准；不承担同工单验收。
- 实现：只实现工单和 SPEC 划定范围；跨层变化先提案。
- 验收：独立会话实测；可修实现级小缺陷，但不得改契约。

同一工单的实现者与验收者必须不同。模型名称不绑定角色，工单任命才绑定角色。

依次读取：`CLAUDE.md`、相关 ADR、本层 `SPEC.md`、直接依赖层的公开契约。先复述范围和不变量，再写失败测试。

## TDD 与门禁

1. 用测试或静态守卫证明缺口会红；
2. 做最小实现；
3. 跑定向测试；
4. 跑包级测试与 build；
5. 完工跑全仓 `pnpm -r build`、`pnpm lint`、`pnpm test`；
6. desktop 行为变更再用隔离端口跑完整 Playwright；

测试数字必须来自完整实跑原始输出；`--list`、选择性运行、缓存或实现者自述不能替代验收。

## 判例（跨工单适用，逐条带出处）

### 声明与效力三判例（2026-07-19 立，源 SKIN-B2-1）

**声明在场不等于效力发生。** 三条同族，凡验证「某物已生效」时逐条自问：

1. **支持声明 ≠ 实际效力**。`CSS.supports('text-spacing-trim', …)` 回报 true，而 `trim-start` / `trim-both` / `space-all` 与 base、与阴性对照四值同宽——引擎认得这个属性名，却没实现它的行为。**装一个证不出效力的属性就是装饰**，克制审计据此拒收。
2. **分支在场 ≠ 胜出**。CSS 规则、feature flag、条件分支存在于源码里，不等于它在真实层叠/优先级/运行路径下赢得了那一票。
3. **字节到位 ≠ 渲染上身**。字体文件入仓、`@font-face` 写对、`document.fonts` 里有这一项，都不等于它真的画在了屏幕上（懒加载、回退、别名不匹配都会在中间截断）。

**共同对治**：断言效力而非断言声明，且每条效力断言旁边跟一个**必定无效的阴性对照**；对照若也显出差异，说明测量本身没有区分力，该断言不成立。

**前向红卫写法（推荐）**：暂时验证不了的项，把「当前验证不了」本身写成断言（如 `expect(CSS.supports(...)).toBe(false)`）。引擎/依赖跟上那天它自己会红，逼着改成真验证——**不留死断言，也不留无声的乐观**。同「登记不是豁免」（源 SKIN-B2-0）。

### 置换批定式：震红既有断言是世界变了（2026-07-19 立，源 SKIN-B2-1）

消费面置换批必然震红一批既有断言。**默认判定是「本批改变了世界」，不是「它们原先写错」**，故处置定式为：**按其本意重写，不放宽、不删除、不加豁免**。三个实例：

- 断言钉死的是**旧机制的形状**（「字面 serif 栈恰一处」）→ 按本意改写为新机制下的等价约束（「裸 `font-family` 零 serif 家族名 + 家族名只许住轨声明」），结果**比旧法更紧**。
- 断言钉死的是**旧定值**（`font-size: 15px`）→ 承「断关系不断值」改为断档位与比值。
- 断言依赖的**前提被新机制改变**（壳自带 `@font-face` 后 `document.fonts.check` 会把同名的所有 face 计入，其中 CSS 那份懒加载故返 false）→ 修正前提（预热真实 face），顺带把该谱从「模拟装字」升格为「验产品真装了字」。

重写后必须复验其**可红性**：注入反例仍红，才算重写而非阉割。

### 枚举必须含阅读，计数不算枚举（2026-07-19 立，源 SKIN-B2-1，补正 SKIN-B2-0「换值前先搜绑定面」）

「换值/换机制前先枚举绑定面」的前一条判例只说了要**搜**。实践证明搜到不够：本批四类绑定面全部搜到，但对其中一处只记了「1 处」未读其内容，那条断言仍由全链跑出来。**枚举的完成态是「读过每一处并判明它断言什么」，只统计出现次数不算枚举。**

### 「逐位相等」管声明处，路由目标以真渲行为锁定（2026-07-19 立，源 SKIN-B2-1 ③ 裁定）

`unicode-range` 一类「声明的覆盖面必须与文件实有覆盖面逐位相等」的判例，**适用域是凡声明 range 之处**——它防的是声明与覆盖失配，**不是命令处处声明 range**。

分野：自带 webfont 的消费点，range 是它的契约面，必须逐位相等；而**以系统字为路由目标**的消费点（如壳侧拉丁配衬走 `local()` 系统字），正确锁法是**行为级双锁**——① 子集确含目标码位（逐位相等在此成立）＋ ② 真渲证明路由确实落到目标（并以阴性对照证明测量有区分力）。

**为满足字面而新造合成字族，是拿新概念换仪式感**，复杂度节制条挡下。

### 在场 ≠ 可见（2026-07-19 立，源 SKIN-B4，补「声明与效力三判例」第四条）

`toHaveCount(1)` 只证元素**在 DOM 里**，不证它**画得出来**。SKIN-B4 的落定章四条断言全绿，
证据一摄才发现它压在标题行下、线重被缩放压到约 0.96px——**一枚看不见的印连装饰都算不上**。

同族还有：`toBeVisible()` 只查 CSS 可见性与盒子非零，不查对比度、不查遮挡、不查缩放后的线重。
**对治**：凡「视觉件已上身」类结论，断言之外必须**摄一帧亲看**；量得出的（色、线重、位）
就量出来写进证据，量不出的就承认是目视。

### 归一化让两侧可比，也让两侧各自的写法约束失守（2026-07-19 立，源 SKIN-B4）

跨面 parity 门（站 vs 壳、源 vs 编译产物、schema vs 实现）为了可比，几乎都要先归一化写法差异。
**代价是它从此看不见任何一侧的本地写法错误**：SKIN-B4 的件库单源门把 `strokeWidth=` 与
`stroke-width=` 归一后逐字比对，于是壳侧误用 HTML 式 kebab 属性——React 当场拒收、该属性
从落地起就没生效过——parity 门一路放行，只有别的谱的运行时错误守卫偶然逮到。

**对治**：每写一条归一化，就同时问「它抹掉了哪一侧的什么约束」，并把那条约束补成独立断言。
补的不是手滑，是归一化自己带进来的盲区。

### 开口子就得同时封口子（2026-07-19 立，源 SKIN-B4）

给某类件开门禁豁免时，**豁免面本身必须立刻获得等价约束**，否则「不经 A 门」会被读成「无门」。
SKIN-B4 为记号系剥出 icon 门的内联禁令（`<use>` 零几何、件库是几何唯一住所），同批即补
「件库纯度」——symbol 之外零几何元素。**豁免与封口同一枚提交落地**，中间不留窗口。

判据：写下豁免条件后自问「符合这个条件的最坏输入是什么」，把它挡住才算写完。

### 不上也要登记（2026-07-19 立，源 SKIN-B4，承 SKIN-B3「答不出即不换」）

克制审计的结论**无论是上还是不上，都必须留痕，且留在机器看得见的地方**。SKIN-B4 五记号
两上三不上，三件不上的理由逐条进门内 `UNCONSUMED` 表并**双向锁**：登记件一旦被接线即红
（逼着改登记并补审计），新件既无消费又未登记亦红。

理由与 B3 的不换清单同源：沉默的未消费件与沉默的裸 1px 同病——**不登记，下一个人无从复核
当初为何不上，只会重新纠结一遍或干脆随手接上。** 推论：**不上者无帧可摄，这不是证据缺失，
是审计结论**；验收不得以「没有截图」判为未交付。

### 排期结论不写死在纸上：互斥是运行时的锁（2026-07-20 立，源 CONVERGE-DOC-1 第二轮验收）

把「依赖顺序」与「资源互斥」压进同一个「波次」列，结果是表**自己违反了自己声明的硬约束**——两行都标着触碰同一串行文件却排在同一波，另有两张未声明的触碰者混在别处。

根因不是数错：**波次号是一个依赖未来改动面的结论，而改动面在开工前不可精确知**，把结论写死在纸上必然漂。拆成两个各自可判定的量才成立——「依赖层」（稳定、开工前可知）与「互斥标记」（逐票显式声明、不留空）；派单时取依赖已满足的票，若其互斥标记为真则确认无第二张在途。

**互斥是运行时的锁，不是纸上的分组。** 同理适用于任何「把调度结论固化进文档」的场合。

### 不为刚证明不该存在的结构立门（2026-07-20 立，源 CONVERGE-DOC-1 第二轮验收）

验收建议「同波次触碰者 ≤ 1」立机器门。但同一轮已判定波次模型本身不成立——为一个刚被废除的结构加锁，是把复杂度花在错的地方，且会让废除动作变难（门会拦着）。

判据：**加门前先问「这个结构是否应当存在」**。若答案是否，先删结构；门只加在留下来的那部分上。此例中留下来的是「每票显式声明互斥标记」——它是关于**单票**的事实，实现会话开工打开文件即知真假；而全局排期结论才是会无声腐坏的那种。

### 文档引码用符号锚，不用行号（2026-07-20 立，源 CONVERGE-DOC-1 自伤实证）

同一枚提交在文件上方插入 8 行注释，就把下方 `App.tsx:567` 推到了 `:575`——**该提交既造成漂移、又把漂移前的行号写进新文档**，而它本身正是为消除幽灵引用而设的批次。

故：文档引用代码位置一律用**符号名**（函数、常量、选择器、testid），不用行号。符号名随重构改名时会被 grep 抓到，行号则无声失效。行号只可出现在**一次性的证据记录**里（验收报告、craft-evidence），因为那些件绑定的是当时的树，不随后续提交演进。

### 锁的输入必须是无条件事实（2026-07-20 立，源 CONVERGE-DOC-1 第二次复验）

派单互斥锁读的是每票的「是否触碰串行文件」。有一票把该格填成**条件式**——「否（若必须触碰则排队列尾）」——锁随即在这一票上失效：它既不是「是」也不是「否」，调度时无从判定。

而那票的范围第①条要求改一个函数的返回形状，其生产消费点之一就在该串行文件里——**「是」是唯一诚实的答案**。条件式措辞看似严谨（把例外也写上了），实际是把判断推给了下游读者，而下游是一台不会读条件的锁。

通则：**任何被机器消费的声明，其取值必须是无条件的事实**。约束、例外、缓解措施写进相邻文字，但那一格只填事实。


### 被测物不得给自己出考卷（2026-07-20 立，源 FILE-PREVIEW-1 验收 A；架构记为该形状第三次）

一条自称「闭集完整性」的断言，其期望集合是从**被测的那张表**反向派生的：

```
const reasons = Object.keys(MATERIAL_BLOCK_REASON_COPY);   // 期望来自被测物
expect(每个 reason 都有去向)                                 // 于是永远成立
```

后果是它**永远看不见「新增」**——独立验收三探针实证：往闭集里加一项一律绿，连把判别器掏空到只认一项时它仍绿。而 SPEC、commit、注释三处都写着「新增时先红」。

**与档位账「自洽不验真」同构**：那本账只比对 `target` 字符串与硬编码期望是否相等，不验路径存在、不解析片段——同样是拿被测物的一部分去校验它自己。

判据：**凡断言「某集合完整/某映射无遗漏」，期望侧必须是与被测物独立的字面量**（冻结集合、外部 manifest、硬编码清单皆可），不得由被测物派生。派生出来的期望只能证明「它和自己一致」，而自洽从来不等于真。

### 一次绿不构成对 flaky 的反驳（2026-07-20 立，源 FILE-PREVIEW-1 e2e 数字之争）

实现会话跑一轮全绿即宣称「326/326」；独立验收在其环境两轮均 325/326，并以对照实验把差额归因为既有负载相关抖动（父提交同跑失败**更多**）。回炉后本机再跑，第一轮完整绿——**这不构成反驳**。

不对称在于证据结构：**红是存在性证据（见过一次即成立），绿是全称主张（须重复才站得住）**。故一次绿对上两轮红 + 对照实验，弱的一方是绿。

推论两条：①宣称通过率须报**完整轮次数**，单轮结果不得写成通过宣称；②被会话时限或其他外因**截断的运行不是结果**，不计入通过率，如实登记为截断。

### 否定性结论须换第二工具交叉（2026-07-20 立，源 FILE-PREVIEW-1 回炉实录）

`grep 'ResolveResult' material-store.ts` 返回空，几乎据此认定该类型不存在、要另起一份定义；改用 `node` 读同一文件，它在第 69 行——工具静默失效（编码/环境），而 grep 无输出与「确实没有」在终端上**长得一模一样**。

判据：**「查无此物」是否定性结论，不得由单一工具的空输出得出**。换一种读法交叉（另一工具、另一入口、或找一个已知存在的锚点验证该工具此刻可用）后再下结论。同理适用于「grep 不到消费者故可删」「未找到证据故不存在」这类判断——本仓验收体例里「未找到证据」正是为此保留的措辞，它说的是我没找到，不是它不存在。

### 类型在场 ≠ 运行时在场：`.default()` 是绕过 parse 就消失的字段（2026-07-25 立，源 CONTRACT-REVIEW-SAFETY-1 WIP 白屏实测）

`RiskListSchema` 写着 `outOfCoverage: z.array(...).default([])`，故 zod 的**输出类型**里该字段是必填，TypeScript 全程认定它在场。但 `packages/demo-data/data/artifacts/risk-list.json` 的顶层键只有 `{caseId, risks}`，它被 `demo/recordings.ts` 直接 `import` 成 JSON 当 `RiskList` 用，**从不经 `RiskListSchema.parse()`**——`.default([])` 因此永远没机会执行。一处无保护的 `props.riskList.outOfCoverage.length` 就抛 `TypeError`，React 树整棵卸载，demo 工作台白屏，所有调 `openWorkbench()` 的 e2e 全线 30s 超时。

这一缺陷穿过了 `tsc -b`（类型上字段在场）与 64 文件 / 499 条 desktop 单测（无一条用 demo fixture 渲染该面板），**只有真跑起来的 e2e 抓得到**。

判据三条：

- **`.default()` / `.catch()` / `.optional()` 后带兜底的字段，其「在场」只对 parse 过的值成立。** 直接 import 的 JSON fixture、手写字面量、`as T` 断言出来的对象，全是绕过 parse 的运行时空洞；对这类字段的访问必须带保护，或让该值真的走一次 parse。
- **单点修补不够，须以族为单位铺满**（承「开口子就得同时封口子」）。本仓现存同族三处：`risk-list.outOfCoverage`、`party-graph.aliases`、`timeline.partyIds`，而五份 demo artifact JSON 无一经 parse。修任一处时须同批处置全族，并留下机器形态——「每份 demo artifact JSON 含其 schema 全部 `.default()` 键」是可静态断言的。
- **「build 绿 + 单测绿」对这一族零区分力**，不得作为该族的通过证据。承「一次绿不构成对 flaky 的反驳」的同源纪律：绿灯的说服力只及于它实际执行到的路径。

### 隔离绿对全链红零区分力；异步前置要等条件，不要赌时长（2026-07-25 立，源 CONTRACT-REVIEW-SAFETY-1 收口）

全链一轮 328 绿 / 9 红里，有一条新写的 e2e 红在「逐条填满后最终提交按钮应启用」；单独跑该谱四条全绿。**隔离下的绿不构成对全链红的反驳**——这是「一次绿不构成对 flaky 的反驳」的对称面：换掉条件重跑一次，并不能撤销已经出现过的那次红。

归因不靠重跑，靠**在复现条件下做对照**。此处用一枚临时探针把 demo 回放的逐事件延时从 180ms 放大到 3000ms，人为放大真实并发下的同一时序，得到两个方向的读数：

- 门禁投影到达**前**：处置照常记下，最终按钮 `disabled`；
- 门禁投影到达**后**：处置格仍是「已确认」，按钮转 `enabled`。

根因由此坐实为**测试对异步前置赌了时长**（`toBeEnabled()` 的 5s 默认上限），不是产品缺陷：按钮的启用判据挂在 `gate.items` 上，而 gate 由回放第 4 枚事件 `confirmation_requested` 触发拉取。

判据两条：

- **修法是把赌注换成条件等待，不是把超时调大。** 要等的是**由该前置派生的可见信号**（此处：risk-03 的「未核验」只可能由 `gate.reason='unverified'` 产生），信号在则前置必在。加超时只是把赌注下大一档，负载再涨一档照样复发。
- **对照实验必须能同时产出红与绿。** 只做「放大延时 → 红」不够，还须做「放大延时 + 等到信号 → 绿」；缺了后一半就分不清「前置迟到」与「前置到达会抹掉已记录的状态」——这两种故障的修法完全相反。

### 重连切支判例（2026-07-26，OUTPUT 轮实证）

会话重连可能把主 checkout 静默切回 `main`；若长跑门禁（dev server 在场）正在进行，文件被脚下替换会产生跨面伪红与错误计数。对策已升格纪律：实现会话一律独立 worktree 施工；长跑门禁期间该树零 git 操作；疑似污染时以 `git reflog` 定位切换时刻，作废窗口内全部验证结果重跑。

### 外提即入册判例（2026-07-26，OUTPUT 驳回轮实证）

「过手即拆」外提与任何新生产模块，产生当刻即入 SPEC 白名单并附职责一句；完工时补录已两次被独立验收抓为契约级阻断（SAFETY 轮一枚、OUTPUT 轮三枚）。

### 红的理由判例（2026-07-26，SITE-CRAFT-2 N2 实证）

改造门形态时，被退役的旧判据须转具名反向锁，不得依赖其以旁效（如裸断言化）触红——红必须报对理由，否则下一个照旧文改写的人读到错误指路。

### 闭口按族，不按验收点名的实例（2026-08-02 立，源 PI-HOST-LOOP 1R→1R2→1R3 三轮）

验收报告列出的反例是**样本**，不是待修清单。HOST-LOOP 连续两轮返修按点名实例逐条闭口，
下一位验收者每次都在同一批判据里找到未点名的同族成员：补了 `maxTurns/maxUsd/modelId`
三项上界，`caseRoot ≤4096`／`apiKey ≤8192` 仍后置于 journal/spawn；冻了 manifest 的
`routeId/nodeVersion/useCodeCache/targets`，`bundle.bytes/sha256` 仍取自被判物自报，
正中「被测物不得给自己出考卷」。

判据：收到反例先问**它属于哪条判据、该判据还辖哪些字段/对象**，把闭集列全再动手；闭口
的完成态是「闭集被穷举覆盖，且覆盖本身有机器自证（手写期望清单＋源码扫描双向核对，
新增成员不入清单即红）」，不是「报告里那几项已修」。同族推论：为某判据补门时，同批清点
它的**期望来源**是否独立于被判物——两者是同一种「自己证明自己」的病。

补正（2026-08-02，源 1R3 复验）：**扫描谓词必须与族定义同宽**。1R3 的覆盖扫描按 `MAX_*`
常量枚举，而族定义是「受验输入」——SafeToken 等函数型判据不在轴上，prompt `requestId`
同时躲过清单与扫描，撤其生产门后全套自证假绿。选扫描轴从族谓词出发（受验输入＝常量上界
门＋格式门＋非空门…），语法标记只是实现便利，不得反过来定义族。

终局形态（2026-08-02，源 1R4 复验）：**名字清单换材质仍是白名单**——常量名单（1R3）与
函数名单（1R4）两轮同败，病根都是「unknown → 跳过」。可靠形态是 fail-closed 扫描：枚举
受审面的**全部拒绝分支**，不认识的判据表达式**判红而非跳过**；排除只能是票面或清账表的
具名理由行，不得是扫描器代码里的过滤器（每加一条过滤就多一个藏身处——1R4 实现自己的
判断，升为通则）。

再订正（2026-08-02，源 1R5 复验）：上条的「fail-closed 扫描」自身也会败——「枚举全部
拒绝分支」的**种群谓词**若仍是文本模式（`return Err(` 字面量），则 fail-closed 建立在
fail-open 的种群上，turbofish 一个合法拼写即出圈。常量名→函数名→return 语句字面量三层
同败的总判据：**在富语言里用文本模式枚举语义构造结构性不可胜**。出路不是第四个更聪明的
扫描器，而是**消灭需要同步的账**：让两处必须一致的东西合并为一处真源（HOST-LOOP 1R6 的
encode-before-effect——codec 在效果前真实编码，wire 判据的前置从「验证同步」变「结构性
成立」），残余担保交给行为级普适不变量（`Err ⇒ 副作用恰零`，不需要知道门在哪）。
**同步消灭优于同步验证；验证不了的同步，先问能不能不同步。**

清理临时产物一律只删**本会话自己创建的精确路径**；禁止对共享 temp（`/tmp`、`/private/tmp`、`$TMPDIR`）做 `rm -rf <前缀>*` 通配删除。实证：某收尾命令 `rm -rf $(dirname $(mktemp -u))/courtwork-pi-*` 恰因本机 `$TMPDIR` 指向用户级 `/var/folders/...` 而未伤及 `/private/tmp` 下同前缀的**活动施工 worktree**——glob 与目标根都是变量时，损伤面由环境而非意图决定。staging/scratch 建目录时记下精确路径，删除时只用该路径；跨会话共用前缀（`courtwork-*`）不构成可删依据。

### 读修分相判例（2026-08-03 立，源 PI-HOST-LOOP 1R6 复验）

效果边界不变量（如「Err ⇒ 副作用恰零」）可以被藏在读取助手里的 durable 修复击穿：名为
`load_*` 的函数若顺手截断、补写或折叠落盘，则任何「先校验后效果」的排序担保都只对
fresh 路径成立。判据两条：其一，**载入与修复分相**——读取既有持久态的路径只允许纯读与
计划，修复以计划值返回、由调用方决定 apply 时机（校验成功后、或以修复为目的的收账路径
立即执行），不得在读取函数内直接落盘；其二，**普适探针的种群必须覆盖持久态形状**——
探针输入只枚举值域（非法值×字段）而不枚举状态域（fresh／可恢复／损坏账本），则带修复
的分支结构性照不到，142 行电池全绿与该分支从未被测同时为真。披露同理：副作用时序的
偏离披露若只写 fresh 路径，属不完整披露。

### 并行 worktree lint 歧义判据（2026-07-26，OUTPUT 清账随批实证）

全仓 lint 若未显式排除并行 worktree 目录（`.claude/worktrees/**`），他会话在途树的文件会被主树扫入，红信号无法归属。判据两条：lint 红先归树——报错路径落在 worktree 目录内的红不构成本树信号；排除须以配置显式落地并附红绿证（`c7897d8` 先例），不得依赖「恰好没并行」维持绿。


### 绕过门链与空跑循环判例（2026-08-06 立，源 GENERIC-PACK-1 自伤实证）

一枚提交带着红门进了树，两件事同时成立才做得到，缺一不可：

1. **`npx playwright test` 不是 `pnpm test:e2e`。** 后者在 playwright 之前串了三十余枚静态门
   （`assert-*.mjs`）。直接调 playwright 二进制看着「e2e 全绿 365/365」，实际整条前置门链
   一次都没跑。**跑门要跑门的名字，不要跑门里那一步。**
2. **shell 循环的空跑与全绿同形。** 本会话用 `cd apps/desktop && for s in …; do …; done` 逐枚跑门，
   而 Bash 工具的 cwd 已在该目录内，`cd` 失败 → `&&` 短路 → 循环体一次未执行 → 末尾的
   `echo DONE` 照常打印。**「没有输出红」与「没有跑」在终端上长得一模一样**（同「查无此物」
   判例的执行侧对偶）。对治：循环自身要报**跑了几枚**，不要只在有红时说话；一个恒为真的
   计数比一句 DONE 有区分力。

被这两条一起漏掉的门是 `assert-graph-theme`——它把「G6 按工作面懒加载」的判据钉在
`App.tsx` 的字面量上，而那一票正把懒载点迁去了 renderer。修法按「红的理由判例」改锚新家
并补唯一性锁，不删判据；已入树的红提交按 Git 纪律**前进式修正**，不重写历史。

### 验收落盘判例（2026-08-05 立，源 PI-LANE-UI-1 清账）

验收记录提交入树是验收交付义务的一部分，未提交即验收未完成。清账会话遇未提交的验收工作区，默认停手报架构；代为提交只在三证齐全（验收会话 PASS 报告在案、盘上内容与报告逐项一致、清账侧独立复跑全量门）时经架构追认，追认与偏差同批登记。

### 落痕先核 HEAD 判例（2026-08-05 立，源 PI-LANE-UI-1 偏离追认落痕）

主仓工作树可能正检出某票分支（共享树非私产族第三例）。任何会话落痕前先 `git branch --show-current`；架构 docs 落痕一律分树（worktree）执行，落后必核目标分支 tip 未动。已骑错分支的提交以「分支复位＋cherry-pick 到 main」纠正，不得留在票链上污染交验点。

## 依赖许可

运行时依赖许可白名单基线为 MIT／Apache-2.0（既有先例：`GENERIC-PACK-1` 拒 pandoc 于 GPL）。**BSD-3-Clause 纳入白名单（2026-07-26 裁定，源 GUI 候选八项·工作稿版本 diff 项）**：宽松许可、无 copyleft 义务，与 MIT/Apache 同级；npm `diff`（上游项目 jsdiff）因此可用，禁止误装另一个 npm `jsdiff` 包。**`Apache-2.0 WITH LLVM-exception` 于 2026-07-28 为 Bytecode Alliance capability filesystem 同系三件 `cap-std/cap-fs-ext/cap-tempfile@4.0.2` 窄项批准**：须 exact 同版本、保留完整 SPDX 表达式与 notices，不扩成任意白名单外许可自动准入。GPL／AGPL 及其派生不入依赖。白名单外许可逐案架构裁定并留痕；`site/` 素材与字体许可另按 `SITE-CRAFT-2` 票面的快照纪律。

**新功能 / UI 的 OSS 前置（2026-07-28 架构纪律）**：实现票冻结前须以现行 HEAD
逐项写入 OSS 候选结论，分类只用「直接依赖 / 借行为或源码范式 / 保留自研 / 删除当期动作」。
核查至少覆盖上游一手来源、当前维护信号、精确许可、直接/传递依赖、包体或宿主代价、现有真源与
状态机是否会被重建。旧报告、归档与 star 数只能帮助找候选；需求、现行源码或上游版本有变化时必须
重查，不能据旧结论直接开工。直接依赖只接管通用机制，项目的 schema、账本、授权、容器隔离、
fail-closed 与领域语义继续由本仓契约拥有。没有合适候选时同样留证；build/test 全绿不构成评估完成。

## Git 纪律

- 多 worktree 环境下，历史复核必须用独立 worktree；共享树禁止 checkout 历史 SHA 或 stash 他人工作。
- 禁止 `git add -A`、`git add .` 和宽通配暂存。
- 逐文件显式暂存，立即检查 `git diff --cached --name-only`，然后尽快提交。
- 混合文件用 `git add -p` / cached patch + 裸 `git commit`；只有整文件完全归本会话时才可 pathspec commit。
- 不重写共享历史。误吞他人内容时前进式修正并如实记录。
- 每枚提交必须在自身 tip 上通过它触及的门禁，不能依赖未来提交补产物。

## 验收


**固定项 · 自述与实现逐条对照**（2026-07-20 立）：注释、立门缘由、门的错误文案**都是宣称**，与代码同样受「宣称须与实测一致」约束。验收须逐条把它们与实现对照——本线已三犯：门注释称句界含闭合标签而实现是剥标签、称对冲「已被 fixture-claims 逐字锁住」而该文件零命中、称「保留偏移映射」而实现里没有映射。三次都是结论对、前提假，靠读代码才发现。
- 使用 clean worktree 和独立 dev-server 端口；`reuseExistingServer` 不得连接共享服务。
- 验证 drift/guard 时实际注入反例并观察变红，再撤除反例恢复全绿。
- 报告写入对应层 `ACCEPTANCE.md`，明确回答是否放行。
- 清账同时满足：提交是 `main` 祖先，且 SPEC/ACCEPTANCE 有留痕。
- **验收自修探例条款（2026-07-17 立，源 PILOT-LIVE-2）**：发现实现缺陷的默认动作是驳回返修。验收会话直接修实现仅限同时满足：缺陷小且定位明确、附独立红证、全量门亲跑、提交以 `fix-by-acceptance:` 标注、架构合并前逐 diff 复核。不满足任一条即退回默认动作；此路径不得成为常态。

## 文档

工单过程不再追加到中央大册。跨层决定进 ADR；层内状态进 SPEC；验收证据进 ACCEPTANCE；全局当前态只进 `docs/status/current.md`。

**档位绑定判例（2026-07-19 立，源 SKIN-R2 P0）**：视觉 selector、组件或设计条款必须在平铺账中绑定唯一激进度档位与唯一已批提案行；同一目标双档、漏档、漏提案行都视为未获授权。档位正文只认 `docs/design/principles.md`，本文件不复制三档规则。

**归档律（2026-07-19 立，源 SKIN-B2-1 判例归档位裁定）**：**跨工单判例进本文件，单批事实进该层 `SPEC.md`。** 判据是可达性——本文件在「开工」序列里被读，下一个工单必然经过；留在某一批的 SPEC 里，下一个人不会翻到。一条经验若只对本批成立，它是事实，进 SPEC；若下一批还会踩，它是判例，进这里并带出处（`（YYYY-MM-DD 立，源 <工单>）`）。

**史料例外**：`archive/` 只存历史材料，现行文档、源码与脚本不得引用（根 `CLAUDE.md`）。**例外枚举只有一份，在 [`docs/README.md`](../README.md)「文档体例」的归档条**（2026-08-05 收编：ADR 来源段／就绪图工单行／`engineering/` 工程报告／各层 `ACCEPTANCE.md`，一律行内代码写路径）。本文件此前单列的「评审引用」例外已并入该枚举第四类，不在此另存一份；其附加条件仍然成立——三方对照评审逐项引原型帧位时，必须标明被引件为归档史料、注明其空跑维度（若有），且结论不得依赖归档件的现行有效性。
