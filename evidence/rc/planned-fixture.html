Planned runtime capabilities, drawn as controls

WO-RC fixture, 2026-09-08. Every control below was designed for the runtime module and then removed from the product, because the host has no adapter behind it. This page is the only place the drawn version exists. It is a static file: it is not linked from the product, and the server's STATIC allowlist does not serve it.

Nothing on this page works. The switches, buttons and fields are inert markup. Do not treat a control here as evidence that the capability exists — the shipped surface for all of it is the text list at the bottom of this page.

G-1 · MCP OAuth

Docs server
State: configured · needs authentication. The server answered 401 and asked for an authorization code.

Needs POST /mcp/:id/authorize, a callback the host can receive, authentication: 'oauth' in the descriptor, and a health value that means “waiting for a person”. Today authentication is fixed at 'unauthenticated-only'.

G-2 · MCP stdio transport

Transport
How the host reaches this server.
Command
Started as a child process of the host and stopped with it.
Process
Running · pid 40122 · started 12 min ago.

Needs McpSource.transport: 'stdio' and a supervised process lifecycle, so that running means a live child process. architecture.md currently rejects it outright.

G-3 · Third-party plugin isolation

Evidence memo
in-process · host-trusted
Trusted built-in code. Untrusting it would unload its renderer.
Install a plugin
Signature and sandbox are checked before the first load.

Needs an installer, a signature check and an execution sandbox. Today trust is always host-trusted and isolation always in-process; there is no third-party code path at all.

G-8 · Token usage beside the character sizes

The product says characters, not tokens and shows no estimate at all. A wrong token number is worse than no token number.
