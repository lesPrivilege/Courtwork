## One remaining bounded blocker

`inspectPreparation` canonicalizes and checks `manifest.sourcePath` (`app/scripts/prepare-coding-dogfood.mjs:184-188`) but does not perform the equivalent containment check for `manifest.dataDir` before `entries()` or `launchContract()` (`:190-203`). `validateManifest` checks `path.resolve(manifest.dataDir)` against the lexical `root/runtime-data` path (`:160-169`), which does not detect that the on-disk `runtime-data` directory has been replaced by a symlink.

The exact probe replaced only the synthetic instance's `runtime-data` directory with a symlink to a separate temporary sentinel containing `synthetic-marker`. `inspectPreparation(root)` returned successfully with:

```json
{
  "accepted": true,
  "hostDataDirUsed": true,
  "lexicalDataDir": ".../instance/runtime-data",
  "realDataDir": ".../cw-dogfood-round2-sentinel-...",
  "sourceHeadMatchesManifest": true
}
```

The returned `launch.args[2]` remained the lexical `.../instance/runtime-data`, but its real target was the external sentinel. No Host was launched. This means a later operator following the derived command would give the Host a data path outside the prepared instance, and `--reuse` has already read the external directory to report `hostDataDirUsed`.

Minimal R3 follow-up: in `inspectPreparation`, `realpath(manifest.dataDir)` and reject unless it remains within the canonical instance root before calling `entries()` or deriving `launch`. Add one regression test that swaps `root/runtime-data` for an external symlink and asserts refusal with no external read. Keep the existing source check and all R1/R2 dispositions unchanged.
