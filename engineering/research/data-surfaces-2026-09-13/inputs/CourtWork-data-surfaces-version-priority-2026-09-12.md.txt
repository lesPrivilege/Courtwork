# 01 · 使用优先的数据治理与可视化裁定稿

2026-09-12。状态：供本地采纳的设计与编排稿；未改仓库，未创建 PR，未实现或验收产品。

## 1. 裁定摘要

CourtWork 不先建设一张覆盖全库的图谱，也不建设第二个资源权威中心。采用“现有 owner + 有界查询投影 + 明确的变更命令”：资料默认列表，工作默认纲要，阅读占主列，版本进入对比，关系按具体问题展开。人和 Agent 消费相同的版本与权限规则，但使用不同的呈现和披露预算。

必须独立建模：对象身份、内容版本、表示版本、工作效力、访问授权、保留要求、检索优先级、人的关注优先级及模型/校验器评估。它们可以组合展示，不合成一个总分或生命周期。

## 2. 证据与原稿处置

本轮仓库只读固定在 `1ac28980c4877f4a86adf586aeb1b66980e23504`。PAPER.md 的工程采用基线为 SE 9.6 / `d78fd312955c1f594e59cbdcbb0d3074ac355940`；本轮读取了该 Canonical 的开篇及工作承诺路径，不冒称逐条重审整篇论文。[R1][R2][R3]

用户消息内的“成熟系统设计谱系”和附件中的资源治理 explore 是研究输入。其“90 个/181 个结果”等历史统计不计入本轮检索成果。外部系统事实与本轮设计建议分别记录，下面的版本/权重/页面字段是 CW 实施建议，不是声称论文已规定这些 DTO。

附件建议统一 Resource Fabric、四级 Promotion 和泛化 Artifact；已入库 RD-007 则采用既有 owner 上的有界治理，并将用途、保留、披露与正式接受分开。采用后者作为当前工程边界，保留附件原字节，不静默改写研究原件。[U1][R4]

| 原研究中的机制 | 本轮处置 | 施工含义 |
|---|---|---|
| 稳定身份、版本、Blob、Representation、Binding | 采用边界，沿现 owner 实施 | 不把所有内容统称 Core Artifact，不复制 accepted 真源 |
| 全部资源进入统一 Fabric | 采用统一查询体验，不另建统一写权中心 | 跨 owner 组合 reader；缺失与跨库中间态合法 |
| Scratch / Working / Shared / Record 四态晋升 | 仅保留为用途讨论 | retention、disclosure、正式决定分别维护；不画一根晋升进度条 |
| 任意 Annotation 表达 Expert approval | 不采用为权威模型 | 注释可以引用正式决定，不能自己变成批准 |
| 索引、OCR、摘要都可随时删除重建 | 有条件采用 | 纯可重建投影可重建；人工校正、唯一观察和决定不可当缓存删除 |
| 同内容只存一次、上传即公共资源 | 不作为首片承诺 | 同字节不等于同业务对象；权限域与保留义务不随物理去重合并 |
| 图谱/Lineage 放深层 | 采用并细化 | 默认不加载全库；仅查询当前任务的关系切片 |
| 对外协议直接兼容 | 改为逐接缝验证 | 数据模型借鉴不等于已实现 A2A/MCP/PROV 合规 |

## 3. 成熟系统 → CW 原语映射

“采用”表示采用机制，不表示安装整个系统；“何时实施”以实际用户任务和原 owner 合同为准。

| 谱系/官方先例 | 经核验的机制 | CW 可借鉴原语 | 不照搬的负担 | 可消费接口或边界 | 实施触发 |
|---|---|---|---|---|---|
| Zotero [W1] | 一个条目可属于多个集合；标签与集合并存；移出集合不删除条目 | 稳定 Resource + relation + Saved View | 所有用户必须先管理复杂目录或书目字段 | 先借对象/集合语义；外部接入另 pin API | 一份材料需供两个获准工作使用 |
| Tropy [W2] | 结构化模板与自由标签分开；模板字段关联词表 | Expert-specific metadata facet，保留自由组织 | 用户先填完表才能阅读；任意 key 无限扩张 | 模板/词表映射；不预承诺完整格式兼容 | 同一专业任务反复需要相同字段 |
| DataHub [W3] | Entity / Aspect / Relationship；Aspect 可独立更新 | typed facets、明确字段 owner、命名关系 | 大元数据平台、万能 EAV、大量治理表单 | 对象与 facet 合同；不整体嵌入 | 同一对象出现不同生命周期的描述/政策/观测 |
| dbt [W4] | Definition 与 Applied 分开；失败尝试不抹掉上次成功 materialization | declared / attempted / observed / accepted 分层 | 把 Applied 等同业务接受；所有工作画固定 DAG | 定义快照与执行回执分开 | UI 要解释“计划已改、实际尚未改” |
| Dagster [W5] | Observation 记录元信息，不表示 asset 已修改 | Observation → Candidate；变化检查结果 | 自动重跑或强制替换一切下游结果 | 观察、版本与依赖关系 | 来源更新后哪些工作需重新检查 |
| lakeFS [W6] | 不可变 commit、branch/ref、版本比较与 revert | immutable revision + adopted ref + 新决定式恢复 | 全量 Git 操作心智、数据湖基础设施、默认给所有资料分支 | 先借版本原则；非直接存储迁移 | 用户确需比较并行候选或可重现基线 |
| Flowable CMMN [W7] | 条件、可用任务、手动激活与阶段/里程碑 | 工作纲要中的“可做/必须做/需决定” | 把 CMMN 状态逐项硬映射到 CW；引入完整引擎 | Work Contract 与实际可用动作 | 真实知识工作不能预排为固定步骤 |
| Obsidian local graph [W8] | 当前对象的局部图与深度控制 | 当前来源的引用与影响邻域 | 全库常驻网络图、度数代表真理或重要性 | 只读关系投影 | 列表无法解释多跳影响关系 |
| W3C COGA / APG [W9–W12] | 简化内容、控制打扰、可操作折叠与焦点语义 | 阅读主列、按需详情、稳定返回、非打断更新 | 用少信息掩盖真实失败，或强套固定控件数量 | 交互合同与验收 | 所有资源/工作页面 |
| Cytoscape.js / elkjs [W13–W14] | JS 图展示/分析与独立布局；ELK 可用于分层布局 | 可替换 renderer/layout adapter | 图数据库、React 改造、默认自由绘图器 | nodes/edges 只读投影；布局本地状态 | 局部图任务已验证，再 pin 版本/许可/预算 |

Facet 独立演化不表示业务不变量可拆散提交。涉及同一决定的状态、事件与 active ref，仍由原 owner 的事务同时维护。跨 owner 不能用视觉上的一张卡伪造原子性。[R4]

## 4. 选择标准

优先级：用户能完成任务 → 效力/权限/版本正确 → 能恢复并回源 → 成本与可维护性 → 可视化丰富程度。没有实测，不给候选库虚构数值排名。

局部图的必要性必须由“更快、更准确回答影响/来源问题”证明；图画得漂亮、节点很多，不构成采用证据。稳定的关系查询合同可先成立，renderer 可以后换。

本稿不要求新建微服务、第二份主数据库、向量平台、全能 workflow builder；也不要求每一个上传必须先变成 Matter。

# 02 · 页面职责、读模型与变更边界

## 1. 先回答五个用户问题

| 用户问题 | 默认承载面 | 后端最小事实 | 真实动作 |
|---|---|---|---|
| 我有哪些材料、在哪里继续？ | scoped 资料列表；工作纲要 | 获准对象、关系、版本、未闭合工作 | 打开/过滤；不隐式写入 |
| 这项判断依据什么？ | 阅读主列 + 引用按需详情 | exact source/revision/representation/range、关系依据 | 展开/续读；无批准 |
| 新旧版本改变了什么？ | 版本时间线 + 精确对比 | 两份确切版本及表示，变更者/时间/原因、当前采用关系 | 查看；采用/撤回另走命令 |
| 这次变化影响了什么？ | 影响清单，必要时局部图 | 类型化边、源/目标版本、覆盖与 freshness | 跳转/检查；不自动重跑或失效 |
| 当前要我判断什么？ | Work 纲要 / Attention 投影 | 义务、决定、请求、检查回执、可行动作 | 由原 owner 接受/拒绝/补证/关闭 |

资料列表与工作纲要不是两套资料库。它们以同一稳定 ref 读取原对象；Chat、Matter、Attention 页面可复用 renderer，而保留 controller、身份、授权与会话合同。

## 2. 两种纲要，不能偷偷合并

**材料纲要**是当前文档/表示中的目录、标题与原文锚点，回答“去哪里读”。它绑定表示版本，可作为可重建投影。

**工作纲要**是当前任务的事项、证据、候选、决定与未完义务，回答“工作到哪里”。每个条目要能回到原 owner，不由模型写的一段摘要替代。模型可以建议分组/标题/摘要；这些建议不自行创建义务或有效结论。

可使用“资料、进行中、待判断、已采用”等任务分组，但仅在有相应事实时展示。它们是视图分组，不冻结为全系统四态；没有待判断时不制造红色零计数。用户手工整理的顺序/纲要是独立的视图资产，不改变正式状态。

## 3. 四种图只选必要的一种

| 图的语义 | 边代表什么 | 本轮姿态 |
|---|---|---|
| 内容关系 | 引用、派生、支持、反对、版本替代等有来源的关系 | 首个局部图候选 |
| 处理 lineage | 原件经某次解析/抽取得到某个结果 | 按需检查与诊断，不占主工作面 |
| 执行编排 | 工具/任务的依赖、触发与运行控制 | 独立设计；不由内容边自动生成 |
| 概念联想 | 主题相似、模型建议关联 | 探索性投影，明确建议，不等同证据 |

首次图只读，围绕选定对象显示一种问题下的有限邻域。初始可试一跳，是否展开下一跳由用户决定；节点/边上限由性能与任务实测确定，不写成认知定律。先提供“上游来源/下游使用处”关系清单，复杂多跳时再展开图。

同一对象不同版本必须可区分；边有方向、类型、记录依据与有效范围。不能根据文件同名、同一 Run 同时出现或文本相似就生成正式 used/derived 边。推断关联与已记录关联分开。图中“影响候选”不代表目标结论已经失效。

节点位置、缩放、折叠只属视图；拖线不授权、不创建正式依赖、不发起运行。将来支持关系编辑时，使用明确类型、精确版本、预览影响与原 owner 命令；不能直接保存画布 JSON 为领域真源。

## 4. 后端组合方式

既有 Source/Intake、Runtime、Core、资源关系与索引 owner 保持。增加的只是面向任务的 query/projection 责任：

1. Host 绑定可信 principal、目标通道与请求 scope；模型/前端传来的 scope 只是请求，不是授权。
2. 各 owner 的获准 reader 返回对象、版本、关系与合法缺失；先限制可披露集合再生成对用户可见的搜索/邻域结果。
3. 查询组合器在有界预算内形成列表/纲要/详情/版本/邻域；部分失败明确报告，不补造所有权与状态。
4. Renderer 只格式化、选择、展开与导航。语义操作提交原 owner 命令，再消费持久回执。

语义层需要图形关系不意味着底层必须换图数据库。首版沿现 owner 的记录与必要索引读取；缺少真实边的历史返回 unknown，不从当前数据重建成历史事实。

以下是字段族草案，不是新增 HTTP API 或已冻结 DTO：

| 字段族 | 责任 |
|---|---|
| objectRef | owner / kind / stableId / revision；来源能力来自服务端 |
| representationRef | 精确阅读表示、转换版本及坐标规则 |
| viewSnapshot | 查询批次、各 owner 版本/读时点、索引 generation；不伪装分布式原子快照 |
| coverage | complete/partial/unavailable、预算与缺件原因；不可暴露隐藏对象计数 |
| relationships | 类型、端点版本、出处/回执、是否推断、适用范围 |
| availableActions | 来自真实合同与当前已知状态；执行时再次授权与版本校验 |
| continuation | 绑定身份/查询/scope/版本/generation 的有界游标；旧游标不得绕过撤权 |

## 5. 命令与 UI 状态分开

打开、比较、切视图、移动画布和本地临时选择不改变正式状态。收藏/自定义顺序若需跨设备保留，则由明确的用户偏好/集合 owner 保存；它仍不等于 grant 或 Core 决定。

保留原件、关联 Matter、修改描述、调整工作优先级、提出候选、采用、撤回、恢复，均有明确 command owner。请求按实际合同带 commandId、作用域、所依赖版本和目标对象；重试沿回执对账。字段级小修改可以独立 CAS，影响同一工作决定的多字段不能拆成分别成功的保存按钮。

跨 owner 的“保留成功、关联失败”显示为已保留但未关联，可重试或对账。不能用一个乐观 UI 的勾号把它写成正式接受。页面拿到的动作可用性不是永久授权；预览以后发生撤权或版本变化，提交应返回精确冲突。

## 6. 舒朗与注意力合同

**一个当前任务，一个主要阅读区域。** 左侧导航/纲要可退后；资料清单选择后进入主阅读，详情按需展开。无需同时常驻等宽导航、列表、正文、Inspector、图谱与 composer。工作中未在交谈时，composer 不必抢占阅读空间。

**少显示工程元数据，不少显示决定依据。** 默认显示自然标题、来源和当前有意义的状态。hash、grant ID、完整 trace、索引批次和原始权重理由进详情；阻断、失效、权限拒绝和未知效果留在实际动作处。

**舒朗不靠降低可读性。** 沿现 typography、间距、对比度、控件高度与主题 token；不新增一套“治理灰”、风险红或极细小字。不用更多卡片和 chip 把每个字段都视觉实体化。窄屏转单列阅读和可返回详情；不把宽屏图缩成不可读缩略图。

**更新不抢走阅读位置。** 用户阅读期间不自动切版本、重排列表、移动图节点或展开 Inspector。非关键更新合并为可检查提示，用户选择刷新；即将进行的决定已失效时立即显示并拒绝旧动作，不能为安静而让旧授权继续有效。

**返回能继续。** 关闭详情或图谱返回原引用、合理焦点与滚动锚点，保留展开状态和草稿；同来源不同版本、快速切 scope 的晚到结果不得串用。

**Agent 活动保持在次级层。** 不每个工具调用 toast；处理进度消费真实任务事实，不用运行事件数冒充进度。需要人的请求由同一持久项在原位置/Attention 投影，不创建互不相认的第二任务。

**图不是唯一通路。** 关系清单可完成相同的核心读取与跳转；键盘、触屏、缩放与 reduced-motion 路径单独测试。折叠用现有原生 controls/APG 对应行为；不能让重要信息只有 hover 才能取得。

W3C 的认知可访问性文档支持减少无关内容、可控打扰和恢复线索；本合同是其在 CW 的具体设计应用，不据此宣称通过 WCAG 等级验收。[W9–W12]

# 03 · SE 下的版本、权重与披露策略

## 1. 版本不是一条全对象递增整数

| 版本轴 | 何时变化 | 不应因此改变 |
|---|---|---|
| 来源内容 revision | 原文/附件产生有意义的新版本 | 旧引用、旧决定、已执行 Run |
| 描述/组织 facet revision | 标题、标签、集合关系等被修改 | 原内容 bytes 与专业接受 |
| Representation revision | 解析器/配置/规范化或人工校正改变 | 不能伪称原文修改；人工校正另保留 |
| 工作状态与决定 revision | 原 owner 接受/撤回/替代合法变化 | 不等于最新文件创建时间 |
| Schema / Work Contract / Expert revision | 解释、验证或能力合同变化 | 旧结果不自动按新规则判无效或迁移 |
| Policy / priority / compiler revision | 授权、任务排序、选择与编译策略变化 | 已执行 Run 的实际输入与决定不重写 |
| Index / query generation | 重建、增量索引或查询快照变化 | 原件、注释和正式状态不变 |

这些是逻辑轴，不要求为每轴新增数据库。优先使用已存在字段，缺消费者的不建；跨 owner 的版本组合以清晰的版本向量与时点说明，不能声称自动获得全局一致快照。

## 2. 面向人的版本表述

初始界面只需要明确三种事实：目前已保留的最新版本、本工作当前采用的版本、本次查看的版本。源对象未进入正式工作时，只显示保留/查看，不编造“已采用”。

示例：『正在查看 r3；本工作仍采用 r2；r3 的适用性待检查。』这是三个不同指针，不是一个 currentVersion 字段的三种别名。当前查询可解析用户请求的“最新”，但入账、引用或正式决定必须绑定那次解析出的精确 revision。

版本历史说明谁在何时改变了什么，以及记录到的原因。内容变化与描述/表示/采用关系变化分开列；不要把 OCR 升级写成合同内容变化。变更摘要可模型辅助，但标注为派生说明，正文对比可回源。首片文本块/行对比，富格式先精确版本阅读，不假称已有版面级 diff。

发现新版本先产生变化与影响候选，不自动失效所有历史结果。是否需要更新，取决于具体工作合同、依赖字段与决定范围。处理器更新使某个阅读锚点不能可靠映射时，标为 unresolved/stale，不悄悄迁移标注。

## 3. 恢复、分支与历史解释

“恢复采用旧版”是今天形成的一条新命令/决定，可在允许时重新引用旧 bytes；不是抹掉中间事件，也不能撤销已经发生的外部效果。先核当前权限、旧资料可读性、义务与兼容性，再说明影响范围。

内容 draft/候选有真实并行比较需求时，才增加分支/候选集；不会让普通上传都先经历 Git 的 checkout/merge。冲突同样是可判断的对象，不由 last-wins 或模型偏好自动合并。

被记录的时间与业务适用时间分开。有可信生效/截止事实才填适用区间，未知不以导入时间替代；首片可只做到明确区分，不强制引入完整双时态平台。

Schema/Expert 升级保留旧版本解释与必要迁移说明。旧快照读不懂时明确 unsupported，不按新 schema 猜出旧结果；冻结版本不是永不修安全/兼容问题。

## 4. “权重”必须拆成独立轴

本节是实现建议，不声称 SE 有一个通用数值权重字段。论文的治理与最小充分投影要求支持这些区分，但数值口径、衰减公式、阈值须由真实任务验证。[R2]

| 轴 | 可以影响 | 不能替代 | 首片 UI |
|---|---|---|---|
| 正式效力/Authority | 哪个决定有效、哪些动作合法 | 不能变成高低分 | 显示已采用/候选/已撤回等实际状态；改变走决定 |
| 依据质量 | 来源层级、检查方法、覆盖/冲突 | 不是概率真理，也不赋予批准权 | “依据与检查”，展开方法/出处 |
| 模型置信或 evaluator 结果 | 本次候选检查与升级建议 | 不与其他模型分数直接可比，不自动接受 | 有方法/版本/任务范围才展示；未知保持未知 |
| 人的工作优先级 | 同一获准工作队列中的处理顺序 | 不改变证据、权限或期限 | 按范围设“优先处理/常规”等离散意图；理由可追溯 |
| 本次检索/Context 优先级 | 当前合法候选中的排序与预算分配 | 不删除必须披露的义务/冲突，不扩大来源范围 | “本次优先参考”“本次不作为参考”“恢复自动”；不展示伪精确总分 |
| 视觉强调/个人收藏 | 用户导航与偏好 | 不暗改检索算法、正式状态或共享优先级 | 关注/收藏与任务优先级分别命名 |

同一个“置顶”不能兼任个人收藏、团队优先级和 context 强制加入。初版先让一次操作只改变一个有 owner 的字段。用户选择“本次不作为参考”也不等于停用数据源或全局删除；若与当前任务的必要输入冲突，预览说明并要求调整任务或恢复必要输入，不能悄悄省略。

## 5. 硬约束先于软排序

建议的选择过程：

```text
可信身份/授权/目的/精确版本校验
  → 区分当前适用信息与有理由读取的历史/已撤回信息
  → 确保本任务必需的决定、限制、未完义务、冲突提示可见
  → 在剩余合法候选中按任务相关性、来源依据与用户偏好排序
  → 按预算编译，记录选择、遗漏、范围与原因
  → 实际披露仍由目标通道的回执确认
```

历史材料不是一概禁读，但不得冒充当前有效规则。高检索分不能越权，低检索分不能掩掉正式限制。必须项超出预算时返回不充分/需要缩小任务，不输出“完整上下文已准备”。

不预定全局乘法公式。不把新鲜程度等同正确性，不让所有资料按时间自动降权；某类稳定制度和某类短期执行记录需要不同的适用/更新规则。未知不填 0 或 0.5。

排序策略与 overrides 有 scope、作者/来源、修订和生效规则。默认只影响下一次准备；正在执行的 Run 不被无声热改。Inspector 可解释『因当前工作引用而纳入』『因版本变化需复核』『因本次用户选择提前』，不伪造模型内部 attention 或实际使用率。

## 6. 与模型权重及工具 hint 的边界

这里管理的是工作语义与 context 选择，不是神经网络权重。prompt 次序、重复和 tool hint 不等于确定可控的模型 attention；效果须以任务实验检验。

Provider/MCP 返回的优先级、read-only 或置信提示是输入声明，不能决定 Host grant、工作效力或 GC。自研 compiler 和 Provider profile 可以分别演进，不能通过同一个无定义“weight”滑块控制全部层。

## 7. 最小综合例子（合成）

来源 r1 已被某研究备忘录采用；来源 r2 新增了一个范围限定。Spark 提出差异候选，并保留引用与缺口。用户把 r2 设为“本次优先参考”。

预期：下一次编译优先披露 r2，同时仍说明备忘录当前依据 r1、哪些结论可能受影响，以及尚未作出正式替换。用户读过差异或 Spark 校验成功，不改变采用指针。Attention 仅提示有明确义务或版本适用问题的事项，不将所有新资料逐条打断用户。

此时撤销 r2 的读取权：新的 search/read/context 编译不得再给出 r2 正文；过去合法披露事实仍保留，不承诺从 Provider 原生历史抹除。提高 r2 的优先级不能绕过撤权。

## 2. 三个 specimen 的具体任务

### S1 · 找到并引用材料

合成集合含上传原件、一个 Run 产物、一个 Core 已接受成果、缺 bytes 条目和仅部分解析条目。用户在工作范围中找到当前采用的来源，展开一个精确片段，再回到原阅读处。另一来源使用同文件名而内容/账号不同，用来测试身份误合并。

验收：不凭同名或同 hash 合并来源权限；没有资料不编计数；详情返回保留焦点/滚动/草稿；改变集合关系不误改 retention、grant 或正式接受。

### S2 · 比较并决定

r1 已采用、r2 仅保留，表示转换器另有一次升级。用户先比较 r1/r2，再检查一条有原文锚点的变化。提交前模拟采用关系被另一操作更新。

验收：内容修改、表示升级与采用变化分开；CAS 冲突不自动覆盖；旧注释仍定位旧表示；“恢复采用 r1”形成新回执而不删中间历史。模型摘要错误时原文对比仍可纠正。

### S3 · 关注、影响与继续工作

来源更新，产生两项有依据的影响候选和一条仅模型建议的关系。用户把新来源设为本次优先参考，检查受影响工作的待判断事项，切 Session 后继续。中途撤销一项来源读权，另一必需约束在预算测试中不能被容纳。

验收：加权不授予读取，不自动接受；关系推断不伪装事实；必要约束超预算明确阻断/缩小任务；Attention 不因已阅、Spark success 或新版本出现而自动关闭；图关闭可用关系清单完成任务。

| 编号 | 故障/反例 | 必须观察到的结果 |

## 4. 人类注意力的验收

机械门：合成更新不主动改变正在阅读的 revision；非用户请求的导航/抢焦点/自动展开为零；graph 布局在静止后不持续漂移；关键错误/需审批/Stop 不藏在 hover；动作清单与原权限一致。

任务门：用固定数据记录找到正确采用版本的时间、误把候选当已接受的次数、从关系详情返回后丢失阅读位置的次数、识别新版本影响的正确性，以及需要关闭的干扰面数量。先与现列表/Inspector 比较，不编造行业通用的完成秒数或点击阈值。

graph 采用门：同任务比较关系清单与局部图。只有多跳理解更准确或路径明显更短，且不损害键盘/触屏任务，才加入正式产品；不能只看首屏观感。量化用于否定或调整设计，不将一次作者熟练操作当用户证据。

界面覆盖沿现规范：1440/1280/390、明暗、长文、空/加载/失败/部分、键盘和200%缩放；涉及动画加 reduced-motion；无障碍声明仅限实际测试。

## 5. 技术选型与维护

首片继续现原生 DOM/ES modules、reader、Markdown、controls、tokens；不为图换 React 或引入可编辑 node canvas。文本比较优先确定性字节/块/行对比，parser 的输出差异注明来源。没有需要不用新依赖。

图确有消费者后，优先核 Cytoscape.js 的 ESM renderer 与独立 layout；稳定分层布局可比较 ELK，极小固定关系也可以保留原生列表/SVG 实现。Cytoscape 核心的 MIT 与本轮 elkjs package.json 声明的 `EPL-2.0 OR GPL-3.0-or-later` 必须分别核查，不能因 adapter 为 MIT 就当所有传递包都 MIT。具体版本、包体、许可证、worker/销毁与大输入行为届时 pin，不在本轮冒称安装兼容。[W13][W14]

维护登记精简为：职责、owner、来源和锁版本、消费者、合同测试、已知限制、升级触发、回退/迁出。局部组件可以停在验证过的自足版本，但外部 API、解析安全、访问控制和宿主安全仍按必要维护处理。

实施作者与独立验收分开。只读研究、合成场景与非冲突 renderer 可以并行；共享 service/store/Core/迁移的写入与接收串行。

## 6. 本轮交付与非交付

交付：输入处置、谱系映射、页面/读模型合同、版本与多轴权重设计、原工单映射、场景及验收清单。保留用户附件原字节并产生文件 hash 清单。

未交付：生产 UI、后端 API、图数据库、新的权重策略实现、视觉 baseline、真实 Provider 验证、产品测试通过或独立接受。本轮文件校验只证明交接材料内部完整，不证明产品能力。
