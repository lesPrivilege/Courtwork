WK9 · Home 三带与工作页两态

设计画布，非产品代码。裁定输入：intake-round-2 §7（WK-32…WK-37）、§8（WK-38）、WK-11/12/13/25/29/30； 数据输入：EX-WK5；语义边界：engineering/design/work-surface-boundaries.md §4–§5； 编排与表面体例：ui-composition-standard.md、surface-hierarchy.md、icon-controls.md、ux-conventions.md §1–§4。 色彩取自 WK7 铅灰 skin（claude/wk7-color-governance 的 styles.css :root），逐字复制为本目录 tokens.css； board.css 只引用 role token，全文件无 hex。

怎么读这张画布

先看 home-a-1440 与 home-b-1440：两者的上带（三个 StatTile 与热力图 gap 行）与中带（hero 一行 + composer）逐像素相同， 唯一受控差异是下带的工作中集合——A 用 WorkCard 网格，B 用同字段的行结构，用于回答 SH-1 的"这些对象该不该成卡"。 再看 work-collapsed-1440 与 work-expanded-1440：右栏收敛态是 Run / File / Workspace 三张悬浮卡，展开态是同一 tablist 的三 kind 面板； 两态的内容字段完全相同，改变的只是可用宽高与层关系，kind 静态映射、renderer 身份与 Escape 次序（第一次还原布局、第二次关闭）均按 EX-WK5 §2 现状绘制，未在本画布内改动。 home-shell-1440 只增加 WK-30 / WK-46 (3) 的 52 px 惰性 shell 条（横贯整窗，条内无任何可读或可点内容，无 Back / Forward），其余与 home-a 相同；两张 390 板检查窄屏 reflow。 alignment-1440 是量板：给收敛态与 Home A 各加一层从画板自身 getBoundingClientRect() 读出的参考线与实测表， 用来验 WK-42 的"三栏 header 顶相等"与 gutter 关系，本身不是产品构图。

r2 的三处结构变化：(1) 顶部带 --band-top（桌面 56；桌面壳下 shell 条 52 + 带 52）由侧栏 wordmark 行、 chat header、右栏 rail header 共用，Home 的那一格只留导航开合位、其余留白但预留； (2) 右栏按 WK-41 拆成宿主的 band（"Work surface" + 展开动作）与模块卡纵列，卡片不自带外边距； (3) 展开态不再是浮在壳上的 modal，而是壳内接管两列的面，tab 条因此能落在同一带内，右端为 Return to chat—— 这一改动会影响 EX-WK5 §2 记录的两级 Escape 次序，见 clean-evaluation.md §8。 每张板都跟随 prefers-color-scheme，也接受 ?theme=dark / ?theme=light；加 ?measure=1 会在左下角打印实测带高与溢出元素。
