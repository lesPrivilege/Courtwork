## What changed

| Ruling | Change |
|---|---|
| HDR-01/OBJ-01 · rename where the chat is named | The open chat's title in the header is a button that opens the same rename dialog as the row menu. Only a chat that can be renamed gets it: not Home, Settings, Attention, the Chat page, an example chat or an Attention conversation. The row menu keeps Rename. |
| THR-05 · Edit and resend | A failed or cancelled run offers "Edit and resend": its prompt goes into an empty composer directly; if a draft is already there, the message editor opens with its warning that the draft will be replaced. Nothing is sent until the person presses Send. The latest run's button sits on the stream column under its activity line; older runs carry it in their status card. |
| CMP-16 · Compact from the context readout | The context popover shows Compact as the Host states it: enabled when the Host's catalogue says it is available, otherwise disabled with the Host's reason (for example "Available after this run ends."). It starts the Host's compaction with a fresh request identity and follows it like `/compact`; the composer and its draft are untouched. |
| SET-03, V5 · save is not select | Save and Save and ask once store the connection and its key and never change the model new runs use. A catalogue provider's endpoint and API format live in the provider configuration, so they are saved only on the provider in force, and then with its model and effort unchanged; on another provider they apply with the new action. **Use for new runs** is that separate, explicit action: it makes the form's connection and model the default for new runs in all chats, and is enabled only for a saved connection with a key (or the local one) that is not already in force. Save and ask once checks the form's own connection and model. After a save the form stays on the connection it saved. |
| SET-09 · Remove key | Removing the key of the connection in force asks once, inline, and says what follows: every next run in all chats fails until a key is saved again. Cancel removes nothing; other connections' keys are removed at once as before. |
| SET-19 · one word, one meaning | "Profile" names only the person's page. The Settings group that holds only the runtime inventory is titled Runtimes (its id stays `agents` for links); it keeps a blank glyph slot rather than the Agent profile glyph. The composer's Agent reading and the Developer profile editor say "agent profile source". |
| Deferred · specimen-only modules | **Kept as specimen code.** `agent-profiles*.mjs` and `runtime-management*.mjs` are not imported by the app but are consumed by the role-composer design specimen, two preview scripts, three test files and about 25 design records. They stay; nothing live depends on them. |

## Review dispositions

A Sonnet non-author review of the uncommitted diff found one high-severity defect.

| Finding | Disposition | Landing |
|---|---|---|
| 1 · HIGH · saving a new endpoint or format for the custom connection in force left the configuration on the old one; the Host admits a run on a custom connection only when the configuration names the connection's endpoint and format (`service.mjs`, run admission), so every next run would fail, and "Use for new runs" ignored the endpoint and stayed disabled | **Adopt**: saving the connection in force carries its endpoint and format into the configuration with its model and effort unchanged (the configuration follows the connection; the execution choice does not move); `routeInForce` compares the endpoint for custom connections too | `settings-view.mjs`; Host test with a mutation check (the test fails with the fix removed) |
| 2 · a save on another catalogue provider could say its endpoint "applies later" when none was typed | **Adopt**: only a typed endpoint for a provider not in force is deferred and said so | `settings-view.mjs` |
| 3 · Configure on the provider in force blanked its endpoint, so a key-only Save could clear a custom endpoint | **Adopt**: Configure shows the provider in force as configured (its endpoint and format) | `settings-view.mjs` |
| 4 · after Remove key focus fell to the page; the question's text was not tied to it | **Adopt**: focus goes to the key field after a removal; the consequence describes the group (`aria-describedby`) | `settings-view.mjs` |
| 5 · a failed catalogue refresh can leave Compact enabled from a stale reading | **Accept**: the Host refuses and the refusal is said in the chat's feedback line | — |
| 6 · a chat with an empty title showed "Loading chat…" as its renamable title | **Adopt**: "Untitled chat", as the rail says | `app.mjs` |
| 7 · header and resend tests pin source text; no test covered editing the in-force endpoint | **Adopt** the endpoint test (finding 1); **accept** the source pins for app.mjs wiring, which has no DOM harness; the captures show the composed behaviour | tests |
