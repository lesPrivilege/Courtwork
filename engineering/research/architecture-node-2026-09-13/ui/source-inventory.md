# Runtime UI route and control inventory

Reviewed against branch codex/architecture-node-20260913, HEAD 8f4a7f4b8358b5a8be1e45cfc194ce7512f69117, plus the shared working-tree changes to app/web/index.html and app/web/styles.css described below. This inventory combines source inspection with Luna composer's browser evidence relayed by Astra; I did not replay the live audit. Luna composer reports that the latest Files correction passed at 175% zoom: the fixed header and visible X remained available, clicking X closed the dialog, and focus returned.

The audit followed the [frontend continuity contract](../../../design/agent-interface-2026-09-10/frontend-contract.md), relevant shell, settings, work, attention, projection and usage rows in [precedent-map.md](../../../design/agent-interface-2026-09-10/precedent-map.md), and the overlay rules in [disclosure-overlay.md](../../../design/home-composition-2026-09-10/disclosure-overlay.md). The return principle is that a transient layer closes locally and returns focus to its opener or originating row; a page route exposes one clear Back action and returns to the originating workspace. A native disclosure keeps focus on its summary when toggled.

## Run outcome versus Core candidate review

The current projection keeps these facts separate:

- projectThread() reads Run states into a Run-ID keyed map and appends kind: run-status rows (thread-projection.mjs:6-14,91-133). The inspector badge uses runLabels[run.status] (inspector.mjs:7-16,58-68); Completed therefore means the Run completed. In Chat, the run-status row calls appendRunBadge() and Inspect this run (app.mjs:3083-3102). The Work pane title plus that badge can visually read as Work Completed in the supplied Chat capture (ui/03-session-chat.jpg), but the source label belongs to the Run status projection.
- Core Candidate state comes from workPacket(projection).candidates[].status, separate from run.status (surface-modules.mjs:663-708,860-878). Advertised decide/revise_candidate controls come only from legal humanActions descriptors; the inbound-NDA renderer suppresses them for read-only packets and otherwise renders only advertised actions (surface-modules.mjs:711-745; app/extensions/inbound-nda/renderer.mjs:325-335).
- The route is nested: Sources and work versions starts closed, the bound packet is fetched on disclosure open, and its collapsed summary does not expose a pending-review state (chat-sources.mjs:29-59,96-99). Only after that read does expanded content expose Open work review (chat-sources.mjs:51-59), which routes into the Workspace/preview tab (app.mjs:2628-2631). Candidate actions then depend on that packet’s descriptors.
- Home Needs a look is not this Core review inbox: its inspection candidates are failed or unknown Run outcomes (home-view.mjs:43-46,431-459). No current Home row advertises a pending Core Candidate review.

**Finding:** Run completion and Core Candidate review are separate facts and projections in source, so Completed must not be reused as evidence that a candidate was accepted or that review is complete. The supplied capture’s combined Work Completed wording may blur the object at a glance, but source inspection alone does not establish semantic conflation. The action-needed Core review is reachable, yet not discoverable from the collapsed Chat summary or Home; it requires expanding the source disclosure, waiting for its Work packet, then choosing Open work review. A pending badge cannot be inferred from Run status; it would require a live, owner-projected review cue at this outer disclosure’s lifecycle.

## Follow-up source review: Home Attention return focus

At follow-up review, branch codex/architecture-node-20260913 was at HEAD 2f0a4e4d68f5009cff7f5a141495490422ee0c90 with an uncommitted app/web/app.mjs diff. The change is limited to a nullable focus-key field, capturing the active element’s data-focus-key on Home before the asynchronous draft-save step, and resolving that key after the Attention page closes and Home is rendered again (app.mjs:116-123,5681-5693,6812-6823). The Home Attention heading link has the stable attention-workspace-link key (home-view.mjs:174-177,233-242; app.mjs:5511-5516).

The route token is checked before the captured key is stored, so an interrupted navigation cannot install a stale return key. On Back, the key is consumed and cleared once; the code finds the current matching Home-module node after render rather than retaining a possibly detached button. restoreLayerFocus() checks connection, disabled state, inert ancestry and layout, then falls back to the global Attention button (app.mjs:250-259). Entries from a non-Home view or without a saved key keep the previous global Attention fallback. This is a narrowly scoped Back-focus improvement; it does not change Attention data, actions, or review state.

The first diff had a pointer-focus edge because it sampled document.activeElement; that version is superseded by the source correction below. No behavioral claim is made for either version by this static review.

## Final source ruling: explicit Home trigger

The latest actual app/web/app.mjs diff (still uncommitted at HEAD 2f0a4e4d68f5009cff7f5a141495490422ee0c90) passes the Home heading button’s event.currentTarget as the third trigger argument. openAttentionWorkspace() reads trigger.dataset.focusKey only when state.view is Home (app.mjs:5515,5681-5689). The Home callback is attached directly to a homeButton click listener, so currentTarget is the actual Attention heading button, whose key is attention-workspace-link (home-view.mjs:174-177,241). The other caller, Attention assistant “Items,” passes no trigger and retains the global Attention fallback (app.mjs:6804). This removes the previous reliance on platform click-focus and prevents an unrelated active Home control from supplying the return key.

On Back, the route is closed, Home is rendered, the saved key is consumed, and the current equivalent node is focused; a missing/hidden node uses the global Attention fallback (app.mjs:6812-6823,250-259). The route-token guard before storing the key and the reset after use are sound. Scope remains Back-focus only.

**Final ruling:** source-level implementation is correct for the requested Home-origin return and preserves the fallback for all other entries.
