# P02 · MCP error and effect settlement

Astra implementation on the P01 candidate; Luna non-author review separately requested. No Core schema or provider/GUI/dependency change.

A received `isError` is now a reported tool failure AND an unknown effect, not evidence of no effect. The callback carries exact callId, server/tool, config hash, binding hash/revision and failure kind, without arguments. The service closes its in-memory gate first, then writes admission=false plus mcp_effect_unknown and a correlated notice in one existing store transaction. If that write fails, the in-memory gate stays closed and final run.status retries correlation metadata. If storage remains unavailable, success is not claimed; process recovery still treats unfinished runs as unknown.

Effect-unknown error identity takes precedence over incidental execution errors and survives startup or no-active-process cancellation, preserving the existing continuation refusal. No automatic MCP retry is introduced. Pre-dispatch canceled/disconnected calls produce no unknown effect receipt.

[Focused tests](p02-focused.txt): 7/7, using actual SDK HTTP and a synthetic remote file written BEFORE isError/drop/delay. Cases include business error, dropped result, receipt transaction failure, cancellation with late result, reconstructed in-flight startup recovery, orphan cancellation, and pre-dispatch refusal. Restart and continuation 409 are checked for each effect case; only one actual remote write and one permission prompt occur. Reconstructed startup state is not a SIGKILL trace. [Adjacent regression](p02-tests.txt): 27/27 before the final continuation assertions were added; final seven-case output covers those assertions.

P02b still owns bounded result/body fidelity. Revert code only if needed; never rewrite effect-unknown data to safe-to-retry. Product GUI/DeepSeek/Runtime replacement and G1–G5 remain open.

## Non-author review and crash follow-up

Luna reviewed archived `c05bd48912f7de5c5db9b5ddd61e620d7beb7afe`: focused 7/7, control-plane 16/16 and `--test-name-pattern=BG02-T3 tests/run-lineage.test.mjs` 1/1. It identified the effect-before-receipt crash window. Astra added a durable `runtime.mcp.dispatch` intent before the SDK call. Failed intent persistence makes no remote call. Startup and orphan cancellation reconcile intents lacking a successful semantic result to mcp_effect_unknown; active pending intents also force unknown settlement. The intent denotes admitted dispatch, not confirmed network transmission.

Host-generated dispatchId separates repeated native callIds and is now the scoped result locator. [Follow-up output](p02-crash-followup.txt): 23/23 P02/P02b, including an actual child-process SIGKILL after the loopback server writes a real synthetic file and before returning any result. Restart preserves the unmatched dispatch, refuses supersedes continuation with 409, and performs no second write. Earlier failures while constructing this fixture came from using a status-string predicate with the worker helper's Run-object predicate; that test setup was corrected before this evidence. The guarantee covers process interruption under the existing store persistence contract, not arbitrary storage hardware failure. A separate human-authorized new Run is not globally prohibited; the fence remains scoped to the affected Run/continuation.
