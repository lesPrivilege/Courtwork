# Source preview · supported use

CourtWork is a local source preview using a fixed Pi 0.85.1 execution integration. Follow the [first-work walkthrough](first-work.md) with synthetic NDA material to configure source binding, candidate submission, human Review and a new Chat attached to the same Matter. Local test checks setup and transport; the walkthrough requires a supported real model to author a candidate, whose actual result must be checked.

| Area | Current use |
| --- | --- |
| Chat | Select a supported model connection; retain the application's own conversation, text attachments and references locally. A normal Chat does not require a Matter. |
| Models | Configure supported DeepSeek/OpenAI connections in Settings. A configured connection or successful connection check does not establish the quality of a particular professional task. |
| Files | Read/search scoped materials and write results in the managed workspace. Retained file versions and comparisons are available through Files. |
| External repository | API-only: an authenticated client may bind one Host directory for read-only `repo_list`, `repo_read` and `repo_grep`, then create one Host-owned private Git candidate from an explicit commit. `candidate_list/read/grep`, `repo_write` and fixed-base `repo_diff` apply only to that candidate; writes never change the selected source checkout and are not merged automatically. There is no folder picker or Connect/Access UI, and no real-provider or professional-task result is established by the synthetic tests. Source reads follow ordinary relative paths in the Host filesystem namespace, including pre-existing same-device mounted descendants; symlinks and different-device descendants are refused. Candidate operations refuse mounted descendants. Neither scope promises OS-level isolation or protection from malicious mount-namespace changes. Any future Connect UI must explain the source scope before binding and identify the private candidate separately. |
| Tools and MCP | Host-admitted tools and supported Streamable HTTP MCP tools follow exposure and execution policy. A catalog entry alone does not grant execution. MCP resources/prompts are catalog-only. |
| Formal work | The fixed NDA consumer supports version-bound candidates, human decisions and accepted artifacts. Deterministic fixture/capture runs can construct candidates; the default Local test reply does not author an NDA proposal. Neither establishes real-model professional accuracy. |
| Spark | Use the independent Explore Agent to compare or check permitted, retained source versions selected for a bounded assignment. It returns version-bound findings with exact source references; assigned sources and exploration notes can be expanded on demand. A separate read-only Source maintenance view shows existing project-scoped Matter derivations. A consumption receipt does not make a formal human Review or accept a work change. |
| Attention | Inspect and act on existing work items and use the explicit Attention conversation. Project and Attention model runs share a single active-run admission. There is no independent background model monitoring your messages or external PRs. |
| Extensions | Supported trusted work extensions and declarative resources use the existing control plane. Arbitrary Pi JavaScript packages, executable lifecycle hooks, browser/desktop automation and generic subagent teams are not installation promises. |
| Commands | Use the existing GUI/API actions and native automatic compaction. Host slash dispatch, manual compaction and an agent-invoked repository test runner are not available; see [commands and compaction](commands-and-compaction.md). |

### Spark sources and limits

`spark_sources` lists metadata only, 20 entries per page. Its default catalog contains exact permitted versions from the current Session's retained Intake materials and `content-version` ArtifactHistory records from that Session's Runs. It excludes unretained workspace paths and versions over 64 KiB. The Agent receives only the exact source references selected for its assignment; it cannot browse arbitrary files. References from another Session require an explicit mount. Project membership by itself grants no source access, and both the source owner's and consuming Session's current `ws_read` policies are checked on expansion and before provider requests.

An assignment accepts at most 16 source versions of at most 64 KiB each. The Agent can use up to 8 turns, 60 seconds and 32 tool calls across an assignment, with at most 8 attempts; remaining parent-run budget may lower those limits. A finding or note is limited to 32 KiB and an assignment retains at most 32 notes. Assignments use the currently configured model connection and the existing single active-Run lane; the parent Run yields before dispatch and must be resumed explicitly. The child receives a separate Session/workspace and only exact-source and note tools. It cannot write source files or take Core actions; it has no web/network search, shell, MCP, arbitrary filesystem access, parent conversation history, shared memory or recursive/parallel delegation. Its version-bound notes are the only child-authored records.

Intake references are labelled `current-retained-version` or `historical-version`; this describes retained revisions, not whether an external original has changed. Run artifact sources are labelled `workspace-freshness-unchecked`. Source content is untrusted. Findings, notes and source-read receipts are version-bound records; reads of a finding, source or note are separate facts. The `read`/`adopt`/`reject`/`defer` consumption receipt is a machine statement only; it does not create a human Review decision, accept an Artifact or update formal Work state. Revoking access prevents later disclosure but cannot recall bytes already sent to a model.

**Source maintenance** is the existing project-scoped, read-only view of retained Matter source revisions and their derived findings/statuses. It does not create, update or regenerate derivations, and it opens a Matter only when a Work Session is already bound. If the maintenance endpoint is unavailable, the view reports that state; its optional frozen sample scenarios are synthetic, read-only and not live Matter data.

Local storage covers data retained by CourtWork. It does not manage third-party cloud chat history or provider-side caches. Sending material to a model remains a disclosure to that connection under the applicable scope and permissions.

The public product story includes future direction; installation and practical use follow this supported set. Historical screenshots and deterministic demonstrations retain their own source identities; they are not new live-provider acceptance results.
