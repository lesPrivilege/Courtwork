# Prototype 施工步骤与裁决门

这是施工计划，尚未执行 prototype。低保真与状态模拟可以早于 Runtime 选型完成；真实执行、持久恢复和正式提交仍依赖 RD-001/002。原型资产创建和执行范围在下一次 Assignment 明确，本轮仅交付文档。

## 两条并行工作线

Design 线回答人能否理解、操控和判断；Engineering 线回答状态、效果和恢复是否真实。原型暴露的接口需求返回局部 RD；不把界面可点击当作后端可靠，不把后端全绿当作体验成熟。

| 阶段 | 产物与工作 | 退出条件 | 证据边界 |
|---|---|---|---|
| D0 来源与任务 | 品牌资料分类、GUI 完成面、六条路径、代表内容 | 每条路径的用户目标与关键状态明确 | 当前处于文档准备；没有 UI 观察结论 |
| D1 实际产品取证 | 在可访问的 OpenWork/DSH 版本中截取路径与失败状态，记录窗口/版本/操作 | 哪些是实际观察、文档声明、推断清楚分开 | 无权限/无环境则记缺证据，不从 README 评判美感 |
| D2 三方向视觉探索 | 相同内容与状态的 A/B/C 视觉稿；比较信息组织、排版和注意力 | 用户选方向、要求修改或全部退回；记录理由 | 静态图只证明表示，不能给交互 PASS |
| D3 可交互状态原型 | 选定方向；使用固定 state fixtures 与延迟/失败开关演练六路径 | P0 的适用状态无死路，键盘/IME/滚动/恢复模拟可重复 | 明示模拟 provider、存储、网络与提交；不外推真实恢复 |
| D4 真实纵向切片 | 换上实际 Adapter/Core，冻结输入版本，重跑相同路径 | 运行、取消、待处理项、候选提交和重启均有实际证据 | 依赖相关 RD 通过；收集真实界面与日志 |
| D5 Craft 与维护 | 中文/长文/缩放/窄窗、可访问性、性能、动效降级；提炼 tokens/原语 | 无阻断任务缺陷；局部组件有状态与回归依据 | 保留已知限制，不把完成 prototype 写成 product-live |

D1 是未来真实界面取证，不是本轮文档研究的已完成环节。若访问受限，可继续 D2 的自主方向探索，但必须标明未对上游 UI 做观察验证。

## 原型范围控制

先桌面 Web，使用少量工作、一个长成果、几份来源、一个待处理问题、一份过期候选。每个点击要么改变可追踪状态，要么明确尚未支持；不得用成功 toast 代替真实状态设计。附件可模拟，但 ready/失败/不支持必须分开。

P1/P2 只在首次能力开放时进入状态演练，不为竞品功能完整性复制市场、多人、远程和桌面更新。P0 并不意味着首版自建所有底层能力；可消费宿主，但必须验证人在本界面完成路径。

## 裁决方法

先判硬失败：无法停止、丢草稿、误认已接受、误答其他工作、证据错版、键盘无法完成、错误没有恢复。出现硬失败则退回，不用视觉偏好总分抵扣。

再比较任务完成、错误发现、恢复理解、定位时间、阅读负担和辨识度。记录参与者、任务、顺序、内容版本、屏幕尺寸、输入方式、错误和理由；交换方案顺序，不把本人熟练度当用户普适证据。小规模探索报告观察，不给虚构统计显著性。

## 设计交接包

选定方向和状态图、必要截图/录像、semantic tokens、控件行为、键盘与焦点顺序、错误和恢复文案、所需 Core/Adapter 状态、禁止的语义捷径、组件候选和已知缺陷。交接粒度仍是局部解耦选择，不在文档阶段铺完整源码。

## 最小下一步

先用当前用户任务写 D2 的 fresh brief，再补 D1 的定向取证：确认代表工作内容和四个比较状态，准备等信息量的三方向视觉输入。历史设计只按 [参考裁取](reference-consumption.md) 提供局部机制，不把整份旧 style guide 或截图包注入为新 brief。每个巧思带“有/无”对照，不能只比较三套都加满装饰的方案。

网页/截图自动生成的 DESIGN.md 只是 Candidate：需要附来源、日期、适用界面、状态覆盖、推断项、资产许可和待验证行为。人工裁决后才编入现行 Design 契约；不另建与本系列竞争的权威 DESIGN.md。具体视觉选择由用户裁决；Prototype 不是全部 runtime 完成后的装饰步骤。
