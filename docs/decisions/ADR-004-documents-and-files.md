# ADR-004：文档生命周期与文件操作

- 状态：Accepted（2026-07-28 窄修订：agent 自有 workspace 不等于用户文件）
- 日期：2026-07-13
- 来源：`fb1a75c`、`f432287`、`b9d5c14`、`d559678`、`f98a55c`、`1ad68d2`、`dd57a23`
- 关系：ADR-022 的 pi `write` 只在本 ADR 定义的 agent 自有 workspace 例外内成立

## 决定

- 新文书定稿前以结构化草稿工作，用户显式“编译为 Word”；定稿后 docx 是权威表示，不回转 md。
- 客户来件 docx 从一开始走 docx 阅读/修订轨；上传原件永远只读。
- 工作稿与正式交付分轨：工作稿可轻量编辑，交付物必须有修订、确认和定稿仪式。
- 文档读取安全预检由 reading-view 提供，output 复用同一防线；不得出现安全强弱不一致的第二套解压入口。
- 文件能力分两级进入产品：无损动作可直接执行；移动/重命名先生成 FileOpsPlan，经用户选择与确认后执行并保留事务日志。删除、覆盖等销毁级动词不进入 agent 能力面。
- 原件、移动前后与举证留痕所称的“内容哈希”必须使用 SHA-256 或更强的密码学哈希；FNV/CRC 等校验和只能用于非举证内部用途，字段名、schema 注释与实现不得混用两种语义。

## 2026-07-28 窄修订：agent 自有 workspace

上段“删除、覆盖等销毁级动词不进入 agent 能力面”继续完整约束原件、用户工作稿、产出与其他
用户文件。ADR-022 的通用 agent 新增唯一窄例外：可在 app data 内 session-scoped、可整删的
**agent workspace** 使用 pi 原版覆盖式 `write(path, content)`。

该目录只承载 agent 过程 artifact，不是用户文件或权威文书；不准写 grant root，也不准自动晋升
为用户「工作稿」。后续晋升须经垂类“修订/晋升”契约和逐次确认。workspace 的路径边界、授权与
落账由 ADR-022 约束，不能用上游 `NodeExecutionEnv` 的裸路径能力实现。ADR-022 A2 首版再收窄为
UTF-8 `.md`；其他格式不是“write 能写但 GUI 看不到”的隐含能力。

## 后果

Word 产物只有在文件已成功写入并可验证存在后才能标记冻结。撤销通过逆向重放实现，日志本身不可由 agent 删除。

## 修订记录

- **2026-07-28**：产品决定“先用 pi 覆盖式 write 跑通，修订后置”。将原“覆盖不进入 agent
