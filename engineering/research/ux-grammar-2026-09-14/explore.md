## What the evidence supports, and where the local rule must stay local

| Draft area | Source finding | CourtWork mapping / limit |
|---|---|---|
| UX-01/02 · copy and disclosure | Shopify’s published content fundamentals advise weighing each word, using subcopy only when needed, and deleting until meaning would be lost. That repository is now archived (Sep 11, 2026), so use it as a documented example rather than a live authority. GOV.UK similarly advises starting with less and fixing an interface that needs extensive operating instructions. GitLab’s current help pattern keeps task-critical facts in context and moves optional reference to drawers/panels/docs. [Shopify archive](https://github.com/Shopify/polaris-react-archive/blob/main/polaris.shopify.com/content/content/fundamentals.mdx), [GOV.UK](https://www.gov.uk/service-manual/design/writing-for-user-interfaces), [GitLab Pajamas](https://design.gitlab.com/patterns/contextual-help/) | Strong support for the deletion pass and task-led disclosure. Much is already covered by [copy-convention §1–2 and its IA audit](../../design/copy-convention.md), plus [ui-composition-standard’s default/context/technical layers](../../design/ui-composition-standard.md#信息预算与跨面编排2026-09-13) and surface-selection table. “identify / act / state / prevent-error” is a useful CourtWork checklist, not an externally universal exhaustive taxonomy. The existing rule that permissions, errors, identity and consequences cannot become hover-only is an important qualification. |
| UX-03 · action/control semantics | Carbon’s Common Actions page gives action-specific meanings and asks designers to check scope, permanence, permissions, expected time, failure and single-vs-bulk effects. Its meanings are a vendor dialect: Carbon `Copy` means make an identical object instance. W3C’s Switch APG defines an accessible binary on/off input, its label and keyboard behavior; it does not define what product permission that input controls. [Carbon Common Actions](https://preview.carbondesignsystem.com/building-blocks/core/patterns/common-actions), [W3C Switch APG](https://www.w3.org/WAI/ARIA/apg/patterns/switch/) | Supports a maintained vocabulary and a real writable binary state. It also proves the vocabulary cannot be copied wholesale: CourtWork’s chosen `Copy` = clipboard and `Duplicate` = new object is intentionally different. The Polaris Common Actions URL supplied in the conversation redirected to a generic Shopify API index, so the claimed Polaris action mapping was not verified. Carbon mentions Apply only as the last saved checkpoint in its Reset guidance; it does not establish a universal rule that Apply is non-persistent. The local `Save / Apply` clause correctly leaves persistence to each owner contract. A switch role conveys on/off semantics, not authorization. |
| UX-04 · feedback | Primer says visible state changes can make a success announcement unnecessary, while its page-specific Delete guidance in Carbon recommends a post-delete success notification. Carbon places errors at a surface appropriate to the affected task. [Primer Loading](https://primer.style/product/ui-patterns/loading/), [Carbon Common Actions](https://preview.carbondesignsystem.com/building-blocks/core/patterns/common-actions) | Keep “usually” in the no-generic-success rule. It is a contextual default, not a ban: preserve necessary recovery information, service receipts and accessible status announcements; apply a Delete pattern’s notification only when the real outcome or recovery path warrants it. Existing Atlas already treats toast as a short result surface, not a decision surface. |
| UX-05 · wait and Agent state | Primer’s >10-second advice is to keep work from blocking other interaction by treating it as background **if possible**. Microsoft describes background execution as a foreground/background relationship, while requiring background actions to remain inspectable/control­able and Agent status to be available. [Primer Loading](https://primer.style/product/ui-patterns/loading/), [Microsoft Agent UX](https://microsoft.design/articles/ux-design-for-agents/) | This supports moving attention away from a long wait only where an actual background capability exists. It does not authorize a new Runtime state or execution lane at a time threshold. Current `ui-state-vocabulary.md` already requires owner-backed values and explicitly has no `queued` Run state; it has no `background` Run state either. The draft’s “over 10 seconds does not grant background execution” is the right local safeguard. Keep execution state, request-in-flight, connection state and foreground/background placement as distinct facts. |
| UX-06 · deletion and recovery | Carbon scales deletion friction by impact: trivial-to-recreate changes can proceed without warning; harder-to-recover and high-impact changes need clearer consequence/confirmation. That advice assumes recoverability where it says “undo”; it does not supply a CourtWork rollback service. [Carbon Common Actions](https://preview.carbondesignsystem.com/building-blocks/core/patterns/common-actions) | Supports consequence-based confirmation, not an automatic Undo affordance. CourtWork’s state vocabulary says the reversible mutation lifecycle has no contract and records BE-34 only as a candidate; Atlas marks `reversible-action` as “no contract.” Keep `Undo`, `Retry`, `Revert` tied to an owner, exact target/revision, and real receipt. Do not claim a false recovery path to reduce confirmation friction. |
| UX-08 · Agent transparency and styling | Microsoft calls for visible/controllable Agent activity, knowledge/tools and uncertainty. Carbon for AI presents labels/explainability and says its AI styling should identify AI usage rather than decorate unrelated UI; explanations belong in the workflow and can appear when needed or requested. [Microsoft Agent UX](https://microsoft.design/articles/ux-design-for-agents/), [Carbon for AI](https://preview.carbondesignsystem.com/building-blocks/foundations/carbon-for-ai) | Supports provenance, tools, uncertainty and history that are available when they matter, and separates actual AI output from ordinary controls. The color/glow treatment is IBM’s visual dialect, not a CourtWork token or required pattern. `Save`, `Search` and other non-AI actions should not acquire AI styling; actual AI-generated/recommended material should remain identifiable when the task requires it. |

## Existing CourtWork coverage

The new document is most useful as a stable entry and a cross-surface index. Its rules should continue pointing to owners instead of restating them:

- [copy-convention.md](../../design/copy-convention.md#1-去留) already limits text to object/state/condition/scope/consequence/definition, ties accessibility names to visible labels, protects units/permission/errors from hover-only disclosure, and now owns the local action dialect. Its IA audit already records text purpose and default/context/technical disclosure without adding a DOM attribute for every string.
- [ui-composition-standard.md](../../design/ui-composition-standard.md#信息预算与跨面编排2026-09-13) already separates default, contextual and technical layers and chooses surfaces by user task. It says this is a decision aid, not a closed template set; avoid adding a second L0–L4 surface taxonomy.
- [frontend-contract.md](../../design/agent-interface-2026-09-10/frontend-contract.md#四类合同) already separates Semantic, Projection/Control, Visual and Placement contracts; it requires capability/schema-backed actions, a nearest implemented precedent, and independent review evidence.
- [Atlas](../../design/atlas/README.md) already orders semantic contract → pattern → anatomy → behavior and treats external systems as donors. Its reversible-action row says there is no contract. The [state vocabulary](../../mvp/execution/work-surface-kit/contracts/ui-state-vocabulary.md) maps actual Host/Core values, omits unsupported queue/staleness states, and records no reversible mutation lifecycle.

The useful supplement is therefore the review procedure and cross-cutting IDs (string deletion trial, explicit text purpose/disclosure, pattern change history), not another component library, state machine, spacing-token namespace, or automatic acceptance gate. The local `proposed/adopted/superseded` rule lifecycle should stay separate from `canonical/reference` precedent status and product acceptance. The source sample did not establish an industry-wide lifecycle vocabulary.

## Exclusions and limits

The official Apple HIG Writing page returned only a JavaScript-required shell in this check; it is not counted as a verified source. The conversation’s Shopify Common Actions URL redirected to a general API index; no claims from that page are used. The checked Polaris fundamentals file is an official archived source, not a current maintained standard. Carbon Common Actions and Carbon for AI are on Carbon’s preview domain. GOV.UK’s UI writing page states it was last updated in 2018. These sources demonstrate useful practice, not authority over CourtWork’s object, state, persistence, permission or recovery contracts.

No broad source search was run; no Exa result count, unattributed quotation, or external design-system API was promoted as a CourtWork requirement. Astra owns final wording and adoption decisions.
